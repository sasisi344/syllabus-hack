## データの形（変えない項目・変える項目）

各問題のキー: `question`・`options`・`answer`・`explanation`・`id`・`keyword`・`category`・`field`・`middleCategory`・`syllabusRef`。キーは増やさない・減らさない。

| キー | 扱い |
|---|---|
| `id` | **変えない**（既存の `genai-<数字>` のまま。利用者の記録が問題の ID を参照するため） |
| `category` | 新シラバスの大項目名を一字一句そのまま: `AIの基礎と歴史`／`生成AI`／`AIエージェント`／`生成AIのリスク予防・AI倫理・ガバナンス`／`生成AIの実践と活用事例`（アプリの分野別ドリルはこの文字列で分野を作る） |
| `syllabusRef` | 新シラバスの中項目番号（例 `3-4`）。今の値は旧シラバスの番号なので、全問付け直す |
| `middleCategory` | 新シラバスの中項目名（`src/data/master/syllabus-genai-pass-2027.json` の `middle_categories[].name` をそのまま） |
| `field` | 変えない（`genai-pass-knowledge`） |
| `options`・`answer` | 形式を変えない（`"ア: …"` の4択、`answer` は `ア`〜`エ`） |

## やること

1. 付録「問題ごとの区分」を `keyword` で各問題に対応させる（同じ keyword が2問ある1種は、設問を読んで中項目を決める）。対応できない問題があれば報告書に書く
2. **区分 A**: `category`・`syllabusRef`・`middleCategory` を付け替える。解説（`explanation`）が旧シラバスの文脈（旧の項目名・旧の原則の列挙など）のままなら、新シラバスの言い方に直す。設問の正誤も1問ずつ読んで確かめる
3. **区分 B**: 付録の「備考」と棚卸し §4 の理由に沿って、設問・選択肢・解説を書き直してから付け替える
   - モデル名・バージョン名・サービス名だけを問う問題（GPT の版の違いなど）は、新シラバスの粒度（推論モデル・マルチモーダル化など、仕組みと特徴）で問う形に直す。特定の版の発表日・性能の数値は問わない
   - 旧「プロンプトの4要素」の名称を暗記させる問題は、新シラバスの「プロンプトの基本構成要素」を、業務の場面で選ばせる形に直す
   - 書き直せない問題（新シラバスで問う意味がない）は、削除して報告書に理由を書く
4. **区分 C**: 削除する（59問）。報告書に削除した `id` と `keyword` の一覧を書く
5. 全問共通
   - 設問・選択肢・解説の Markdown の `**` を消す（8問ある。アプリは Markdown を描画しない）。否定の問い（「できないもの」など）は、`**` ではなく文の形で伝わるようにする（例: 「できないものはどれか」を文末に置く）
   - 正解の位置がア〜エに偏らないようにする（書き直す問題で調整。A の問題は正解の位置を変えなくてよい）
   - 正解の選択肢だけが長く留保つきにならないよう、選択肢の長さをそろえる（書き直す問題で）
   - 法令・ガイドラインに依存する問題は、解説に一次情報の名前と時点を書く（例: 「AI事業者ガイドライン第1.2版（2026年3月）」）。確かめられない事実は問わない
6. 最後に、新しい分類ごとの問題数と、中項目ごとの問題数を数えて報告書に表で書く（b の作問の量をこの表で決める）
