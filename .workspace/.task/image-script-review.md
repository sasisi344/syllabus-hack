# 画像生成スクリプトの見直し（TODO §2）

> 正本タスク: `TODO.md` §2「画像生成スクリプトの見直し・最適化」
> 対象: `.workspace/scripts/Antigravity-nanobana/generate-image.js`

## 1. 現状レビュー

| 観点 | 現状 |
|---|---|
| API呼び出し方式 | Gemini API（モデル: `gemini-3.1-flash-lite-image`）を`https`モジュールで直接POST。SDK不使用、依存パッケージなしの最小実装 |
| コスト | flash-lite系の軽量課金モデルを選定済み（意図的なコスト最適化）。ただし呼び出し回数・コストのログ出力は無く、追跡不能 |
| 生成品質 | `temperature: 1.0 / topP: 0.95 / topK: 40` と高いランダム性設定。同一プロンプトでも毎回結果が大きく変わりうる。スタイル一貫性は呼び出し側（`image_rules.md`のスタイル修飾子・ネガティブプロンプトをプロンプト文字列に含めること）に依存しており、スクリプト側では強制していない |
| 失敗時のリトライ挙動（修正前） | **リトライ機構が皆無**。APIエラー応答時（`candidates`なし）や画像パート欠落時はコンソールにエラーを出すのみで、`process.exit`せず正常終了（exit code 0）していた。呼び出し元（エージェント）が失敗を検知できず「成功したように見える」リスクがあった |

## 2. 実施した修正（2026-09-09）

1. **リトライ追加**: 最大2回リトライ（3秒間隔）。API応答に画像データが含まれない場合・ネットワークエラー時ともに対象
2. **失敗時のexit code修正**: 全リトライ失敗時は`process.exit(1)`で終了するように修正。`main()`に`.catch`を追加し、未処理のPromise rejectionによる不明瞭なクラッシュも解消
3. 動作確認: `node --check`で構文検証のみ実施（実際のAPI呼び出しは、画像生成が明示指示のない限り実行しないというCLAUDE.mdの方針に従い今回は見送り）

## 3. 最適化の方向性（検討結果）

- **プロンプトテンプレートの改善**: `image_rules.md` §4のスタイル修飾子・ネガティブプロンプトは現状「呼び出し側が手動で毎回組み込む」運用。スクリプト側にデフォルトのスタイル修飾子・ネガティブプロンプトを固定文字列として組み込み、呼び出し側は被写体部分のみ渡す設計に変更すると、一貫性担保とプロンプト漏れ防止の両方に効くが、**呼び出しI/Fの変更は既存ワークフロー（エージェントがプロンプト全文を組み立てて渡す運用）に影響するため、変更するかは要判断**。今回は見送り、現状の「呼び出し側で毎回スタイル修飾子を含める」運用を維持
- **theory共通カバー方針との整合**: 既存方針（2026-07-12決定、`image_rules.md` §0）「共通カバーは意図的なコスト設計であり一括置換しない」は変更なし。今回のスクリプト修正でも踏襲
- **courseコレクション用カバーの扱い方針**: 既存の「アプリ・特定ジャンルは共通カバーでコストダウン」という決定と同じロジックを適用し、**courseコレクションもデフォルトで共通カバー（`course/common-cover.png`）を使う方針とする**（`image_rules.md` §0に追記済み）。個別カバーが必要な場合（例: 章ごとに差別化したい等）はWeek3実装時にユーザーへ改めて確認する
