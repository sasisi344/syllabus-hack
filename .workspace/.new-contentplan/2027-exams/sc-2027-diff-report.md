# SC（情報処理安全確保支援士）2027年シラバス差分レポート

> 出典: IPA公開シラバス案 Ver.0.1（2026年公開）と、現行シラバス Ver.2.1（2023年12月版）の比較。構造化データは `src/data/master/syllabus-sc-2027.json`。`examId: 'sc'` は `src/content/config.ts` に既存登録済みのため、新規登録作業は不要。

---

## 1. サマリ

| | 旧（Ver.2.1・2023） | 新（Ver.0.1・2026案） |
| --- | --- | --- |
| 構成方式 | 「要求される知識」を各スキル項目に**埋め込み**。独立した用語体系なし | **知識（専門知識・その他の知識）**と**技能**を分離。知識は他試験区分（IP等）と共通の中分類番号体系で構造化 |
| 知識（専門知識・大分類6セキュリティ＋大分類4ネットワーク） | — （構造化データなし） | 中分類5個・**615語** |
| 知識（その他の知識・大分類1/3/4/5から抜粋） | — （構造化データなし） | 中分類5個・**246語** |
| 知識 合計 | — | 中分類10個・**861語** |
| 技能（大項目/小項目） | 大項目4・小項目**30**（1-1〜1-7, 2-1〜2-8, 3-1〜3-11, 4-1〜4-4） | 大項目4・小項目**31**（1-1〜1-11, 2-1〜2-8, 3-1〜3-8, 4-1〜4-4） |

**最大の変化は「知識」の扱い方**。旧シラバスは各スキル項目（例: 2-6セキュリティテスト）の中に「・脆弱性診断，ペネトレーションテストの実施方法に関する知識」のような箇条書きを埋め込む方式で、独立した用語集としては使えなかった。新シラバスはIT パスポート等と同じ「大分類→中分類→小分類→用語例」の構造化フォーマットに統一され、**シラバスハックの既存キーワード駆動コンテンツ設計とそのまま相性が良い形**になった。

## 2. 技能（大項目/小項目）の再編

小項目の総数は30→31（+1）だが、中身は単純増加ではなく**大項目1（組織的推進）への集約**が起きている。

| 変化 | 内容 |
| --- | --- |
| 大項目1が7→11項目に拡大 | 旧・大項目3（技術対策）にあった「人的管理」「サプライチェーンの情報セキュリティの推進」「コンプライアンス管理」が**大項目1（組織的推進）に移動**。新規追加は「1-5 セキュリティ運用状況の点検」の1項目のみ |
| 大項目3が11→8項目に縮小 | 上記3項目が抜けた分、purely技術対策（暗号・マルウェア・データ保護・監視・ネットワーク・脆弱性・物理・アカウント管理）に純化 |
| 大項目2・4は項目数維持 | 名称・粒度もほぼ同一（開発ライフサイクルのセキュリティ、インシデント管理） |

**解釈**: 「人的管理」「サプライチェーン」「コンプライアンス」を技術対策の一部ではなく組織マネジメントの一部として再定義したことで、支援士に求められる役割が「技術者」から「組織全体のセキュリティガバナンスを支援するマネジメント人材」寄りに再定義されている。

## 3. 知識面の新設・大幅拡充テーマ（テーマ別）

### 3-1. 生成AI・AIシステムのセキュリティ（完全新規）

旧シラバスには「AI（生成AIを含む）」という**IT動向の一項目としての言及のみ**（技術詳細ゼロ）。新シラバスでは中分類23（脅威）・中分類26（実装技術）に具体的な攻撃・対策技術が新設された。

- **AIへの攻撃**: プロンプトインジェクション（直接・間接）、ジェイルブレイク、敵対的サンプル（Adversarial Examples）、データポイズニング、モデルインバージョン攻撃、メンバーシップ推測攻撃、モデル窃取（Model Extraction）、システムプロンプトの窃取
- **AIを悪用した攻撃**: マルウェア亜種の自動生成、フィッシング文面の巧妙化、ディープフェイク・音声クローンによるなりすまし
- **AIを守る対策（Security for AI）**: プロンプト分離、エージェントの権限分離、RAG用データストアへのアクセス制御、システムプロンプトの強化
- **AIを使う対策（AI for Security）**: AI for Security という概念自体が新設
- **標準**: OWASP Top 10 for LLM Applications、ISO/IEC 42001（AIマネジメントシステム）、AI事業者ガイドライン

→ **シラバスハックとして最も差別化しやすい新規テーマ**。「生成AI×資格試験」を軸にするサイトの強みが最も活きる分野。

### 3-2. ゼロトラスト・クラウドセキュリティの専門技術化

旧シラバスは「クラウドコンピューティング」という動向言及のみ。新シラバスは実装レベルの具体語彙を多数追加。

- ゼロトラストアーキテクチャ（ZTA、NIST SP 800-207、ポリシー決定ポイント/実施ポイント）、ZTNA、マイクロセグメンテーション
- CASB（Cloud Access Security Broker）、CSPM（Cloud Security Posture Management）、CWPP（Cloud Workload Protection Platform）、SASE（Secure Access Service Edge）
- クラウドの設定不備、インスタンスメタデータサービスの保護、IaCのセキュリティスキャン

### 3-3. ソフトウェアサプライチェーンセキュリティの技術詳細化

旧シラバスは「サプライチェーンリスク」という契約・取引の文脈（大項目3-10）のみ。新シラバスは技術的対策が中分類26に新設。

- SBOM（Software Bill of Materials）を利用した脆弱性管理、ソフトウェア構成分析（SCA）
- 依存関係混同（Dependency Confusion）、タイポスクワッティング、OSSメンテナアカウントの乗っ取り
- 署名付きコミット、成果物の署名検証、SLSA（サプライチェーンセキュリティのフレームワーク）

### 3-4. 暗号技術の耐量子化（完全新規）

- 耐量子計算機暗号（PQC、ML-KEM、ML-DSA）、量子鍵配送（QKD）、量子乱数生成器（QRNG）、暗号アジリティ（Crypto Agility）

いずれも旧シラバスに一切登場しない用語。

### 3-5. パスワードレス認証・認証技術の刷新

- FIDO（FIDO2、WebAuthn、CTAP、パスキー）、フィッシング耐性のある認証
- アイデンティティ連携（OpenID Connect、SAML、OAuth 2.0、PKCE、JWT）、IDaaS

旧シラバスは「認証プロトコル」という抽象言及のみで、これらの固有技術名は無かった。

### 3-6. 脅威インテリジェンス・検知技術の高度化

- サイバーキルチェーン、MITRE ATT&CK（旧シラバスにも言及ありだが「攻撃の分析モデル」という一言止まり）→ 新シラバスは戦術・技術・手順（TTP）、偵察・初期侵入・権限昇格・永続化・ラテラルムーブメント・C2という**攻撃ライフサイクルの各段階**まで具体化
- SIEM、EDR、NDR、XDR、SOAR、MDR、MSS（旧シラバスはSIEMのみ言及）
- EPSS、SSVC、KEV（脆弱性の優先順位付け手法。旧シラバスのJVN/CVE/CVSS/CWEに加えて新設）

### 3-7. 中分類26「セキュリティ実装技術・評価」の新設

旧シラバスにおける「セキュア開発」「セキュリティテスト」の知識断片（大項目2の各スキル項目に散在）が、**独立した専門知識分野として統合・格上げ**された。フォレンジック（証拠保全・マルウェア解析）とセキュリティ評価（コモンクライテリア、暗号モジュール評価）もここに集約されている。

## 4. 旧シラバスにあって新シラバスで扱いが変わったもの

- **無線LANのセキュリティ**: 旧は3-5で専用言及があったが、新では中分類16（ネットワーク）に一般的な無線LAN用語として吸収され、セキュリティ専用の深掘りとしては後退した可能性がある（Ver.0.1が未完成のため今後の版で復活する可能性もあり要注視）
- **VDI（仮想デスクトップ）**: 旧3-5に明記されていたが新シラバスの抽出語彙には見当たらない。リモートワークセキュリティの一般語彙に統合された可能性
- **要求される知識の粒度**: 旧シラバスは「〜に関する知識」という抽象レベルの記述が多く（例:「ハッシュ関数に関する知識」）、新シラバスは具体的な用語例（SHA-2、SHA-3等）まで踏み込んでいる。これは後退ではなく**具体化**

## 5. シラバスハックのコンテンツ企画への示唆

1. **trend記事**: 「情報処理安全確保支援士（SC）2027年シラバス改訂の要点」— 上記3章のテーマ別新設ポイントを軸に、既存の`method/advanced-ipa-hub`（高度試験クラスターのハブ）から誘導する構成が作りやすい
2. **method記事の新規候補**: 「生成AI時代のセキュリティ脅威4選（プロンプトインジェクション・データポイズニング・モデル窃取・ディープフェイク）をAIで学ぶ」のような、3-1テーマに特化した記事は競合が薄く、サイトの「生成AI×資格」軸とも直結する
3. **既存SC関連記事の棚卸し**: 今回は実施していない。既存記事（`career`/`method`カテゴリのSC関連記事）が「無線LANセキュリティ」「VDI」など§4で後退が疑われる用語を主題にしている場合、2027年施行までのタイムラインを踏まえたリライト要否を別途判断する必要がある
4. **20hoursコース展開**: SCは高度試験（応用〜専門レベル）のため、ITパスポートのような「未経験者向け入口コース」の対象にはならない。展開するなら実務者（IT経験者）向けの「総復習コース」という位置づけが自然（[`../20hours学習法の基本理念.md`](../../20hours学習法の基本理念.md)のIT経験者/未経験者の区分と整合）
5. **examId**: `sc` は `src/content/config.ts` に既存登録済み。追加のenum登録作業は不要
