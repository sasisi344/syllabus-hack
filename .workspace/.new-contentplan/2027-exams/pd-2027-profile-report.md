**構造上の発見**: PD-MとPD-Sで**共通する中分類は「経営戦略・デジタル戦略」（中分類2）ただ1つ**。それ以外は完全に棲み分けており、PD-Mは「大分類1（ビジネス変革）＋組織活動＋セキュリティマネジメント＋法務」というマネジメント層の知識、PD-Sは「大分類4（デジタル技術）＋システムの開発・運用＋セキュリティ実装」という実装層の知識で構成される。これはSCの「情報セキュリティマネジメント（24）」がPD-Mにも同名で登場する構造（＝同じ中分類番号を複数試験が共有し、試験ごとに専門的知識としての深さ・切り口を変える）と同じ設計思想である。

### 中分類2「経営戦略・デジタル戦略」の差異詳細

| 小分類 | PD-M | PD-S |
| --- | :---: | :---: |
| 1. 経営戦略 | ●（MVV，ダイナミックケイパビリティ，ファイブフォース分析，SWOT分析など） | — |
| 2. デジタル戦略 | ●（DX戦略，DX経営に求められる3つの視点など） | ●（同様だが「データの有効活用」「最新技術の活用（生成AIなど）」を追加） |
| 3. 情報システム戦略 | ●（情報システム投資方針，IT投資マネジメントなど経営判断寄り） | ●（コンプライアンス，リスクマネジメント，情報セキュリティなど要件定義寄りの語を追加） |
| 4. エンタープライズアーキテクチャ | ●（ザックマンフレームワーク，TOGAF等、共通） | ●（同一内容） |

PD-Mは「経営戦略の策定」小分類を持つ点が最大の違い（PD-Sには無い）。PD-Sは代わりに要件定義寄りの語（性能要件など）を追加している。

## 3. 各試験の主要テーマ整理

### PD-M（マネジメント）の柱

1. **ビジネス変革の推進**: イノベーションマネジメント（JIS Q 56002準拠）、チェンジマネジメント（ADKARモデル、コッターの8段階プロセス）、デザイン経営
2. **経営戦略とDX戦略の接続**: 全社戦略（M&A、TOB等）とDX戦略（DX認定制度、DX推進指標）の橋渡し
3. **ビジネスモデル設計とマーケティング**: ビジネスモデルキャンバス、LTV、Web マーケティング指標（CVR/CPM/CPA/ROAS）
4. **サービス・プロジェクトマネジメント**: JIS Q 20000／PMBOK的な体系（アウトカム、テーラリング等）を専門知識として深掘り
5. **ガバナンス・監査**: コーポレートガバナンス（スチュワードシップ・コード等）、内部統制（J-SOX、COSO、COBIT）
6. **情報セキュリティマネジメント（経営視点）**: リスクファイナンシング、サイバー保険など、技術より経営判断寄りのセキュリティ知識
7. **ビジネス関連法規**: 知的財産権の国際条約（パリ条約、TRIPS等）まで踏み込む

技能（科目B）は「組織の変革を推進・支援する」視点で一貫しており、"策定する能力" "評価する能力" "助言・支援する能力" という言い回しが多い（コンサルティング・マネジメント色が強い）。

### PD-S（システム）の柱

1. **経営戦略とシステム要件の接続**: PD-Mより狭いスコープで「システムに落とし込む」ための経営戦略知識のみ
2. **デジタルサービス活用**: ビジネスシステム（ERP・CRM相当の個別業種システム）、エンジニアリングシステム（かんばん方式、MES等）、ECシステム
3. **システム基盤技術**: サイバーフィジカルシステム、コンピュータ構成要素（プロセッサ高速化技術、マルチプロセッサ）、クラウド（FinOps、移行戦略）、ネットワーク（かなり技術的：OSPF/BGP等ルーティング詳細）、データベース（分散データベース、CAP定理）
4. **システムライフサイクル**: JIS X 0170/0160に準拠したシステム開発の全工程（要件定義〜廃棄）を非常に詳細に規定
5. **開発・運用方法論**: アジャイル（SAFe、LeSS等スケール手法まで）、DevOps（DORA メトリクス、Four Keys）、**AI駆動開発**（バイブコーディング、エージェンティックコーディング、仕様駆動開発）、フィジカルコンピューティング（信号処理、半導体、ロボット基盤モデル）
6. **セキュリティ実装**: プロトコルレベル（IPsec/TLS等）の実装技術、AIセキュリティ（プロンプトインジェクション対策）

技能（科目B）は「システムを設計・実装・運用する」視点で一貫しており、"設計するスキル" "実装するスキル" "評価するスキル" という言い回しが多い（エンジニアリング色が強い）。

**特筆点**: PD-Sの「AI駆動開発」（バイブコーディング、エージェンティックコーディング等）と「フィジカルAI」（ロボット基盤モデル、Sim to Real Gap等）は、現行のどの試験区分（AP・高度試験）にも存在しない完全新規の出題領域。生成AI時代の開発手法を正面から扱っている点で、シラバスハックの「生成AI×資格試験」という軸と極めて親和性が高い。

## 4. 既存コンテンツとの接続点分析

`src/data/cert-hubs.ts` の該当Hub:
- `method/ap-hub`（応用情報技術者）
- `method/advanced-ipa-hub`（高度試験: SC・NW・PM ほか）
- `method/level4-strategy-hub`（高度試験 論文・記述対策）

IPAの再編方針（応用情報技術者試験＋既存高度試験をPD試験に大括り化）を踏まえると、この3つのHubが今後の主な影響を受ける。

| 現行Hub | 影響の見立て |
| --- | --- |
| `ap-hub`（応用情報） | PD-M/PD-Sの科目A-2に相当する内容の多くが応用情報の午前・午後知識と重なる（経営戦略、プロジェクトマネジメント、ネットワーク、データベース等）。応用情報自体は当面存続するとみられるが、「応用情報の次に何を受けるか」という導線がPD試験に置き換わる可能性が高い |
| `advanced-ipa-hub`（SC・NW・PM等の高度試験） | NW・DB・PM・ST・SA・SM・AU・ESの各高度試験区分が「マネジメント」「システム」の2区分（＋データ・AI）に統合される方向性と一致。特にPMの技能領域はPD-Mの「プロジェクトマネジメントに関すること」とほぼ1:1対応、NW/DBの専門知識はPD-Sの中分類16・17とほぼ1:1対応 |
| `level4-strategy-hub`（論文・記述対策） | PD試験は科目Bが「技能」形式（大項目・小項目・技能例）であり、現行のPM/ST論文形式とは出題形式が異なる可能性がある。論文対策のノウハウがそのまま使えるかは要検証 |

## 5. シラバスハックのコンテンツ企画への示唆

1. **examId未登録**: `'pd-m'` `'pd-s'` は `src/content/config.ts` の enum・`.workspace/.task/exam-id-catalog.md` のいずれにも未登録。記事化する場合はまず両方に追加が必要
2. **データ・AI領域（PD-D相当）のシラバスが未取得**: PD試験を包括的に扱うには3区分目の入手が必須。ユーザーに追加取得を依頼すべきタイミングで確認するとよい
3. **新規Hub候補になりうるが時期尚早**: 現行試験は2026年度で終了、PD試験の実施は2027年度夏〜秋頃（予定）。IT パスポートと同様、**今すぐHub化するのではなく、まずtrend記事で「PD試験とは何か」を告知する段階**が妥当（`new-content-plan.md` の「2027年IPA改訂への対応」と同じ扱い）
4. **PD-Sの「AI駆動開発」「フィジカルAI」は独自コンテンツ化の価値が高い**: 現行試験に存在しない完全新規領域であり、生成AI時代のエンジニアリングをテーマにしたmethod/trend記事の種になる。ITパスポートの「生成AI」章と同様、独立したジャンルとして扱う価値がある
5. **PD-MとPD-Sは「マネジメント志向」「エンジニアリング志向」で完全に読者層が分かれる**: 将来Hub化する際は、応用情報Hubのように1本にまとめず、ITパスポートの20hoursコース設計と同様に「対象読者が違うものは別コンテンツにする」原則を踏襲すべき（[`../20hours学習法の基本理念.md`](../20hours学習法の基本理念.md) の二層構成の考え方と同根）
