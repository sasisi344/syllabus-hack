# 20時間コース 共通テンプレート

> 20hours学習法をどの資格にも同じ型で展開するための共通仕様。第1号の適用例は [`ip-course/ip-course-curriculum.md`](./archive/ip-course/ip-course-curriculum.md)。実装スキーマは [`structure-migration-plan.md`](./structure-migration-plan.md) §4-1。

---

## 0. 全コース共通の注意書き（必須・省略不可）

**20時間コースは基礎知識を身につけるための学習教材であり、合格を保証するものではない。** どの資格のコースを作る場合も、この位置づけを弱めずに次の3箇所へ必ず掲載する。

| 掲載箇所 | 文面の目安 |
| --- | --- |
| コースTOP・導入直後（§2 の1） | フル文言。「本コースは20時間で基礎知識を身につけるための学習教材であり、合格を保証するものではありません。仕上げにはCBT模擬試験や有料教材を併用してください」程度 |
| 各章ヘッダ直後（§3 の1〜2の間） | 1文に圧縮。「本コースは基礎学習用であり、合格を保証するものではありません」 |
| コース完走画面（§2 の5） | 「ここからは実戦演習・発展学習のフェーズです」という文脈で再掲し、CBT・noteへの導線と結びつける |

実装時はこの3箇所を固定コンポーネント（例: `CourseDisclaimer.astro`）として共通化し、コースごとに文言がぶれないようにする。新規コースの章ドラフトを生成する際も、この注意書きの挿入をスキャフォールドの標準ステップに含める（§7）。

## 0-1. 二層モデル（Tier1無料／Tier2有料）について

2026-09-07、ITパスポートのケースで「20時間で資格試験の全知識体系をアウトプットさせるのは非現実的」という考察（[`../20hours学習法の基本理念.md`](../20hours学習法の基本理念.md)「20時間学習法の射程」）から、**本テンプレートが対象とする「20時間コース」は常に Tier1（無料・精選版・入口テキスト） である**ことを明確化した。

- Tier1（本テンプレートの対象）: シラバス全体を網羅しない。ジャンルごとに高価値な用語を精選し、20時間に収める
- Tier2（有料note・合格テキスト）: シラバスの中分類を1:1でフルカバーする別コンテンツ。本テンプレートの対象外（章立て原理が異なるため、Tier2用のテンプレートは別途必要になった場合に新設する）
- 新しい資格へ展開する際は、**Tier1だけを作るのか、Tier2も並行して企画するのか**を最初に決める（§7 手順1に追加）。詳細な二層設計の実例は [`ip-course/ip-course-curriculum.md`](./archive/ip-course/ip-course-curriculum.md) を参照

## 1. コースの構成単位

```
コース（1資格＝1コース）
├── 診断テスト（16〜24問）    … 1章2〜3問。全体正答率で入口ルートを、章別正答率で重点章を決める（§1-1）
├── 学習ルート                … 診断結果から3ルート（演習／重点／基礎）のいずれかを提示（§1-1）
├── 第1章〜第N章（6〜8章）    … ジャンル別。各章に節（3〜5）＋章末チェック（3〜4問）
└── 総復習（20問）            … 章末チェックの再出題＋新規。合格ライン60%
```

- **章の切り方はジャンル別**。シラバスの区分・大分類の順序ではなく、学習者が「いま何を学んでいるか」を直感できる単位（例: PC用語／ネットワーク／ストラテジ／マネジメント／セキュリティ／生成AI）
- **章の根拠はシラバス構造化データ**（`src/data/master/syllabus-{examId}.json`）。各章がどの中分類を担当するかを必ず表にする。扱う用語はその中分類のキーワードから選ぶ
- **時間配分は本試験の出題比率をベース**にし、語数・関心度で微調整する。合計は必ず20h（診断0.5h＋総復習1.5h＋章18h）
- **6〜8章が上限**。8章を超える場合はジャンルを統合する（章が多いと「20時間で終わる」体感が崩れる）
- **読む時間より解く時間を厚くする**。カウフマンの原典は「調べる（学習）」を練習のための手段と位置づけ、20時間の中心は練習に置いている。資格試験における練習は「本番形式の問題に答えること」なので、どのルートでも「読む→解く→間違えた節に戻る」の往復を基本にし、章本文を読んで終わる設計にしない

### 1-1. 診断ルーティング（2026-10-17追加）

診断テストは「重点章のハイライト」で終わらせず、**結果から入口ルートを1つに決めて提示する**。読者に「どのパターンで進めるか」を選ばせない。旧版の「カリキュラムマップ3パターン（標準/実務者/直前）」はこの3ルートに置き換える。

判定は2段で行う。

1. **全体正答率 → 入口ルート**
2. **章別正答率 → 重点章**（章内で半数以上を間違えた章を重点章とする）

| 全体正答率 | ルート | 進め方 |
| --- | --- | --- |
| 80%以上 | 演習ルート | 基礎学力はある前提。CBT模擬試験を1回フルで解く → 模擬試験・診断で落とした分野の章だけを読む → 総復習。診断はシラバスの一部しか測れないため、全問正解でも模擬試験での確認を必ず挟む |
| 40〜79% | 重点ルート | 重点章を正答率の低い順に学ぶ。得意な章は本文を読み飛ばし、章末チェックだけ解いて確認（間違えたら該当節に戻る）。得意分野はCBT模擬試験で維持する |
| 40%未満 | 基礎ルート | 第1章から順に進める（Tier1本来の対象）。章ごとに「読む→章末チェック→間違えた節を読み直す」を往復する。完走後は総復習 → CBT模擬試験へ |

- **しきい値の根拠**: 4択問題は勘でも期待正答率25%になるため、「2割以下」のような低いしきい値では誰も基礎ルートに該当しない。基礎ルートの線は勘の水準を明確に上回る40%に置く
- **問題数の根拠**: 章別判定をするには1章2〜3問が必要（1章1問だと1問の正誤で得意/苦手が決まってしまう）。8章なら16〜24問、診断の所要時間は0.5h以内に収める
- **試験直前で時間がない読者**: 正答率に関わらず演習ルートを推奨する（旧「直前」パターンの役割）
- **章別20時間型（SC等の最難関区分）**: 全体正答率の代わりに「重点章の数」で進め方を分ける既存の表（`src/data/course/sc/index.mdx`）を、本節の重点ルートの変種として扱う
- **実装状況（2026-10-17時点）**: 未実装。現行の `ChapterQuiz`（`mode="diagnosis"`）は1問でも間違えた章を苦手章として列挙するだけで、ルート判定はない。また SC 以外の診断JSONは10問（1章1〜2問）。新規コースは本節に従い、既存コースは診断JSONの増問とルート表示の実装をセットで移行する

| 6 | この章のまとめ | 章末チェックの直後。2〜3文で①この章で学んだ内容の要約 ②次章で学ぶ内容の一言紹介＋リンク（最終章はコースTOPの「完走したら」への案内に差し替え）。詳細は§3-1 |
| 7 | 前後ナビ | 前の章／次の章／コースTOP（`CourseLayout`が自動生成する機械的なナビ。§3-1の「この章のまとめ」とは別物で、両方必要） |
| 8 | 続きの導線 | 章の内容に対応する有料noteの章があれば1行で案内（`noteUrl`） |

### 3-1. セクション冒頭・章末の定型文ルール（2026-09-09追加・ITパスポートコースで確立）

「AIで学ぶ」「章末チェック」はプロンプトや問題を置くだけだと、読者から見て「これで何をすればいいのか」が伝わらない。また章末チェックの後（章の一番最後）は前後ナビ（機械的なリンクのみ）で終わらせず、学習の区切りとして要約と次への案内を必ず挟む。講師が生徒に語りかける口調で、長すぎず短すぎない1〜3文にする。

**「AIで学ぶ」冒頭の1文（例・ITパスポートコース第1章）**

> ここまでの用語は、ChatGPTやClaudeなどの生成AIに以下のプロンプトを投げかけると、比較表つきでさらに深く掘り下げて学習できます。コピーして使ってみましょう。

**「章末チェック」冒頭の1文（固定文でよい）**

> 最後に、この章で学んだ知識をアウトプットして定着させましょう。全問に答えたら「答え合わせ」を押してください。

**「この章のまとめ」（章末チェックの直後、`## この章のまとめ` 見出し）**

- 1文目: この章で扱った用語・視点を軽く並べる要約（列挙しすぎない。3〜4個の代表語で十分）
- 2文目: 次章のジャンルを一言で紹介し、リンクする（`<strong>次章のジャンル名</strong>` を使い、文末に `→ [第N+1章 タイトル](/course/{examId}/{NN-slug}/)`）
- 最終章のみ2文目を差し替え: 「これで全N章の学習は完了です。お疲れさまでした。[コースTOP](/course/{examId}/)の「完走したら」で、模擬試験や合格テキストなど次のステップを確認しましょう。」

例（ITパスポートコース第1章末尾）:

```
## この章のまとめ

この章では、経営・組織論、ガバナンス・監査、そして著作権・労働法・個人情報保護などの関連法規を通じて、「会社を運営する」「会社を守る」という2つの視点からビジネスの土台を押さえました。

次章では、その会社が市場でどう戦っていくかを考える<strong>経営戦略</strong>と、ERP・CRMなど戦略を実行に移すためのデジタルツールを学びます。→ [第2章 経営戦略とビジネスモデル・ツール活用](/course/ip/02-strategy-business-model/)
```

リンクは相対パスではなく`/course/{examId}/{slug}/`のルート相対で書く（章ページのURLは`/course/{examId}/01-xxx/`のように1階層深いため、相対パスだと解決を誤りやすい）。

### 執筆ルール（章ページ）

- 見出しに番号を付けない（`## 1. 〜` 禁止）。見出し全体を「」で囲まない（CLAUDE.md準拠）
- 節の見出しは「学習者が得ること」を表す名詞句（例: 「会計と財務諸表を読む」）。中分類名の丸写しにしない
- 用語リストはシラバスのキーワードを**原文どおり**に載せる（表記ゆれを作らない）
- 1段落1〜2文。bold（本番は `<strong>`）は1段落1〜2個まで
- 数式が必要な資格は KaTeX（`$...$`インライン／`$$...$$`ブロック）。ITパスポートでは原則使わない
  - **導入済み（2026-09-07 PoC完了）**: `astro.config.ts` に `remark-math`/`rehype-katex` を追加済み。数式を使う章ページでは `import KatexStyles from '~/components/common/KatexStyles.astro'` を追加し `<KatexStyles />` を配置するだけでよい（CSSは該当ページにのみスコープされ、他ページへの影響はゼロ。検証結果は [`week1-task.md`](./archive/week1-task.md) 参照）
- **構造・関係性を持つ内容は Mermaid 図解を使う（2026-09-22 PD-Sコースで導入）**。20時間コースは知識体系を俯瞰して学ぶ設計思想のため、用語を並べるだけでなく「要素同士がどう関係しているか」を視覚化できる箇所には積極的に図を挟む。判断基準は次のとおり:
  - **使うべき内容**: 階層・包含関係（例: リージョン⊃AZ、EAの4層構造）、プロセス・手順の流れ（例: システムライフサイクル、インシデント対応フロー）、トレードオフ・スペクトラム（例: クラウド移行5Rの改修コスト×恩恵）、対比構造（例: ガバナンスとマネジメントの役割分担）
  - **使わなくてよい内容**: 単なる用語の列挙、フラットな分類（親子関係のない並列語）、章に1つあれば足りるため入れすぎない（目安: 1章あたり0〜2個）
  - **実装方法**: `import MermaidDiagram from '~/apps/mermaid-diagram/MermaidDiagram'` と `import MermaidStyles from '~/components/common/MermaidStyles.astro'` を追加し、章冒頭付近に `<MermaidStyles />` を1回配置。図は `<MermaidDiagram client:load chart={`flowchart TB ...`} caption="図のタイトル" />` の形で該当する解説パラグラフの直後に置く（KaTeXと同じ「使うページにだけimportする」方針。CSSはスマホ幅の横スクロール対応込みで`MermaidStyles.astro`に分離済み、ダークモード切り替えにも自動追従する）
- 既存記事へのリンクはルート相対（`/theory/xxx/`）

### 3-2. 隣の席コメント（筆者の callout）（2026-10-19追加）

20時間で学びが完了するとは考えていない。だから筆者が章を実際に読み、わかりにくい所・間違えやすい所に「隣の席の人に『ここわかりにくいよね？』と話しかける」感覚のコメントを入れ、読者が一人で抱え込まずに読み進められるようにする。

- **書き方**: 章のアウトラインや本文に Obsidian 形式の callout を書く（import不要。`learnerCalloutRemarkPlugin` が「筆者」の吹き出しに変換する）
  - `> [!forAI]` AIへの指示（読者には表示されない。AIが本文に反映したら削除）
  - `> [!exp]` 実際にやった感想（緑の吹き出し・「やってみて思ったこと」）
  - `> [!question]` 出題に対する深掘りの問い（青の吹き出し・「この問題、ここが気になる」）。直後か次の節に答えへの道筋を置く
  - `> [!think]` 疑問に思ったこと（黄の控えめなメモ・「ここ、引っかからない？」）
  - exp / question は出題に対する筆者のリアクションが主体なので、目立つ吹き出しで表示する。章末チェックや該当問題・解説の直後に置く
  - `> [!think] ラベル` のように同じ行に書いた文は、次の行に本文が続くときはラベル、1行だけなら本文になる
- **中身は筆者の実体験のみ**。AIは exp/think/question を創作しない。AIの仕事は、その callout に合わせて周囲の解説を直すこと（`.agents/post_writer.md` Step 0-5）
- **密度**: 1節（H2）につき最大1個。目安は1章2〜4個
- **進捗**: [`../.task/course-seat-notes.md`](../.task/course-seat-notes.md) で章ごとに管理

## 4. 問題データの規約

| 種別 | ファイル | 問数 | field |
| --- | --- | --- | --- |
| 診断 | `src/data/quiz/{examId}/course-diagnosis.json` | 16〜24（1章2〜3問） | 各問に `chapterOrder: N` を持たせる |
| 章末 | `src/data/quiz/{examId}/course-ch{N}.json` | 3〜4 | `chapterOrder: N` |
| 総復習 | `src/data/quiz/{examId}/course-review.json` | 20 | `chapterOrder: N`（章別集計用） |

- スキーマは `.agents/quiz_data_rules.md` の `Question` 型＋`chapterOrder` フィールド（実装の `ChapterQuiz` が読むフィールド名。旧版の `chapter` は誤り）
- ディレクトリ名は原則 `examId`。ただしITパスポートは既存資産の都合で `src/data/quiz/it-passport/` を使っている
- id は `{examId}-course-{diag|chN|review}-{連番}`
- 既存問題からの再利用可。ただし章末と総復習で同一問題を使う場合は id を変えずに参照する

## 6. 進捗・計測

- localStorage `sh_course_{examId}`: `{ diagnosis: { chapterScores: {1: 0.5, …}, takenAt }, completedChapters: [1,2], reviewScore, lastUpdated }`
- GA4イベント（実装済み・2026-10-17時点）: `quiz_start` / `quiz_complete`（`quiz_mode` で diagnosis / chapter を区別、`correct_count`・`total_count` 付き）/ `chapter_complete` / `course_complete` / `course_nav_click`。送信は `src/utils/ga.ts` の `trackEvent`
- GA4イベント（未実装・追加予定）: `route_assigned`（§1-1の判定ルートを `route: practice|focus|basic` で送る）/ `gate_submit` / `note_click`

## 7. 新しい資格へ展開する手順

1. **Tier1のみか、Tier2（有料note）も並行企画するかを決める**（§0-1）。Tier1のみなら以下の手順2〜9をそのまま実行、Tier2も作る場合はシラバスの中分類をそのまま章立てに使う設計を別途行う（[`ip-course/ip-course-curriculum.md`](./archive/ip-course/ip-course-curriculum.md) §4を参考にする）
2. `syllabus-{examId}.json` の中分類とキーワード数を実測する（`node -e` で集計）
3. ジャンル別に6〜8章へ再編し、章⇔中分類の対応表を作る
4. 出題比率から時間配分を決め、合計20hに揃える
5. **Tier1は精選が前提**。全キーワードを章に割り当てるのではなく、高価値な用語（既存theory記事の有無・出題実績・トレンド性を基準に）を4〜5割程度に絞り込む（[`ip-course/ip-course-curriculum.md`](./archive/ip-course/ip-course-curriculum.md) §3-3の基準を流用可）
6. 既存記事（theory中心）を章に割り当て、新規要約が必要な節を洗い出す
7. `ip-course/ip-course-curriculum.md` と同じ構成で `{examId}-course/{examId}-course-curriculum.md` を書く（コースごとにフォルダを分ける）
8. 章ドラフト骨組みを生成（`.workspace/scripts/scaffold-course.cjs {examId}` — ITパスポート版を汎用化して使う）。生成時に §0 の注意書き（フル文言・圧縮版）を各ファイルへ自動挿入する。§3-1の定型文（AIで学ぶ・章末チェックの冒頭1文、この章のまとめ）は内容が章ごとに固有なため自動挿入せず、次の本文執筆ステップで手動で書く
9. 診断・章末・総復習の問題を作る。診断は1章2〜3問（§1-1）で、章ごとの難易度を揃える（特定の章だけ難問だと重点章判定が偏る）
10. `src/data/course/{examId}/` に配置してビルド
