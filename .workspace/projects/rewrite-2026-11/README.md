## 2. リライトの基準（全記事共通。Codex は記事ごとにこの順で点検する）

### 2-1. 何に答える記事か（Step 0）

`.agents/post_writer.md` Step 0 と `.agents/reader_segments.md` に従い、記事ごとに次の4つを決めて報告書の表に書く。

- TARGET_KW（ロングテールの主KW 1つ）／READER（誰が・どの段階で）／ANSWER（答えの方向）／TAKEAWAY（読み終えて持ち帰る判断材料）
- 全面の記事では、タイトルの前半に主KW、リードは結論を言い切らず「答えの方向性＋読後の約束」（`CLAUDE.md` 記事方針）
- 1本で2つの問いに答えている記事は、主の問いに絞る。外した内容は報告書の「止めた箇所」に書く（ほかの記事への統合は CC が決める）

### 2-2. この記事にしかない情報（有用性）

次のうち、その記事の情報を運ぶのに要るものだけを足す（棚卸し README §4。飾りは足さない）。`waves.csv` の「必要な要素」「不足」が出発点。

| 要素 | 足し方 |
|---|---|
| 出典 | 変わりうる事実（日程・受験料・合格率・出題数・制度・法令・統計）の直後に、一次情報（IPA・試験団体・省庁・法令）へのリンク。確認日を報告書に書く。まとめサイト・ブログは出典にしない。確かめられない事実は書かない |
| 判断の基準 | 「どちらを選ぶか」「何から始めるか」に、条件ごとの答え（表か箇条書き）を置く。一般論で終わらせない |
| 図 | 手順・順番・構成（要素4つ以上がつながる）は Mermaid（` ```mermaid `、`.md` でも描画される）。ハブは取得までのルート図。1記事1枚まで。Mermaid にできない図は画像マーカー（`hq/org/README.md` §4） |
| AIの実行例 | プロンプトを載せている記事だけ。Codex は実行結果を作らない。入れる位置に `<!-- AI_EXAMPLE: 使うAI=… / プロンプト=本文の〇〇 / 見せたいこと=… -->` を置き、報告書に一覧で書く（ユーザーが実行して画面・回答を用意する） |
| 筆者の体験 | Codex は書かない。体験が合う箇所に `<!-- LEARNER_NOTE: 候補=… / 種類=exp・think・question / 筆者の実体験で記入 -->` を置くだけ。置けるのは `src/data/author-exam-status.ts` で受験・学習・実務の記録がある資格だけ。1つの H2 に最大1個、記事で0〜2個 |

### 2-4. つながり

- 同じ資格の20時間コース（`/course/{examId}/`）があれば、本文の該当箇所からリンクする（ある: ip・sg・sc・dm・pd-m・pd-s・g-kentei・ai-work）
- 同じ資格のハブ（`*-hub`）へ1回リンクする
- 公開停止・統合した記事へリンクしない（`astro.config.ts` の `redirects` と、`draft: true` の記事を確かめる）
- 内部リンクは1記事で新たに足すのは3本まで（リンク集にしない）

### 2-5. 形式（`CLAUDE.md`「必須ルール」）

- 本文の強調は `<strong>`（コードフェンス内のプロンプトは Markdown の `**太字**`）。1段落1〜2個まで
- 1〜2文で改行し、改行は空行で入れる。見出し全体を「」で囲まない。見出しに番号を振らない
- frontmatter: `lastmod` を作業日に、`publishDate`・slug・URL は変えない。`toc: true`、`metadata.description` 120〜160字
- アフィリエイトのリンク・広告を足さない（AdSense の審査中）
