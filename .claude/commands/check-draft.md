# ドラフト品質チェック

対象ファイル: $ARGUMENTS

指定されたファイル（またはディレクトリ内の全ファイル）を品質チェックしてください。
引数が空の場合は `.workspace/draft/` 内の全ファイルを対象にする。

## チェック項目

### 1. フロントマター必須フィールド確認

以下がすべて存在するか確認する:

- [ ] `publishDate` — ISO形式（T00:00:00Z 付き）
- [ ] `lastmod` — YYYY-MM-DD 形式
- [ ] `title` — 30〜40文字推奨
- [ ] `excerpt` — 約100文字
- [ ] `image` — `~/data/post/{category}/{slug}/cover.jpg` 形式
- [ ] `category` — trend / method / career / app / theory のいずれか
- [ ] `tags` — 3〜5個
- [ ] `draft` フィールドの存在確認
- [ ] `metadata.description` — 120〜160文字
- [ ] `persona` フィールドの存在確認
- [ ] `knowledge.examId` フィールドの存在確認

### 2. Bold 変換チェック

```
Grep パターン: \*\*[^*]+\*\*
```

- `**bold**` 形式が残っている箇所をすべてリストアップ
- 本番移行前に `<strong>` への変換が必要な箇所を明示

### 3. 画像パス検証

- `image:` フィールドが `~/data/post/` から始まっているか
- 相対パス（`./` `../`）や絶対パス（`/src/`）が混入していないか
- IMAGE_PROMPT コメントの有無を確認

### 3.5. 改行（段落区切り）チェック

- [ ] コードフェンス・表・リストの外で、地の文の行が空行なしで連続していないか（単一改行は描画時に結合され、1段落に詰まる）
- 検出: コードフェンス外で「空行・見出し・表・リスト・コメント以外の行」が2行続く箇所を列挙する（`REGEX_LIBRARY.md` の「段落区切り漏れ」参照）

### 3.6. 改行コード確認

- [ ] ファイルが LF のみか（CRLF・混在がないか）。確認: `git ls-files --eol <ファイル>`（新規ファイルは `file <ファイル>` で `CRLF` が出ないこと）

### 4. ヘッダー規約確認

- `「」` 括弧を使った見出しがないか
- `## 1. タイトル` のような番号付き見出しがないか

### 5. ロングテールKW整合チェック（post_writer.md Step 0）

- [ ] 本文冒頭に `TARGET_KW` / `READER` / `ANSWER` / `TAKEAWAY` コメントがあるか（Hub記事は対象外）。READER にセグメントコード（例: `S3-義務-検討前 / 検索`）が入っているか
- [ ] `title` の前半（約20文字以内）に主KWが入っているか。読者の言葉（落ちた・いらない・どっち等）を使っているか
- [ ] `title` に `完全攻略` `徹底解説` `まとめ` 等の汎用語だけで埋めた部分がないか
- [ ] `excerpt` / `metadata.description` に主KWが1回入り、READER の状況と答えの方向性が書かれているか

### 6. リード・読了設計チェック（post_writer.md Step 0-3 / 0-4）

- [ ] リード（最初の H2 の前）が「状況 → ひねり → 答えの方向性 → 読後の約束」になっているか
- [ ] リードで結論を言い切っていないか（「結論：〜です」で完結していないか）。逆に、何の記事か分からない思わせぶりになっていないか
- [ ] 主チャネルが検索の場合、答えの方向性が1画面目（リード内）に出ているか
- [ ] 各 H2 の末尾に、次の見出しへつなぐ問いがあるか
- [ ] 新しい用語が1つの H2 に4個以上出ていないか。用語は身近な例 → 正式な用語の順で導入されているか
- [ ] 答えの全体（判断表・結論）が、仕組みの説明の後に置かれているか
- [ ] まとめで、リードの状況・問いに戻って答えを1行で示し、TAKEAWAY を「説明・判断できるようになったこと」として回収しているか
- [ ] 主KWと関係のない H2（試験概要・合格率一覧など Hub の役割の内容）が混ざっていないか
- [ ] `## 合格までの勉強時間` が、勉強時間・学習計画系のKW以外で挿入されていないか

### 7. タグ正規化確認

以下のエイリアスが使われていないか確認する（tag_rules.md の正規タグ名を使用すること）:

- `ITパスポート` ✓ / `IP`, `Iパス` ✗
- `基本情報技術者` ✓ / `FE`, `基本情報` ✗
- `応用情報技術者` ✓ / `AP`, `応用情報` ✗
- `情報処理安全確保支援士` ✓ / `SC`, `登録セキスペ` ✗

## 出力フォーマット

各チェック項目について `✅ OK` / `⚠️ 要修正: {詳細}` の形式で報告する。
問題がある場合は修正コマンドを提案する（実行はユーザーの判断に委ねる）。
