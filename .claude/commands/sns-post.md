# SNS投稿（Threads）週次作成

対象週: $ARGUMENTS（例: `w41` または `10/5-10/11`。空の場合は `post-task.md` の現在の記載内容と `archive/log.md` の最終日から次週を判断する）

`.workspace/sns-post-work/` 配下のThreads投稿を、ペルソナ起点の選定ロジックで作成し `post-task.md` に書き出す。投稿は週3本、すべて連投（スレッド）形式。1件目は結論を出さず、興味づけに徹する。

## 手順1: 規約の読み込み

以下を<strong>並列で</strong> Read する:

1. `.workspace/sns-post-work/CLAUDE.md` — 運用ルール全体
2. `.workspace/sns-post-work/sns-tone-parameter/README.md`・`persona-channel-map.md`・`weekly-rotation-template.md`・`app-directory.md`
3. `.workspace/draft/sns/posting-strategy.md` — 型定義（A〜G）・配分ルール（週3本）・スレッド形式・フック絵文字ランダム性ルール・用語表記ルール
4. `.workspace/sns-post-work/archive/log.md` の直近2週間分 — 直近のペルソナ・型・トーン・連投の目印方式の配分を把握する

前週分に `[x]` 済みで `post-task.md` に残っているブロックがあれば、先に `archive/CLAUDE.md` の手順でアーカイブ処理を終わらせる。

## 手順2: 記事候補の洗い出し

- `.workspace/task-results/article-index.md` を Read する。古い可能性がある場合は `node .workspace/scripts/index-articles.js` を実行してから読み直す（手動スキャン・記憶による記事一覧の把握は禁止）
- `weekly-rotation-template.md` の基本ローテーション雛形（週3投稿: ①価値提供＋②導線＋③E）に沿って、投稿日（火・木・土 21:00）ごとに届けたいペルソナ（#1〜8）を仮決めする
- 各ペルソナに対応する元記事・アプリ候補を`persona-channel-map.md`の性質列から絞り込む

## 手順3: 重複チェック（必須・スクリプト実行）

候補が固まったら、**必ず**以下を実行して機械的に判定する。目視・記憶による「多分大丈夫」判断は禁止。

```bash
node .workspace/scripts/check-sns-topic.js <候補1のcategory/slug> <候補2のcategory/slug> ...
```

- exit code が 0（すべて🟢）になるまで、🔴と判定された候補を別の記事に差し替えて再実行する
- 型F（クイズ誘導型）でアプリに誘導する場合は、`app-directory.md`の`status: stable/beta`一覧からのみ選ぶ（development状態のアプリは誘導しない）

## 手順4: 執筆（連投形式・大衆性重視）

元記事を**全文 Read** し、記事固有の具体（数字・用語・プロンプト・事例）を2つ以上見つける。そのうえで次のルールで書く（正本は `posting-strategy.md`「投稿フォーマット」「スレッド形式」）。PREP（結論先出し）は使わない。

**スレッドの役割（標準4スレッド。3〜5可、既定4）**
1. **フック**: 共感・意外性・数字・損失回避・問いのどれかで「続きを読みたい」を作る。**結論・答え・理由を出さない**。専門用語・略語・概念名を出さない。1〜3行
2. **共感・状況**: 「あるある」「よくある失敗」「世間の常識」を具体で見せ、自分事にする。まだ答えを出さない
3. **答え**: フックで匂わせた答え・意外な事実・手順の核を**1点だけ**出す。元記事の具体の中心はここ。全体像は詰め込まない
4. **行動**: 一言でまとめ、「記事はこちら」＋絵文字＋URLで誘導。新しい論点を足さない
- 薄い題材は3スレッド（1 フック／2 共感＋答え／3 まとめ＋誘導）にする。匂わせた答えは必ず回収する（釣りで終わらせない）。水増しのためにスレッドを増やさない

**大衆性**
- スレッド1〜2は中学生にも通じる言葉で書く。概念名は答えのスレッド以降に出す
- フックの型（共感／意外性／数字／損失回避／問い）を週内でローテーションする
- 説明しない・教えきらない・網羅しない。一文40字以内、1スレッド250字以内を目安（上限500字）、全体400〜800字。「です・ます」調で話しかける
- 「IPA」を単独略称で使わない（正式名称を使う）

**連投の目印（週内で同じ方式を連続させない）**
- 「（1/N）」方式: **各スレッド本文の末尾（URLより後ろ）に、1行空けて単独行で**「（1/4）」「（2/4）」…と総数Nを入れて置く。フックは目印なしで「？」か絵文字で結ぶ
- 「続きます👇」方式: ルートの**フック文末**（疑問形なら「？」の直後）に置き、最終スレッド以外の各スレッド末尾にも単独行で置く。最終スレッドには置かない

**URL・絵文字**
- URLはルート（スレッド1）に入れない。誘導のある投稿は**最終スレッド**に「記事はこちら」（記事以外は「トップページはこちら」等）＋絵文字1つ＋URLの順で置く。型A・Eなど誘導先のない投稿はURLなし
- 絵文字は連投全体で3〜6個、各スレッド0〜2個。フック文末・箇条書きの行頭・段落の締め・誘導の行に置いてリズムを作る。同じ絵文字を連続で使い回さない。1行に複数並べない
- 疑問形フックは必ず「？」で結ぶ（「。」で止めない）。疑問形にしない回は、絵文字を添えた言い切り・数字提示にする

**書式（`post-task.md`）**
- 各スレッドの本文を、**インデントなしの ```` ```post ```` コードブロック**に入れ、直前に `**スレッドN**`（ルートは `**スレッド1（ルート）**`）の見出しを置く。ブロックの中身だけが投稿本文で、見出し・チェックボックス・メタ情報は含めない
- チェックボックス・日付・時間・型・元記事・連投の目印の方式はリスト項目（`- [ ] **日付 — 型X（①…・ペルソナ#N）**` ＋ 2スペースインデントの子項目）に書く。本文ブロックはそのリストの外（インデントなし）に書く
- 元記事は `https://syllabushack.com/{category}/{slug}/` のフルURL形式で記載する

## 手順5: セルフチェックと書き出し・台帳更新

書き出す前に、全投稿が次を満たしているか確認する（満たさなければ直す）。

- [ ] 全投稿が連投形式（3〜5スレッド）で、各本文が ```` ```post ```` ブロック（インデントなし）に入っている
- [ ] スレッド1が結論・答え・理由を出していない。専門用語・概念名を使わず、続きを読みたくなる内容になっている
- [ ] フックで匂わせた答えを、答えのスレッド（統合版は2）で回収している
- [ ] 連投の目印が入っていて、週内で方式が連続していない（「（1/N）」の番号は各スレッド末尾の単独行）
- [ ] URLがルートに入っていない。誘導のある投稿は最終スレッドにURLがある
- [ ] 各スレッドが500字以内（目安250字）。元記事の固有の具体が2つ以上、スレッド2〜3に入っている
- [ ] 絵文字が連投全体で3〜6個に収まり、連発・使い回しがない

確認後:
- `.workspace/sns-post-work/post-task.md` に、上記の書式でチェックボックス付きで書き出す
- `.workspace/sns-post-work/used-topics.md` に、使用した記事を「予定」ステータス・使用予定日つきで追記する

## 禁止事項

- `check-sns-topic.js` を実行せず、記憶や目視だけで「このネタは使っていないはず」と判断すること
- development状態のアプリ（`app-directory.md`参照）を型Fの誘導先にすること
- 週内で同じ型・同じペルソナ番号を連続させること
- 元記事のない投稿（型E等）以外で、リンク・元記事情報を省略すること
- 1ポスト完結の単発投稿を作ること（2026-10-06以降は全投稿が連投形式）
- スレッド1で結論・答え・理由を出すこと、PREP（結論先出し）で組み立てること、スレッド1〜2で専門用語・概念名を使うこと
- フックで匂わせた答えを回収しないこと（釣りで終わらせる）
- ルート（スレッド1）にURLを入れること、スレッド本文をインデント付きで書くこと、本文ブロックに見出し・メタ情報を混ぜること
