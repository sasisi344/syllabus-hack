# 学習体験の共有ルール（2026-10-19制定）

2026-11-27 に `CLAUDE.md` から移した（中身は変えていない）。`CLAUDE.md` には要点だけを残している。

### 方針

- 「生成AI×学習」のコンセプトは継続する。変えるのは届け方
- 筆者自身が記事・コースを実際に学習し、わかりにくかった所・間違えやすかった所にコメントを入れる
- 目指す体験は、講義中に隣の席の人と「ここ、わかりにくいよね？」と話す感覚。読者が「わかる、その気持ち」と感じ、一人で抱え込まずに読み進められるようにする
- **AI 活用は、学習方法のひとつとしてプロンプト例を示すまでにする**（2026-11-15 ユーザー決定）。AI の回答は毎回変わり、筆者は多くの資格を受験・学習していないので、実行結果（回答・画面）は載せない。`AI_EXAMPLE` マーカーも置かない。書けるのは「プロンプトをこう組むと、回答を確かめやすい」という方法の説明まで。すでにある「〇〇で実行した結果」の節は筆者の実行記録なので残す
- 最優先は20時間コース（`src/data/course/`）。20時間で学びが完了するとは考えていないため。進捗は `.workspace/.task/course-seat-notes.md` で章ごとに管理

### callout の種類（筆者が記事・アウトラインに書く）

| callout | 意味 | 読者への表示 |
| --- | --- | --- |
| `> [!forAI]` | 筆者からAIへの指示 | **表示しない**（ビルドで除去） |
| `> [!exp]` | 筆者が実際にやった感想（出題へのリアクション） | 緑の吹き出し「やってみて思ったこと」（目立つ） |
| `> [!question]` | 問題に対する質問で深掘り（出題へのリアクション） | 青の吹き出し「この問題、ここが気になる」（目立つ） |
| `> [!think]` | 筆者が疑問に思ったこと | 黄の控えめなメモ「ここ、引っかからない？」 |

- `.md` 記事・`.mdx` コースの両方で import 不要。変換は `src/utils/frontmatter.ts` の `learnerCalloutRemarkPlugin`
- `> [!think] 独自ラベル` のように同じ行に書いた文は、次の行に本文が続くときはラベル、1行だけなら本文になる
- `[!NOTE]` `[!TIP]` `[!important]` など他の callout は変換しない

### AIの扱い方

- **`[!forAI]`**: その箇所への筆者の指示として本文に反映する。作業中のドラフトでは残し、本番移行時に削除する
- **`[!exp]` / `[!question]` / `[!think]`**: 筆者の言葉。置かれた場所のまま残し、**内容に合わせて周囲の本文を書く**（例: think で「わかりにくい」とあれば、その点を本文で丁寧に説明する。exp と矛盾する記述をしない）
- **`[!question]`**: 直後か次の節に答え、または答えへの道筋（解説かAIプロンプト）を置く。読者を問いのまま放置しない
- **創作禁止（最重要）**: exp / question / think をAIが書くこと、AIが一人称の学習体験（「私も最初は〜」）を創作することは禁止。AIが直してよいのは誤字・改行・`**`→`<strong>` のみで、意味は変えない
- コメントがあるとよい箇所を見つけたら、提案だけ残す: `<!-- LEARNER_NOTE: 候補=〇〇と△△の混同 / 種類=think / 筆者の実体験で記入 -->`。筆者が callout で記入するか削除する。未処理のまま本番移行しない

### 配置と密度

- 該当する概念・問題・解説のすぐ後に置く。記事末尾にまとめない。リードには入れない
- exp / question は出題へのリアクションなので、該当問題・章末チェック・その解説の直後に置く
- 目安は記事で0〜2個、コース1章で2〜4個。1つのH2につき最大1個（2026-10-27 変更。多すぎると作り話に見えるため、記事には全部入れない）
- 体験を書けるのは、筆者が実際に受験・学習・実務で使った範囲だけ（`src/data/author-exam-status.ts`）。未受験の資格の記事では書かない。未受験であることは記事末尾の執筆者欄に自動で出る。AIの実行結果（画面・回答）への一言は、どの記事でも書ける
- 語り口は読者の隣から。「簡単です」「当然ですが」は使わない。1〜3文で、解説そのものは本文に任せる
