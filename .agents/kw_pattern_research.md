# KWパターンリサーチ — スキル定義

## 1. 適用タイミング

以下を開始する**前**に本スキルに従うこと。記事を直接書くためのテンプレートではなく、`cert_keyword_db.md` の KW DB（`*-kw-db.md`）を新設・拡張する**前段のリサーチ工程**で使う。

- `.workspace/data-set/cert-keyword-db/` に未登録の新規資格を調査するとき
- 既存 `*-kw-db.md` の状態が `×未着手` / `△不足` の行を拡充するとき
- `.workspace/.task/TODO.md` の「未登録資格を探す」案件に着手するとき

## 2. データソース

```
Read(.workspace/data-set/kw-pattern-library.md)
```

P1〜P9 のパターンテーブル・競合占拠度の実査基準・ニッチKW選定基準（AND条件）はすべてこのファイルにある。本スキルはその使い方（手順）のみを定義する。

## 3. 手順

1. **資格名を確定**: 正式名称＋通称を `.workspace/.task/exam-id-catalog.md` で確認（未登録なら新規行を仮置き）
2. **候補KW生成**: `kw-pattern-library.md` の P1〜P9 テンプレートに資格名（`{C}`）を当てはめ、各パターン2〜3語、合計20〜30語程度の候補リストを作る
3. **競合占拠度の実査**: 生成した候補それぞれを `WebSearch` で検索し、上位5件のドメインを「頻出競合プレイヤー」リストと照合して 高/中/低 を判定する
   - P1・P8・P9（既定値が高〜中）は実査優先度を下げてよい（既定値どおり高確率で高占拠のため）
   - P2・P4・P5・P6・P7（既定値が低〜中）を優先的に実査する
4. **ニッチ×需要ありKWを抽出**: `kw-pattern-library.md` の「ニッチ×需要ありKWの選定基準」AND条件（占拠度低〜中 × パターンP2/P4/P5/P6/P7 × 検索意図が具体的）を満たす候補を選定
5. **DBへの記録**: 抽出結果を該当 `*-kw-db.md` のキーワードマップ表に追記する。既存列（KW / 検索意図 / 記事タイプ / 優先度 / 状態 / 差別化角度 / 既存記事slug）に加え、**`方向性パターン`列（P1〜P9のコード）を追加**して記録する
6. **インデックス更新**: `.workspace/data-set/cert-keyword-db/index.md` の最終更新日と該当行を更新
7. **記事化判断**: 占拠度「高」のP1/P8/P9系候補は新規スポーク記事の主軸にしない。Hub記事の入口導線、または既存差別化角度（AI活用等）を強く掛け合わせた場合のみ例外採用する（`kw-pattern-library.md` 末尾の例外条件参照）

## 4. 出力後の連携

記事化フェーズに入る場合は通常フローに合流する。

```
Read(.agents/cert_keyword_db.md)      # KW DBから記事企画への結びつけ
Read(.agents/cert_hub_template.md)    # Hubの場合
Read(.agents/post_writer.md)          # 執筆ルール
```

## 5. 再調査のタイミング

- P5（制度変化）系のKWは半年〜1年で占拠度が「高」に変わりやすいため、Hub記事の `lastmod` 更新時に再実査する
- 新しい競合プレイヤーを発見したら `kw-pattern-library.md` の「頻出競合プレイヤー」リストに追記する
