ITパスポートや基本情報技術者試験に合格して、次はもっと難しいIPAの試験に挑戦したい。そう思って調べ始めると、試験の種類の多さに迷っていないでしょうか。

SC、NW、DB、PMといった略称で紹介されることが多いのも、わかりにくさの原因です。略称だけでは、それが何の試験なのか判断できません。

この記事では、IPAの難易度が高い試験を<strong>正式名称ごとに</strong>整理します。対象は、応用情報技術者試験と、その上にある高度試験です。2027年度からは、これらがプロフェッショナルデジタルスキル試験（仮称）という新しい試験にまとめられる予定なので、その移り変わりもあわせて説明します。

読み終えたときには、今の仕事と目指すキャリアから、自分が受けるべき試験を選べるようにします。

## IPAの試験は難易度の段階で並んでいる

IPA（情報処理推進機構）が実施する国家試験は、難易度の段階で並んでいます。現行の制度では、おおまかに次のとおりです。

| 段階 | 主な試験 |
| --- | --- |
| 入門 | ITパスポート試験 |
| 基礎 | 情報セキュリティマネジメント試験、基本情報技術者試験 |
| 応用 | 応用情報技術者試験 |
| 高度 | 情報処理安全確保支援士試験、ネットワークスペシャリスト試験など9区分 |

この記事で扱う「高難易度」は、応用と高度の段階です。

応用情報技術者試験は、ITの知識を技術からマネジメント、経営まで幅広く問う試験です。高度試験は、その中からひとつの専門分野を深く問う試験で、記述式の問題や論文で、実務に近い判断や説明を求められます。

### 2027年度からはプロフェッショナルデジタルスキル試験へ

IPAは、2027年度から試験の区分を見直す予定です。公表されている見直し案では、<strong>応用情報技術者試験と高度試験を大きくまとめ直し</strong>、プロフェッショナルデジタルスキル試験（仮称）を新設するとしています。

| 現行（2026年度まで） | 2027年度からの予定 |
| --- | --- |
| 応用情報技術者試験、高度試験（情報処理安全確保支援士を除く8区分） | プロフェッショナルデジタルスキル試験（マネジメント・データ・AI・システムの3区分） |
| 情報処理安全確保支援士試験 | 一部を変更して継続 |
| － | データマネジメント試験（新設。ITパスポートの次のステップ） |

今から勉強を始める人は、「2026年度の現行試験を受けるか」「2027年度の新しい試験を待つか」も考えることになります。ただ、新しい試験の範囲の多くは、現行の応用情報と高度試験の知識と重なっています。今の試験に向けて学んだ知識は、新しい試験でもそのまま土台になります。

では、それぞれの試験はどんな内容なのでしょうか。まずは高度試験の入口になる応用情報から見ていきます。

## 応用情報技術者試験

<strong>応用情報技術者試験（AP）</strong>は、基本情報技術者の上の段階にあたる試験です。テクノロジ・マネジメント・ストラテジのすべての分野から、基本情報より深い内容が出題されます。

午前は選択式、午後は長い問題文を読んで記述で答える形式です。午後は、セキュリティ、ネットワーク、データベース、プロジェクトマネジメント、経営戦略などの中から、自分で問題を選んで解きます。

| 科目 | 形式 | 内容 |
| --- | --- | --- |
| 午前 | 四肢択一 80問 | テクノロジ・マネジメント・ストラテジの全分野 |
| 午後 | 記述式 | 11分野から5問を選ぶ（情報セキュリティは必須） |

合格基準は、午前・午後ともに100点満点中60点以上です。合格率はおおむね20%台で、基本情報より一段難しい試験です。最新の試験日程や方式は [IPAの公式サイト](https://www.ipa.go.jp/shiken/) で確認してください。

### 午後は「得意な分野を選ぶ」試験

午後は、情報セキュリティ（必須）のほかに、経営戦略、プログラミング、システムアーキテクチャ、ネットワーク、データベース、組込みシステム開発、情報システム開発、プロジェクトマネジメント、サービスマネジメント、システム監査の10分野から4問を選びます。

すべての分野を対策する必要はありません。<strong>自分の仕事や経験に近い3〜4分野に絞る</strong>のが基本です。

| 分野 | 向いている人 |
| --- | --- |
| プロジェクトマネジメント・サービスマネジメント・システム監査 | 文系・非エンジニア。技術の細かい知識より、状況を読んで説明する力が問われる |
| ネットワーク・データベース | インフラやDB設計の実務経験がある人 |
| プログラミング | コードを日常的に読み書きする人 |
| 組込みシステム開発 | 組込み開発の経験がある人 |

選ぶ分野を決める前に、候補の分野の過去問を1問ずつ解いてみて、時間内に解答欄を埋められるかを確かめると判断しやすくなります。分野の決め方は [応用情報の捨て問戦略](/method/ap-discard-strategy/) でくわしく扱っています。

### 記述は「根拠＋行動」の形で書く

午後の記述式は、問題文の状況を読み、設問の字数や観点に沿って自分の言葉で答える形式です。1つの設問の解答は数十字から百字程度が中心です。

IPAが公表している解答例を読むと、<strong>「〇〇という状況であるため（根拠）、△△する（行動）」</strong>という形がくり返し出てきます。「パスワード管理を徹底する」だけでは、なぜそうするのかが伝わりません。根拠の部分を問題文から拾って書くのがコツです。

点が伸びないときによくある原因は、次のとおりです。

- 「2点述べよ」に1点しか書いていない、または同じ内容を言い換えて2点にしている
- 問題文に出てくる言葉を使わず、自分の言い回しで書いている
- 「情報が漏れないようにする」のように、用語（機密性の確保など）を使わずに書いている
- 字数制限を超えている

記述の練習の進め方は [応用情報の記述式で点が取れない理由](/method/ap-grader-blackbox-hack/) と [午後記述をAIで対策するプロンプト集](/method/ap-pm-descriptive-ai-prompts/) で扱っています。

### 応用情報が高度試験の入口になる理由

応用情報に合格すると、<strong>高度試験の午前Iが2年間免除</strong>されます。午前Iは応用情報の午前と同じ範囲の問題なので、そこを飛ばして、午後の記述や論文に集中できます。

免除のほかにも、応用情報の勉強は高度試験にそのままつながります。

- 午後の記述で練習する「状況を読み、根拠を示して答える」書き方は、高度試験の論文の骨組みになる
- プロジェクトマネージャやITストラテジストの問題では、ネットワークやデータベース、セキュリティの話も出てくる。応用情報で幅広く学んだ知識が、問題文を読み解く土台になる

いきなり高度試験の過去問から始めると、問題文に出てくる前提の知識を調べるだけで時間がかかります。高度試験を目指すなら、まず応用情報で幅広い知識と記述の力を固めるのが、無理のない順番です。

### ITパスポートから応用情報までの順番

ITパスポートから順に進むなら、<strong>ITパスポート → 情報セキュリティマネジメント試験または基本情報技術者試験 → 応用情報</strong>の順がおすすめです。

情報セキュリティマネジメント試験を間に挟むと、応用情報の午後で必須になるセキュリティ分野の土台を先に固められます。技術職を目指していてアルゴリズムも押さえたい人は、基本情報を挟みます。

## 情報処理安全確保支援士試験

攻撃の手口、検知の方法、対策を組み合わせて理解しているかが問われます。午後は記述式で、論文はありません。高度試験の中でも受験者が多く、春と秋の年2回受けられます。

## データベーススペシャリスト試験

<strong>データベーススペシャリスト試験（DB）</strong>は、データベースの設計・運用を担う技術者を対象にした試験です。

業務の要件からデータの構造を設計する概念データモデリング、正規化、SQLが中心です。問題文の業務の説明から、どんなデータの持ち方が適切かを読み取って答えます。

### ベクトル検索・RAGはDB設計にどう影響するか

これまでのDBは、厳密に定義されたスキーマと、整合性を保つ正規化されたリレーショナルデータ（RDB）が中心でした。生成AIの広がりで、テキスト、画像、音声のような形式が決まっていないデータを扱い、その「意味」で検索する<strong>ベクトル検索</strong>も、設計の対象になっています。

| 用語 | 内容 |
| --- | --- |
| ベクトル検索 | キーワードの一致ではなく、「意味の近さ」で情報を探す |
| 埋め込み（Embedding） | テキストや画像などを、意味を表す数値の並び（ベクトル）に変換すること |
| 近傍検索（ANN） | 膨大なベクトルから、似たものを高速に探す技術。厳密な最近傍ではなく、近いものを速く見つける |
| メタデータフィルタリング | 商品の色やカテゴリのような構造化データで絞り込み、ベクトル検索と組み合わせる |
| チャンキング | 参照させる文章を、AIが扱いやすい長さに区切ること。長すぎても短すぎても精度が落ちる |

実務では、ベクトル検索だけでは足りないことが多くあります。たとえば「赤いTシャツ」を探すとき、意味の近さに加えて、色やサイズの条件は厳密に絞り込む必要があります。RDBの強みである整合性や構造化データの条件と、ベクトル検索を組み合わせる、ハイブリッドな設計が求められます。

また、RAG（検索拡張生成）の回答精度は、参照するデータの質に左右されます。重複の排除、最新性の維持、鮮度の管理といった、DBの担当者が培ってきたデータ品質管理の知識が、AIの時代にもそのまま役立ちます。

## エンベデッドシステムスペシャリスト試験

<strong>エンベデッドシステムスペシャリスト試験（ES）</strong>は、家電や自動車、産業機器などに組み込まれるコンピュータシステム（組込みシステム）の開発を担う技術者を対象にした試験です。

ハードウェアとソフトウェアの両方の知識が必要で、機器の仕様を読み取り、制御の流れや設計の判断を記述で答えます。

## プロジェクトマネージャ試験

<strong>プロジェクトマネージャ試験（PM）</strong>は、システム開発のプロジェクトを計画し、進めていく責任者を対象にした試験です。

午後IIは<strong>論文</strong>で、自分が関わったプロジェクトの経験をもとに、問われたテーマについて書きます。進み具合の管理、リスクへの対応、関係者との調整などが毎年のように問われます。

- [PMの午後Ⅱ論述を、論文モジュールにして準備する方法（午後記述プロンプト集）](/method/ap-pm-descriptive-ai-prompts/)

### AIプロジェクトの品質管理

従来のシステム開発は、同じ入力には同じ出力が返る「決定論的」なものでした。生成AIは、同じ入力でも異なる答えを返すことがあり、「バグゼロ」を前提にした品質の考え方が通用しません。PMには、この不確実性をどう管理し、関係者と合意するかが問われます。

- <strong>品質を数値で定義する</strong>：再現率（実際に陽性のもののうち、正しく見つけられた割合）や適合率（陽性と判定したもののうち、実際に陽性だった割合）のような指標で、何を「合格」とするかを決める
- <strong>終わらない開発を防ぐ</strong>：精度の改善は、あるレベルを超えると、投じた時間に見合う成果が出にくくなる。期間で区切り、その時点で最善のものをリリースする、タイムボックスの判断が必要になる
- <strong>継続的な改善の仕組み</strong>：LLM（大規模言語モデル）に特化した運用の仕組みであるLLMOpsを、必要に応じて検討する
- <strong>AI特有のリスク</strong>：プロンプトインジェクション（悪意のある指示で、意図しない出力を引き出す攻撃）への備えとして、テストケースを増やす。著作権侵害のような倫理的なリスクも、早い段階で洗い出す

再現率や適合率の定義と計算は、試験でも問われます。機械学習の用語は、[教師あり学習と教師なし学習とは？](/theory/ml-supervised-unsupervised/)でも整理しています。

## ITストラテジスト試験

<strong>ITストラテジスト試験（ST）</strong>は、経営の課題をITでどう解決するかを考え、事業の戦略を立てる人を対象にした試験です。高度試験として、2027年度以降も区分が続きます。

試験名が抽象的で、ほかの高度試験に比べて認知度が高いとは言えません。けれど、難易度は高い試験のひとつです。

### どんな人が持っているとよいか

理想を言えば、CTO（最高技術責任者）のような経営に近い立場の人が持っている資格です。現実には、企業のIT部門の中枢にいて、経営の方針をシステムの計画に落とし込む人が持っていると、役割を説明しやすくなります。

実務で経営層と話す機会が少ない人にとっては、経験が遠い試験です。そのぶん、経験の少なさをどう補うかが、勉強の中心になります。

### 午後IIの論文は「経営課題→IT施策」の2段階で考える

午後IIは論文で、経営とITを結びつけた提案を書きます。受験生が苦労するのは、「DXを推進する」「AIを活用する」のような抽象的な言葉で終わってしまい、経営課題とIT施策の結びつきが弱くなることです。

次の2段階で考えると、論理がつながりやすくなります。

1. <strong>経営課題の特定</strong>: 顧客対応のコストが増えている、のような具体的な困りごと（Pain Point）を見つける
2. <strong>ITによる解決</strong>: その困りごとに対して、シラバスにある技術（AI、クラウド、データ活用など）を、なぜ・どう使うかを説明する

この2段階を、生成AIに壁打ちしてもらいながら考えます。

```text
あなたはITコンサルタントとして振る舞ってください。

ステップ1：「（経営上の悩み）」という抽象的な課題について、SWOT分析を行い、解決すべき具体的な課題を特定してください。
ステップ2：特定した課題に対して、AI、クラウド、データ活用などを使ったIT施策を提案してください。投資対効果の見込みと、経営層を説得する論理的なストーリーを含めてください。
```

AIの案は、そのまま使わず、公的な統計や業界の資料で裏付けを確かめてください。論文では、提案が現実的で、リスクやガバナンスにも触れているかが見られます。

- [ITストラテジスト論文で実務経験がないとき｜経験を補う順番と、今からできる業務の練習](/method/st-no-experience-essay-hack/)

### AI導入を「実験」で終わらせない役割

STの試験では、AIを導入するだけでなく、<strong>ビジネスの価値につなげる</strong>ことが重要なテーマです。

- <strong>PoCとPoV</strong>: PoC（概念実証）は「技術的に実現できるか」を確かめます。PoV（価値実証）は「ビジネスに利益や価値をもたらすか」を確かめます。PoCで満足せず、PoVまで進める視点が求められます
- <strong>投資対効果（ROI）</strong>: 経営層は、投資に見合うリターンを見ます。コスト削減などの「守り」と、売上や新しい価値を生む「攻め」を、バランスよく提案します
- <strong>AIガバナンス</strong>: 著作権、情報漏えい、誤情報（ハルシネーション）、公平性といったリスクに対して、利用ガイドラインやデータ保護の体制を整えます
- <strong>人の介在（HITL）</strong>: 重要な判断には、人間による確認を入れる設計にします。AIの不完全さを認めたうえでのマネジメントが、論文で評価されやすい点です

これらは、STが「何を証明する資格か」を表す例でもあります。技術を知っていることではなく、<strong>経営の目標とITをつなぎ、組織に定着させるまでを主導できる</strong>ことを示す資格です。

<strong>システムアーキテクト試験（SA）</strong>は、システム全体の構造を設計する人を対象にした試験です。業務の要件を、どんなシステムの構成で実現するかを考えます。

## ITサービスマネージャ試験

<strong>ITサービスマネージャ試験（SM）</strong>は、システムを安定して動かし続ける運用の責任者を対象にした試験です。障害への対応や、サービスの品質を保つ仕組みが問われます。午後IIは論文です。

## システム監査技術者試験

<strong>システム監査技術者試験（AU）</strong>は、情報システムが適切に作られ、使われているかを、独立した立場で確かめる監査の専門家を対象にした試験です。午後IIは論文です。

## プロフェッショナルデジタルスキル試験（2027年度新設予定）

<strong>プロフェッショナルデジタルスキル試験（仮称）</strong>は、応用情報と高度試験をまとめ直して新設される予定の試験です。次の3つの区分が予定されています。

- <strong>マネジメント区分</strong>: データやデジタル技術を使う仕事の進め方を管理する。プロジェクトマネジメントやIT戦略などが中心
- <strong>データ・AI区分</strong>: データを整備し、データに基づく活動を支える基盤をつくる
- <strong>システム区分</strong>: システムの要件定義、アーキテクチャの設計、開発、運用を主導する

試験は、共通の知識を問う科目A-1と、区分ごとの専門知識と技能を問う科目A-2・科目Bで構成される予定です。科目A-1は、情報処理安全確保支援士試験と共通になる予定です。

公開されているシラバス案をもとにした無料のコースを用意しています。

- [プロフェッショナルデジタルスキル（システム）試験 20時間コース](/course/pd-s/)

## データマネジメント試験（2027年度新設予定）

<strong>データマネジメント試験（仮称）</strong>は、主にビジネス部門の人を対象に、AIを使うためのデータの整備や管理の力を問う試験です。ITパスポートの次のステップとして位置づけられています。

## 自分に合った試験の選び方

ここまでの試験を、今の仕事と目指すキャリアから選ぶと、次のようになります。

| 今の仕事・目指す役割 | 最初の候補 |
| --- | --- |
| 基本情報の次に、幅広い知識を固めたい | 応用情報技術者試験 |
| セキュリティの担当・専門家を目指す | 情報処理安全確保支援士試験 |
| ネットワークの設計・構築 | ネットワークスペシャリスト試験 |
| データベースの設計、データ基盤 | データベーススペシャリスト試験 |
| 組込み機器の開発 | エンベデッドシステムスペシャリスト試験 |
| プロジェクトの責任者・管理職 | プロジェクトマネージャ試験 |
| 経営とITをつなぐ企画・戦略 | ITストラテジスト試験 |
| システム全体の設計 | システムアーキテクト試験 |
| システムの運用の責任者 | ITサービスマネージャ試験 |
| 監査・内部統制 | システム監査技術者試験 |

原則は、<strong>今の仕事でいちばん使っている知識を問われる試験から始める</strong>ことです。実務で見たことのある場面が問題文に出てくるので、記述や論文で書く内容に困りにくくなります。

論文試験は、自分の実務経験をもとに書く必要があります。実務経験がまだ少ない人は、記述式の試験（情報処理安全確保支援士、ネットワークスペシャリスト、データベーススペシャリストなど）から始めるのもひとつの方法です。

## 記述と論文はAIを採点者にして練習する

高度試験で多くの人が苦労するのが、記述式の問題と論文です。答えがひとつに決まらないため、自分の解答のどこが足りないのかを、一人では判断しにくいからです。

ここで生成AIを、採点者の目で読んでくれる相手として使えます。

```text
あなたは情報処理技術者試験の高度試験の採点者です。
以下の解答を読み、**根拠が薄い所・専門用語が足りない所・論理が飛んでいる所**を指摘してください。
最後に、改善した解答の例を1つ示してください。

【設問】:（ここに貼る）
【私の解答】:（ここに貼る）
```

AIの指摘は、過去問の解答例やIPAが公表している出題の趣旨と照らし合わせて確かめてください。

AIに解答そのものを書かせると、本番で自分の手で再現できません。使うのは、次のような<strong>考える手間を短くする場面</strong>に絞ります。

- 長い問題文を、時系列や原因と結果の関係に分けて整理してもらう
- 設問が何を求めているかを、箇条書きで書き出してもらう
- 自分の答案に足りない観点を指摘してもらう
- 論文の骨組みを2〜3案出してもらい、どれを使うか自分で決める

### 高度試験の勉強は午後問題から逆算する

高度試験を独学で進めるときは、次の順番にすると迷いにくくなります。

1. 応用情報の範囲で、理解があいまいな単元を書き出す
2. 受ける区分を1つに決める。論文型と記述型では練習の仕方が違うため、複数を並行しない
3. 午後の過去問を解きながら、足りない知識をそのつど補う
4. 間違えた原因を「知識が足りない」「問題文を読み違えた」「設問の要求を取り違えた」「時間が足りない」に分けて記録する

論文の練習の進め方は [記述式・論文問題をAIに採点してもらう練習法](/method/common-essay-ai-examiner/) でくわしく扱っています。

## 合格後のキャリアの広げ方

高度試験で身につけた専門知識は、ほかの資格にもつながります。

ネットワークスペシャリストの知識はクラウドのインフラ設計にそのまま応用でき、情報処理安全確保支援士のセキュリティ設計の視点は、クラウド環境のセキュリティにも役立ちます。クラウドの資格に広げるなら [AWS・CCNA・LPICの取る順番](/method/aws-hub/) を、特定のメーカーに依存しないネットワークの基礎を確かめたいなら [CCNAとは？勉強時間の目安とIPA試験でいうとどのレベルか](/method/ccna-hub/) を参照してください。

## まとめ

IPAの高難易度の試験は、幅広い知識を問う応用情報技術者試験と、専門分野ごとの高度試験に分かれています。

- まず応用情報で土台を固め、今の仕事に一番近い高度試験を選ぶ
- 論文試験は5区分。実務経験が少ないうちは記述式の試験から始める方法もある
- 2027年度からは、応用情報と高度試験がプロフェッショナルデジタルスキル試験にまとめられる予定。今の知識はそのまま新しい試験の土台になる

これで、略称ではなく試験の中身から、自分が受ける試験を選べるはずです。まずは上の表から、自分の仕事に一番近い試験を1つ選び、その試験の過去問を1問読んでみてください。
