試験まであと10日。

まだ参考書の半分も終わっていない。過去問を解いても、合格ラインに届かない。

そんなとき、「もう間に合わない」とスマホを置いて天井を見上げてしまう人は少なくありません。

けれど、直前の追い込みは、ITパスポートだけでなく、どの試験にも共通する悩みです。そして、10日あっても、<strong>1日2時間使えば20時間</strong>になります。シラバスハックの20時間コースと同じ長さです。

この記事では、残り10日を、限界を迎えてから慌てるのではなく、先に決めて動くための考え方と進め方をまとめます。最後に、ITパスポートを例にした頻出キーワードの確認リストもつけています。

## 最初に、自分に聞いてみること

いきなり勉強を始める前に、1分だけ、次の3つを自分に聞いてみてください。

1. この試験に、本当に合格したいのか
2. 合格したい理由は、何か（仕事、進学、会社からの指示など）
3. 受験料や時間を、ほかの誰かが出してくれていないか

受験料を親や会社が出してくれている場合、結果が出ないまま終わるのは、お金を出した側にとって、いちばんつらいことです。落ちること自体よりも、<strong>準備をしないまま、受けただけで終わる</strong>ほうが、あとに残ります。

反対に、答えが「あまり合格したくない」「別の試験を優先したい」であれば、それも大切な答えです。試験日の変更や延期が可能かどうかは、試験ごとに決まりが違うので、受験の公式案内で確認してください。

「合格したい」と答えられたら、残りの10日の使い方を決めます。

## 10日間は、1日2時間で20時間と考える

残りの時間は、「あと10日しかない」ではなく、<strong>「2時間 × 10日 = 20時間ある」</strong>と数え直します。

20時間は、基礎を整理して、弱点を埋めるには十分な長さです。範囲のすべてを理解しようとするのではなく、合格ラインに届くために必要な部分に、時間を集中させます。

| 日 | 内容 | 時間の目安 |
| --- | --- | --- |
| 1日目 | 過去問を1回分、通して解き、分野ごとの得点を出す | 2時間 |
| 2〜3日目 | いちばん落とした分野を、AIの説明と過去問で埋める | 各2時間 |
| 4〜5日目 | 次に落とした分野を、同じ手順で埋める | 各2時間 |
| 6〜7日目 | 間違えた問題だけを、もう一度解く | 各2時間 |
| 8日目 | 過去問を1回分、本番と同じ時間で解く | 2時間 |
| 9日目 | 8日目の間違いを見直し、頻出の用語を確認する | 2時間 |
| 10日目（前日） | 用語の確認だけ。早めに寝る | 1時間以内 |

日数が10日より少ないときは、同じ順番のまま、弱点の分野の数を減らします。

## 2時間が取れない日は、先にスケジュールを調整する

仕事や学校があると、毎日2時間をまとめて取るのは難しい日があります。そのときに、「今日は無理だった」と積み残していくと、最後に限界が来ます。

- 2時間を一度に取らず、朝30分・昼20分・夜70分のように分けて数える
- どうしても取れない日が出るなら、先に別の日に振り替える
- 休みが取れるなら、直前の1日だけでも確保する
- 睡眠を削らない。眠れていない頭では、覚えた内容が残りにくい

先に調整しておけば、「できなかった」という焦りが減り、続けやすくなります。

## 勉強の優先順位は、配点と弱さで決める

範囲の広い試験で、すべてを同じ重さで勉強すると、時間が足りません。次の順番で優先順位を決めます。

1. 合格ラインと、足切りの条件を、公式の案内で確認する
2. 1日目の過去問で、分野ごとの得点を出す
3. <strong>配点が大きくて、落としている分野</strong>から、時間をあてる

合格ラインは試験ごとに違います。たとえばITパスポートは、総合評価点が1000点満点で600点以上が合格ラインで、さらに分野ごとに30%以上の得点が必要です。100点を取ることを目指さず、合格に必要な点を取る戦い方に切り替えます。

## 生成AIを、弱点を埋める相手にする

直前期は、分厚い参考書を読み直す時間がありません。間違えた問題と、わからない用語を、生成AIに投げて、短い説明と確認クイズで埋めていきます。

```text
# 指示
あなたは**（試験名）**の試験対策の講師です。
試験まで残り**（日数）**日、1日**（時間）**時間しか使えない私が、合格ラインの**（点数）**に届くように、優先順位をつけて教えてください。

# ルール
1. 私が「間違えた過去問」や「わからない用語」を入力します。
2. あなたは解説に加えて、関連する重要キーワードを3つ選び、短く説明してください。
3. 最後に、理解を確かめる1問1答の短いクイズを出してください。
4. 私が正解するまで、別の角度から説明を繰り返してください。
```

AIの説明は、間違っていることがあります。気になったときは、過去問の解説や公式のシラバスで確かめてください。

## 前日と当日は、新しいことをしない

試験の前日は、新しい範囲に手を出さず、これまでに間違えた問題と、頻出の用語を見直すだけにします。

- 持ち物と会場、受付の時間を確認しておく
- 早めに寝る
- 当日は、わからない問題に長く止まらず、先に進む

直前に不安になって詰め込むと、かえって眠れなくなり、本番の集中力が落ちることがあります。

## 例：ITパスポートの頻出キーワード確認リスト

ここからは、ITパスポートを受ける人向けの例です。次のキーワードを「見た瞬間に説明できるか」で確認し、説明できなかったものだけをAIに聞いてください。

### ストラテジ系（出題の約35%）

- <strong>DX</strong>: デジタルを手段として、ビジネスモデルまで変える「変革」
- <strong>BCP</strong>: 災害が起きても事業を継続させるための計画
- <strong>サブスクリプション</strong>: 所有ではなく「利用」に対して対価を払うモデル
- <strong>知的財産権</strong>: 著作権（創作物を守る）と特許権（発明を守る）の違い
- <strong>財務諸表</strong>: B/Sはある時点の財産状態・P/Lは一定期間の損益
- <strong>SWOT分析</strong>: 強み・弱み・機会・脅威で戦略を整理するフレームワーク
- <strong>PPM</strong>: 花形・金のなる木・問題児・負け犬の4象限で事業を評価

### マネジメント系（出題の約20%）

- <strong>アジャイル</strong>: 小さな単位を繰り返す、スピード重視の開発手法
- <strong>ウォーターフォール</strong>: 上から下へ工程を順番に完了させる従来型開発
- <strong>SLA</strong>: サービスの品質基準をサービス提供者と利用者が取り決めた合意書
- <strong>内部統制</strong>: 会社が正しく動いているか自らチェックする仕組み
- <strong>PDCA</strong>: 計画・実行・評価・改善のサイクル
- <strong>WBS</strong>: プロジェクトの作業を階層的に分解した構造図

### テクノロジ系（出題の約45%）

- <strong>OS</strong>: ハードウェアとアプリの間を取り持つ基本ソフト
- <strong>LAN / WAN</strong>: 構内ネットワーク（LAN）と広域ネットワーク（WAN）
- <strong>公開鍵暗号</strong>: 「公開鍵で暗号化、秘密鍵で復号」の方向を確認
- <strong>ファイアウォール</strong>: 不正な通信を遮断するネットワークの関門
- <strong>SQL</strong>: データベースを操作する言語。SELECT・INSERT・UPDATE・DELETE
- <strong>仮想化</strong>: 1台のサーバーを複数の独立した環境に分けて使う技術
- <strong>IoT</strong>: モノがネットワークに繋がり、データを収集・活用する仕組み

ITパスポートの全体の進め方は、[ITパスポート 合格ロードマップ](/method/itp-hub/)にまとめています。

## まとめ

- 残り10日は、「あと10日」ではなく「1日2時間で20時間」と数え直す
- 勉強の前に、本当に合格したいのかを自分に聞く。出してくれた人がいるなら、準備せずに受けて終わることがいちばんつらい
- 2時間が取れない日は、限界が来る前にスケジュールを調整する
- 配点が大きくて、落としている分野から時間をあてる
- 前日は新しいことをせず、見直しと睡眠を優先する

まずは今日、過去問を1回分、通して解いて、分野ごとの得点を出してみてください。
