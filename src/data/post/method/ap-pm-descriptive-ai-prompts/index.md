## IPA高度試験の午後問題とは

<strong>IPAの高度試験</strong>とは、例として次のような<strong>情報処理技術者試験のLevel4</strong>に相当する区分の総称です（受験資格や試験区分の細部は[IPA公式](https://www.ipa.go.jp/)で必ず確認してください）。

- <strong>応用情報技術者</strong>（AP）… 科目Bなどに記述式の要素がある
- <strong>プロジェクトマネージャ</strong>（PM）… 午後Ⅰ・午後Ⅱなどに記述問題と論述
- <strong>情報処理安全確保支援士</strong>（SC）… 科目Bなどが記述式
- <strong>ネットワークスペシャリスト</strong>（NW）… 午後Ⅰ・午後Ⅱの長文シナリオと記述

これらに共通する最大の壁は、<strong>記述式解答の自己採点が極めて難しい</strong>ことです。模範解答を見ただけでは、「なぜ自分の言い回しではダメなのか」「どうすればその思考にたどり着けたのか」が分かりません。市販のテキストでも、本番さながらの記述の例題は数問程度に留まることが多く、あらゆるパターンの対策を立てるには足りません。

一方、<strong>生成AI</strong>なら、記述問題の作成、採点、添削、類題づくりまで任せられます。テキストを置き換えるというより、<strong>出題を繰り返しながら思考力を鍛える装置</strong>として組み合わせる使い方です。この記事は、そのためのプロンプト集です。

## どの試験に、どのプロンプトを使うか

| 試験 | 午後で苦労しやすいこと | 使うプロンプト |
| --- | --- | --- |
| AP | 解答例と自分の答えの違いの理由が分からない | 共通の採点・添削、ソクラテス式、類題、AI別の使い分け |
| NW | 長文シナリオで、解答の根拠がどこか特定できない | 読解→図解→AI添削の3段サイクル |
| PM | 午後Ⅱの論述のネタに困る | 実務経験の論文モジュール化 |
| SC | 長文インシデントの状況把握、科目Bの記述の自己採点 | タイムライン・構成図の生成、S.E.L.Fループ |

## ChatGPT・Gemini・Claude：どれが最適か

プロンプトは、<strong>ChatGPT・Gemini・Claudeのいずれでもそのまま使える</strong>ように書いています。

- 「この試験対策にだけ最適なモデルはこれ」という決め打ちは、基本的にありません。普段使っているサービスで構いません
- 各サービスには無料で使える範囲があり、その範囲でも出題、解答例の生成、添削は回せることが多いです
- 同じ論点の記述を何度も書いて添削を受ける学習は、紙や高価なテキストの「数問」だけより、生成AIが向いている場面が多いです

モデルの切り替えより、<strong>プロンプトの使い分け</strong>（厳しめの添削、ヒントのみ、類題生成）と、<strong>公式・テキストとの照合の習慣</strong>のほうが、合格に効きます。

## 共通プロンプト1：採点・添削（厳しめ）

最もよく使う添削用です。○×をつけるだけでなく、キーワードの過不足や論理の飛躍を厳しくチェックさせます。過去問や[科目Bケーススタディ](/app/ap-subject-b/)を自力で解き終わり、自分の解答の「ズレ」を知りたいときに使います。

```text
あなたは情報処理技術者試験（AP・高度試験）のベテラン講師であり、採点官です。
以下の【シナリオ】と【設問】に対する、私の【解答】を厳格に採点し、添削してください。

# 評価基準
1. 問題文の制約や条件（前提）を無視していないか
2. IPAが求める専門用語（キーワード）や概念が正しく使われているか
3. 論理の飛躍がなく、簡潔で説得力のある記述になっているか

# 出力フォーマット
- **採点（100点満点）**:
- **良かった点**:
- **不足しているキーワード/観点**:
- **減点対象となる論理の飛躍**:
- **講師による模範解答例（文字数制限などを考慮）**:

---
【シナリオ】
[ここに問題のシナリオ（長文）を貼り付ける]

【設問】
[ここに問われている設問を貼り付ける]

【私の解答】
[自分の書いた解答を入力する]
```

## 共通プロンプト2：答えを見ずに粘るソクラテス式ヒント

「解説を読んだらすぐ分かったのに、本番だと解けない」のは、気づきを得る過程を他人に任せているからです。手も足も出ないときは、答えを見る前に、AIから「良い質問」をもらいます。

```text
私は情報処理技術者試験の午後問題（記述式）を特訓中です。
以下の【シナリオ】と【設問】に取り組んでいますが、解答への道筋が見えません。

**[重要設定]**
絶対に「模範解答」や「直接的な答えとなる一文」を教えないでください。

**[依頼内容]**
私が自力で正解にたどり着けるように、ソクラテスの対話法で指導してください。
1回の返信につき**「私が着目すべきシナリオの1文」**や、**「矛盾を突くための1つの問いかけ」**を提示してください。
私の返答を待ってから、次のステップへ導いてください。

---
【シナリオ】
[ここに問題のシナリオを貼り付ける]

【設問】
[ここに問われている設問を貼り付ける]

【現在私が考えている方針や迷い】
[今どこで詰まっているかを素直に書く]
```

## 共通プロンプト3：もう一問の類題ジェネレーター

過去問を何周もすると、答えを覚えてしまいます。同じ論点で、場面だけが違う問題をAIに作らせると、応用力を試せます。

```text
あなたは情報処理技術者試験の作問委員です。
私が今学習した以下の【過去問の焦点】と全く同じ「問われる知識・論理展開」をベースにして、
「企業や業態などのシチュエーション」だけを現代風にアレンジしたオリジナル模擬問題（ケーススタディ）を1問、作成してください。

# 問題フォーマット
- 【シナリオ題材例】：クラウド移行、アジャイル開発、DX、セキュリティインシデントなど
- 文字数は300文字程度の短編シナリオにすること
- そのシナリオに関する記述式の設問を1つ用意すること（文字数指定あり）
※ このプロンプトの直後には、必ず「シナリオ」と「設問」のみを出力してください。解答は出力せず、私が回答するのを待ってください。

---
【過去問の焦点（学習した論点・使われたキーワード）】
[例：「標的型攻撃におけるラテラルムーブメントの検知と対策」、「フェールソフトの考え方に基づくシステム設計」など]
```

## 応用情報（AP）：AIをコーチにして、解答例との差を埋める

「自分の答えも意味は合っているはずなのに、なぜこの表現でないとダメなのか」という疑問が、記述への苦手意識の元です。AIは、あなたの具体的な解答に即してフィードバックできます。

| AIが見ること | 内容 |
| --- | --- |
| 意味の近さ | 解答例との違いが、本質のズレか、単なる表現の揺れかを判定する。表現を丸暗記せず、核となる概念の理解に集中できる |
| 不足しているキーワード | シラバスや業界で標準的な専門用語が、適切に使われているかを指摘する |
| 部分点の可能性 | 設問の要求をどの程度満たしているかを推測し、強化すべき要素を示す |

ツールごとの特性を活かした、短いプロンプトも使えます。

```text
あなたは応用情報技術者試験の午後記述式の採点官です。
以下の【設問】【公式解答例】【私の解答】を比較し、
1) 加点対象のキーワード
2) 減点される論理の飛躍
3) 30文字以内の改善答案
を提示してください。
```

```text
あなたはAP午後問題の添削者です。
長文シナリオを読み、設問の要求事項を先に分解してください。
そのうえで私の解答をA〜Dで評価し、Aに近づける修正案を1本示してください。
```

```text
応用情報午後の記述答案を点検します。次の3点だけをチェックしてください。
- 設問の要求事項に未回答がないか
- IPAシラバス用語の不足
- 主語と目的語の曖昧さ
最後に「最低限入れるべき語句」を3つ提示してください。
```

1つ目は、加点要素の抽出に向き、2つ目は、長文シナリオから設問の要求を分解して評価する用途に、3つ目は、抜け漏れの確認に向いています。使い続けるうちに、「この問題は、可用性ではなく機密性の話をすべきだ」「具体的な対策名よりも、その目的を書くべきだ」といった、記述の作法が自分の中に入ってきます。

AIは答えを教えるカンニングツールではなく、自分の思考の癖を映す<strong>鏡</strong>として使ってください。

## ネットワークスペシャリスト（NW）：読解→図解→AI添削の3段サイクル

NWの午後は、Ⅰ（知識の抜けのチェック）とⅡ（読む教材）で、過去問の使い方を変えます。

| 区分 | 過去問の役割 | 進め方 |
| --- | --- | --- |
| 午後Ⅰ | 知識の抜けのチェック | 時間を計って解き、知らない技術を洗い出す |
| 午後Ⅱ | 読む教材（参考書代わり） | 解き切ることに固執せず、シナリオと解説を精読する |

午後Ⅱは超長文で、本番では読解だけで時間が溶けます。「時間があるから余裕」と構えず、1問ごとに、次の3段サイクルを回します。

<strong>ステップ1：読解</strong>。いきなり書かず、設問が何を求めているか（理由を問う、対策を問う、動作を問う）を、AIと整理します。

```text
あなたはネットワークスペシャリスト試験の講師です。
以下の過去問シナリオを読み、解答はまだ教えないでください。

# 依頼
1. この問題が試そうとしている技術テーマ（例: VRRPの切替動作、BGP経路制御）を挙げる
2. なぜこのテーマが実務・試験で重要なのか、背景から説明する
3. 設問ごとに「何を問う型か」（理由説明型／対策提案型／動作記述型など）を分類する

【シナリオ】
（ここに問題文を貼り付け）

【設問】
（ここに設問を貼り付け）
```

<strong>ステップ2：図解</strong>。長文シナリオをMermaidの構成図に変換できた時点で、読解の大半は終わっています。解答の根拠がシナリオのどこにあるかが、視覚的に特定できます。図の描き方は、[ネットワーク図の書き方](/method/nw-mermaid-hack/)で扱っています。

<strong>ステップ3：解答</strong>。自分の言葉で書いたら、模範解答と見比べる前に、AIに添削させて、理解の穴を特定します。

```text
あなたはネットワークスペシャリスト試験の採点官です。
以下の【設問】に対する【私の解答】を添削してください。

# 評価基準
1. シナリオ中の根拠を踏まえた解答になっているか
2. 問われている型（理由／対策／動作）に正面から答えているか
3. ネットワーク用語が正確に使われているか（曖昧な用語は指摘）

# 出力フォーマット
- **判定**: 合格答案に届くか
- **根拠のズレ**: シナリオのどの記述を見落としているか
- **表現の改善**: 字数制限内での書き直し例
- **理解確認の質問**: 私の理解が曖昧そうな点を1つ、質問形式で

【シナリオ要約】
（ステップ2で作った図または要約を貼り付け）

【設問】
（設問を貼り付け）

【私の解答】
（自分の解答を貼り付け）
```

最後の「質問形式で1つ」が大切です。答え合わせで終わらせず、対話で理解の穴を掘り当てると、類似の論点が出ても対応できる知識になります。過去問が尽きたら、理解できたテーマに限って、共通プロンプト3の類題で確認します。過去問は、技術の変化が速い分野なので、新しいものから数年分を目安にするとよいでしょう。

## プロジェクトマネージャ（PM）午後Ⅱ：経験を論文モジュールにする

午後Ⅱの論述は、知識の羅列ではなく、自分のマネジメント経験を、設問に合わせて論理的に書く力を問います。対策の核心は、ゼロから書くことではなく、自分の経験を<strong>論文モジュール</strong>として用意しておくことです。IPAが公開しているシラバスの項目（進捗管理、品質管理、リスク管理など）に沿って、経験を200〜400字程度の部品に分けておくと、本番では設問に合わせて組み合わせられます。

同じプロンプトでも、モデルが変わると出力の癖が変わります。1つの受験シーズンでは、主役のツールを1つに固定します。

| 状況 | 固定先の目安 |
| --- | --- |
| 経歴の箇条書きが少なく、モジュールを何度も直したい | ChatGPT（同じスレッドで反復する） |
| 職務経歴が長く、案件が複数にまたがる | Claude（長文の整理に向く） |
| 移動中の下書きなど、量を出してから整形したい | Gemini（確定稿は別のツールで仕上げてもよい） |

```text
あなたは情報処理技術者試験の専門家として振る舞ってください。
これから私の「実務経験」の断片を渡します。
これを元に、プロジェクトマネージャ試験の午後Ⅱ論文でそのまま使える「論文モジュール」を作成してください。
論文モジュールとは、以下の要素を含む200〜400文字程度の文章の塊です。
1. 背景（プロジェクトの概要と制約）
2. 直面した課題（リスクや進捗の遅れ）
3. 具体的な対策（PMとしてのアクション）
4. 結果と評価（定量的・定性的な成果）
特に「シラバス」に記載されている重要テーマ（進捗、品質、リスク等）に適合するように整理してください。

私の経験：[ここに自身の経歴を箇条書きで入力]
```

AIが書くのは、あくまで自分の経験を整理した部品です。経験の事実を、AIに創作させてはいけません。本番で問われるのは、自分が実際に行ったマネジメントです。

## 情報処理安全確保支援士（SC）：状況の可視化と、再現答案の添削

SCの難しさは、2つあります。数ページに及ぶインシデントの状況把握と、自由記述の自己採点です。

### 長文インシデントを、表と図に変換する

誰が、いつ、どの端末で、何をしたのかを、AIに表と図へ整理させると、設問の推論（犯人や、抜けていた対策）に思考を集中できます。

```text
以下の情報処理安全確保支援士の問題文から、インシデントの経緯を時系列で整理してください。
出力はMarkdownの表形式で、【発生日時】【対象ホスト/サービス】【事象の詳細】【原因/一次対応】の列としてください。

問題文：
[ここから過去問をペースト]
```

```text
以下のネットワーク構成に関する記述を元に、Mermaid形式のネットワーク構成図を作成してください。
また、図の下に「セキュリティ上の懸念点（脆弱性）」を箇条書きで3つ挙げてください。

記述：
[ここからネットワーク構成の記述をペースト]
```

図ができたら、「攻撃者が内部ネットワークに侵入しうる経路を示して」と続けると、弱点を視覚的に学べます。AIの図は、自分の理解との差分を直す材料として使い、鵜呑みにはしません。

### S.E.L.Fループで、再現答案を添削してもらう

SCの科目B（記述式）は、サイト側では自動採点できません。そこで、AIを「模範解答を書く講師」ではなく、「自分の答案を編集する添削者」として使います。[S.E.L.Fループ](/method/self-loop-ai-learning/)の考え方を応用した、4段階です。

- S（Select）：過去問などから、1つのケースを選ぶ
- E（Extract）：AIに、採点者が見ている論点を構造化させる（模範解答は書かせない）
- L（Live）：論点を見ながら、自分の実務経験を交えて、答案を実際に書く
- F（Forge）：書いた答案をAIに添削させ、抜け落ちた視点を指摘してもらう

模範解答を先に読むと、本番でその文章をなぞろうとしてしまいます。先に論点だけを整理させます。

```text
あなたは情報処理安全確保支援士（SC）試験、科目B（記述式）の採点者です。
次のケースについて、模範解答は書かずに、採点者が答案のどこを評価するかという「論点」だけを整理してください。

【ケース】
（ここに過去問、またはケーススタディから選んだ場面を貼り付ける）

以下の形式で整理してください。
1. このケースで支援士に求められている役割（指導する相手は誰か、何を判断すべき場面か）
2. 答案で必ず触れるべき論点を3〜5個、箇条書きで
3. 実務経験があっても見落としがちな視点（法令・規程・他部門との調整など）
4. 加点される可能性が高い「具体性」のポイント（一般論で終わらせず、何を書くと差がつくか）
模範解答の文章そのものは書かないでください。あくまで論点整理までにとどめてください。
```

論点を見ながら答案を書いたら、添削を頼みます。

```text
以下は、情報処理安全確保支援士（SC）科目Bの練習問題に対して、私が実際に書いた答案です。

【ケースと論点】
（先ほどAIが整理した論点をここに貼り付ける）

【私の答案】
（自分で書いた答案をそのまま貼り付ける）

採点者の視点で、この答案を添削してください。
1. 論点のうち、答案で触れられているもの／抜けているものを整理
2. 抽象的な表現になっている箇所を指摘し、「もっと具体的に書くとしたら」の方向性だけ示す（文章を書き直さないでください）
3. 「指導・助言する立場」としての文体になっているか（作業者目線の記述になっていないか）を評価
4. 総合評価と、次に書き直すべき優先順位を1つだけ提示
模範解答は不要です。あくまで私の答案に対する添削としてフィードバックしてください。
```

1つのケースで、添削、書き直し、再添削を2〜3周すると、実務経験を試験向けの文体に変える感覚がつかめます。

学習の方向性に迷っている場合は、答案を書く前に、AIとの対話で弱点の正体を言葉にします。

```text
あなたは優秀なエグゼクティブコーチ兼、情報処理安全確保支援士（SC）試験の学習アドバイザーです。
私はSCの学習を進めていますが、自己診断テストの正解数が伸び悩み、何をどう学び直せばいいのか、まだ言葉にできていません。

【対話の進め方】
1. 一度に複数の質問をせず、必ず1回につき1つだけ質問してください。
2. 答えにくい質問には、具体的な選択肢や例を添えて答えやすくしてください。
3. 私の返答を深掘りし、「それは具体的にどの業務の話か」「なぜそこで迷ったのか」を掘り下げてください。
4. 対話を通じて、次の3つを順番に明らかにしてください。
   - ①診断テストで間違えた問題に共通する傾向（知識不足なのか、実務用語との対応づけができていないのか）
   - ②普段の実務でセキュリティに関わる場面のうち、自信を持って説明できないもの
   - ③その2つを踏まえて、優先して着手すべき章
5. 3つが出揃ったら、最後に「今の弱点の正体」と「最初に着手すべき章」を要約してください。
準備ができたら、まず最初の質問をしてください。
```

## AIに頼るときの注意点

AIは強力なパートナーですが、万能ではありません。

- <strong>ハルシネーション（誤り）に注意</strong>：存在しない専門用語や、IPAの採点基準と微妙に異なる解釈を出すことがあります。納得がいかないときは、公式の採点講評、過去問の解答例、シラバスと照合してください
- <strong>機密情報の入力は避ける</strong>：実務の実際のシステム構成や、顧客データを、そのままプロンプトの事例にしないでください
- <strong>経験の創作をさせない</strong>：論述や記述に使う経験や事実は、自分のものを使います。AIには、整理、構造化、添削を任せます

当サイトの[AP 科目B対策シミュレーター](/app/ap-subject-b/)で問題を選び、自分の解答を書いてから、このプロンプトと一緒にAIに渡す「アプリ×生成AI」の学習も相性がよい方法です。試験区分ごとの学習の進め方は、[情報処理安全確保支援士（SC） 合格ロードマップ](/method/sc-hub/)にもまとめています。
