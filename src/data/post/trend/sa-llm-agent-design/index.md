「AIエージェント」という言葉は、エンジニアの間でも、意味が少しずつ違って使われています。

自分で考えて、勝手に何でもやってくれる存在、と思っている人もいます。けれど、そう考えると、うまく使えない場面が出てきます。

この記事では、まずAIエージェントの基本原理を説明します。そのうえで、仕事に使うときの設計の考え方と、システムアーキテクト（SA）試験で問われる観点をまとめます。

## AIエージェントの基本原理

AIエージェントは、大規模言語モデル（LLM）に、<strong>道具を使う</strong>力と、<strong>結果を見て次の行動を決める繰り返し</strong>を加えたものです。

1. 目標を受け取る
2. LLMが、次に何をするかを考える
3. 道具（検索、ファイルの読み書き、他のシステムの呼び出しなど）を使って実行する
4. 結果を見て、まだ続けるか、終わるかを決める

LLM自身は、考えて文章を作る部分です。行動や記憶を持つのは、周りに組み込まれた仕組みです。つまり、エージェントは、自由に何でもできる存在ではなく、<strong>与えた目標、道具、ルールの範囲で動く</strong>仕組みです。

## 自律して動いてほしいなら、自動応答か定期実行が向く

「自律して動いてほしい」と考えたとき、いちばん設計しやすい形は、きっかけが決まっていて、毎回同じ流れで処理できるタスクです。

- 自動応答: 問い合わせが届いたら、回答案を作る、のように、イベントをきっかけに動く
- 定期応答: 毎朝、前日の記録をまとめる、のように、決めた時間に動く

何をきっかけに、何をして、どこへ出力するかが決まっている作業は、エージェントに向いています。反対に、目的がはっきりしない作業を丸ごと任せると、期待と違う結果になりやすくなります。

まずは、自分の仕事から、向いている作業を選び、AIに任せやすい形に整えます。AI駆動開発では、作業内容をそのAIに最適化することが大切です。

## 部署で考える｜監督役の自分と、従業員としてのAIエージェント

設計を難しく考えすぎる必要はありません。次のように置き換えると、考えやすくなります。

- 指示を出す自分、または代表: 監督役
- AIエージェント: 部署にいる従業員

こう考えると、仕事は上流から下流へ流れる、というイメージを持てます。ふだんの業務がどんな順番で流れているかを整理し、その流れを、AIへの指示として書いていきます。

## 指示は「やってはいけないことリスト」から作る

指示を作るときは、やってほしいことを並べる前に、<strong>やってはいけないことのリスト</strong>を先に作ります。

現在のAIは、作業のやり方そのものを、LLMがすでに知っています。そのため、仕事の内容を細かく教えなくても、次の程度の指示があれば、効率よく動きます。

- 仕事の内容（何を作るか）
- ファイルや出力の規則（名前の付け方、置き場所など）
- どこを参照するか（参照してよい資料、見てはいけない資料）

これに加えて、「勝手に外部へ送らない」「元のデータを書き換えない」「わからないときは推測せず質問する」のような禁則を、先に書きます。禁則があるほうが、思わぬ行動を防ぎやすく、品質も安定します。

## 品質チェックは、別のエージェントに任せる

禁則事項を守れているかの確認は、仕事をしたエージェント自身ではなく、<strong>別のエージェント</strong>に任せるのが定番です。

流れは、会社の業務に例えると、次のようになります。

1. 代表からの指示を出す
2. 部署が受理する（ここで品質チェック）
3. 従業員にタスクを渡す
4. 完了する
5. 品質チェック
6. 完成

最初の受け取りの時点と、仕事が終わった時点の、2回チェックを入れます。同じエージェントに作らせて同じエージェントに確認させると、見落としが残りやすいので、役割を分けます。

## SA試験で問われる設計の観点

ここまでの考え方は、システムアーキテクト試験で問われる、AIを組み込んだシステムの設計とつながります。

- <strong>応答時間とコスト</strong>: LLMの応答には時間がかかり、使うトークンの量に応じて費用も発生する。応答を待たずに次の処理を進める非同期処理や、イベントをきっかけに動くイベント駆動の設計が使われる。簡単な質問には安価なモデル、複雑な処理には高性能なモデルを使い分ける、というルーティングも考える
- <strong>RAG（検索拡張生成）</strong>: AIが学習していない社内の情報などを参照して答えさせる技術。ベクトルデータベースの選定と、情報を切り分けるチャンキングの設計が、回答の精度を左右する
- <strong>ガードレール</strong>: ハルシネーション（事実に基づかない回答）や、プロンプトインジェクションのような有害な入力を防ぐために、入力と出力を検査する仕組み。禁則リストと品質チェックの考え方は、これにあたる
- <strong>フィードバックループ</strong>: 稼働後も、ユーザーの評価をもとに、検索の仕組みや指示を改善し続ける

試験では、「なぜその設計を選んだか」を説明できることが求められます。上の観点ごとに、選ぶ理由を自分の言葉で書いてみてください。

## まとめ

- AIエージェントは、道具を使い、結果を見て次を決める繰り返しを持つ仕組み。目標、道具、ルールの範囲で動く
- 自律して動かしたいなら、きっかけが決まった自動応答や定期実行の作業から始める
- 自分を監督役、AIエージェントを部署の従業員と考えると、作業の流れを組み立てやすい
- 指示は、やってはいけないことのリストを先に作り、品質チェックは別のエージェントに任せる
- SA試験では、応答時間とコスト、RAG、ガードレール、フィードバックループの設計と、その選択理由が問われる

まずは、自分の仕事から、きっかけと出力が決まっている作業を1つ選び、禁則リストを書き出してみてください。
