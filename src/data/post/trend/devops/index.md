<h2>試験での出題ポイント</h2>
<p>試験では、「DevOpsを導入する最大の目的は何か」や、それを実現するための「自動化」について問われます。DevOpsは、現代のITサービス開発において非常に重要な概念であり、その本質を理解することが合格への鍵となります。</p>
<ol>
<li><strong>目的</strong>: 新機能リリースの頻度（スピード）を高めつつ、システム障害を減らす（安定性）。この両立を目指す。
    <p>従来のIT開発では、<strong>Development</strong>（開発）チームは新機能の追加や��善を迅速に行いたい一方、<strong>Operations</strong>（運用）チームはシステムの安定稼働を最優先するため、新しい変更には慎重になりがちでした。この開発と運用の間の対立は、ITサービスの提供を遅らせ、ビジネス機会の損失につながることもありました。DevOpsは、この壁を取り払い、両者が協力して「ビジネス価値を迅速、かつ高品質に提供する」という共通の目標に向かうことを目指します。ITパスポート試験では、この「開発と運用の協調」や「ビジネス価値の最大化」がDevOpsの導入目的として問われることが多いです。</p>
</li>
<li><strong>CI / CD</strong>: <strong>継続的インテグレーション（CI）</strong>と<strong>継続的デリバリー（CD）</strong>。コードの変更を自動でテストし、自動で本番環境へ反映させる仕組み。
    <ul>
        <li><strong>継続的インテグレーション（CI）</strong>：開発者が書いたコードを頻繁に共有リポジトリに統合し、その都度自動でビルドやテストを行う仕組みです。これにより、問題が早期に発見され、修正されるため、開発終盤での大規模な手戻りを防ぎ、ソフトウェアの品質を向上させます。試験では「コードの変更を頻繁に統合し、自動テストで品質を確保するプロセス」として出題されます。実務では、GitHubなどのバージョン管理システムとJenkinsやGitLab CI/CDといったCIツールを連携させ、コードのプッシュをトリガーに自動テストを実行する形で利用されます。</li>
        <li><strong>継続的デリバリー（CD）</strong>：CIで品質が保証されたソフトウェアを、いつでも本番環境にリリースできる状態に保つ仕組みです。手動でのデプロイ作業はミスや時間を要するため、自動化することでリリース頻度を高め、市場の変化に迅速に対応できるようになります。ITパスポート試験では、「テスト済みのコードを���つでもリリース可能な状態にする」という点が問われます。実務では、CIツールと連携して、テストが成功したビルドを自動でステージング環境にデプロイしたり、承認後に本番環境に自動デプロイできるように準備したりします。なお、手動承認なしで本番環境へ自動デプロイする手法は「継続的デプロイメント」と呼ばれ、CDをさらに推し進めたものです。</li>
    </ul>
</li>
<li><strong>アジャイル開発との関係</strong>: DevOpsはアジャイル開発と相性が良く、短いサイクルで改善を繰り返す現場で必須の考え方。
    <p>アジャイル開発は、短い開発サイクル（スプリント）を繰り返し、顧客のフィードバックを受けながら柔軟にソフトウェアを開発する手法です。DevOpsは、このアジャイル開発で生み出された「動くソフトウェア」を、CI/CDパイプラインを通じて迅速かつ安定してユーザーに届ける役割を担います。つまり、アジャイルが���何を」「どう開発するか」に焦点を当てるのに対し、DevOpsは「開発されたものをいかに早く、安定してユーザーに届けるか」を実現するものです。試験では、アジャイル開発とDevOpsが連携することで、ITサービスの提供サイクルが大幅に短縮され、ビジネス価値が最大化される、という文脈で問われることがあります。</p>
</li>
</ol>
