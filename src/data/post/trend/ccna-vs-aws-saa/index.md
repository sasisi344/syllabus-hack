CCNAとAWS SAAはどっちが先か。判断の分かれ目は、資格を持っているかより、サブネットと通信経路を説明できるか、どの仕事を目指すかです。

ネットワーク基礎から順に学ぶルートと、必要な基礎を補ってAWSから始めるルートを比べます。読み終えたときに、CCNAの認定取得まで進むか、部分学習にとどめるかを選べるようにします。

## 先に答えを知りたい人へ

- ネットワーク基礎が説明できず、ネットワーク運用も目指す：<strong>CCNA先行</strong>
- IPアドレス・経路を説明でき、AWS設計が目的：AWS SAA先行
- 転職を急ぐ・クラウド案件が目的：AWS SAA先行（VPC章だけCCNA範囲で補強）

自分の状況に近い行の詳細は、[状況別の優先順位](#状況別の優先順位)の表で確認できます。

## なぜこの順番の議論が重要なのか

インフラエンジニアを目指す人にとって、CCNAとAWS SAAは目指す仕事によって候補になる資格です。両方の取得が必須とは限らず、「どちらも取ればいい」という単純な話でもありません。学習には時間という有限のリソースが必要であり、順番を誤ると同じ内容を二度学び直すような非効率が発生します。

特に、ネットワークの基礎知識がゼロの状態でAWS SAAから学習を始めると、VPC・サブネット・ルートテーブルといった概念がすべて初見の単語として襲いかかってきます。一つひとつの用語を暗記はできても、「なぜこの設計が必要なのか」という本質的な理解に到達する前に、試験範囲の広さに圧倒されて構成を説明できないまま進んでしまうおそれがあります。

逆に、CCNAで基礎を固めてからAWS SAAに進むと、多くの概念が「知っているものの応用」として立ち現れます。この違いが、本記事で取得順番を論じる理由です。

## 2つの資格が証明するもの

CCNAはネットワーク基礎・アクセス・IP接続・IPサービス・セキュリティ・自動化などを扱います。公式範囲を使って、自分に不足する領域を確認できます。[CiscoのCCNA試験案内](https://www.cisco.com/site/us/en/learn/training-certifications/exams/ccna.html)

AWS SAAはAWSサービスを使った構成設計の知識・スキルを評価する認定です。資格の取得を、実務経験そのものとは分けて考えます。[AWSのSAA試験案内](https://aws.amazon.com/certification/certified-solutions-architect-associate/)

両者は別の試験ですが、<strong>CCNAで学ぶネットワーク知識とAWS SAAで問われるVPC設計は直接的な知識の継承関係があります</strong>。この継承関係を理解しているかどうかで、AWS SAAの学習にかかる体感的な難易度は大きく変わります。

## CCNAとAWS SAAの試験概要を比較

順番を決める前に、2つの試験の基本情報を並べておきます。

| 項目 | CCNA（200-301） | AWS SAA（SAA-C03） |
|---|---|---|
| 出題の中心 | ネットワーク全般（公式トピックで対象範囲を確認） | AWSサービスを使った設計判断 |
| 形式 | 選択式・ドラッグ＆ドロップ・シミュレーション | 択一・複数選択 |
| 問題数・試験時間 | 120分（問題数を固定して学習計画を作らない） | 65問・130分 |
| 実機操作の要素 | シミュレーション問題あり | なし |
| 有効期限 | 3年 | 3年 |
| 受験料 | 300 USD | 150 USD |

CCNAの出題範囲と配点の詳細は[CCNAとは？勉強時間の目安とIPA試験でいうとどのレベルか](/method/ccna-hub/)にまとめています。

試験時間・問題数・米ドル建て受験料は2026年10月31日確認、2026年10月時点の情報です。税・為替や受験地域で支払額が変わるため、申込画面を確認してください。認定の有効期間と更新条件は、[CiscoのCCNA認定案内](https://www.cisco.com/site/us/en/learn/training-certifications/certifications/enterprise/ccna/index.html)と[AWSの再認定案内](https://aws.amazon.com/certification/recertification/)を参照してください。

出典: [CCNA Exam（200-301）｜Cisco](https://www.cisco.com/site/us/en/learn/training-certifications/exams/ccna.html)、[AWS Certified Solutions Architect - Associate｜AWS](https://aws.amazon.com/certification/certified-solutions-architect-associate/)

為替や制度の改定で変わることがあるため、申込前に最新の公式情報を確かめてください。

AWS SAAの難易度は、非公式の合格率や合格までの時間で順位づけせず、公式のサンプル問題と出題範囲で確かめます。CCNAはネットワーク設定、SAAは構成選択の理由を説明できるかを比べてください。

## CCNAがAWS SAAの学習コストを下げる具体的な理由

### VPCはCCNAのネットワーク設計のクラウド版

VPCでは、CCNAの範囲にもあるIPアドレス・経路選択・アクセス制御の知識を使います。ただし、ネットワーク機器とAWSサービスは1対1で同じものではありません。

| CCNAの概念 | AWS SAAでの対応 |
|---|---|
| サブネット分割 | VPCのパブリック・プライベートサブネット |
| ルーティングテーブル | VPCのルートテーブル |
| NATの仕組み | NATゲートウェイ |
| ACL（アクセス制御リスト） | ネットワークACL・セキュリティグループ |

<strong>CCNAを先に取得していると、AWS SAAのVPC章が「既知の概念のクラウド置き換え」として理解できます</strong>。取得前でも基礎を説明できれば進められます。受験済みかどうかだけで入口を決めないでください。

### セキュリティ設計の論理が共通している

アクセス制御という考え方は共通でも、IAMは認証・認可、セキュリティグループとネットワークACLは通信制御を担います。AWSでは前者の通信制御はリソース単位、後者はサブネット単位です。[AWSのVPCセキュリティ](https://docs.aws.amazon.com/vpc/latest/userguide/VPC_Security.html)

「誰が何にアクセスできるかを論理で設計する」という思考パターンは両資格で共通しており、先に習得した側が後の学習コストを下げます。

### 障害対応・トラブルシューティングの思考回路が共通している

CCNAではping・tracerouteによる切り分け、OSI参照モデルに基づく層ごとの原因特定など、ネットワーク障害を体系的に切り分ける思考法を学びます。AWSでも経路や通信制御を確かめますが、S3のアクセス拒否などはIAMやリソースポリシーの確認も必要です。通信の問題だけに原因を限定しないでください。

CCNAで「どの層で問題が起きているか」を切り分ける訓練を積んでいると、AWS環境のトラブルシューティングでも同じ思考の型がそのまま使えます。逆にこの型を持たないままAWS SAAだけを学習すると、「なぜこの設定が必要か」を理解せずに手順だけを暗記する学習になりがちです。

### CCNAで学ぶなぜがAWS SAAの丸暗記を防ぐ

AWS SAAの学習でよくある失敗は、「サービス名と用途を暗記する」だけの学習に陥ることです。VPCエンドポイント、NATゲートウェイ、Direct Connectなど、似たような役割を持つサービスが多数存在するため、丸暗記では混同が起きやすくなります。

CCNAでネットワークの基礎原理（ルーティングはなぜ必要か、NATはなぜ必要か）を先に理解していれば、AWS SAAで登場する各サービスを「基礎原理の実装のひとつ」として位置づけられます。これにより、単なる用語暗記ではなく、構造的な理解に基づいた学習になります。

## AWS SAAのためにCCNAのどこまで学ぶか

「VPC章でつまずきたくないだけで、CCNAの全範囲は不要」という人もいるはずです。

その場合は、CCNAの出題ドメインのうち、VPC設計に直結する範囲から先に学びます。

| CCNAのドメイン | AWS SAAでの出番 | 優先度 |
|---|---|---|
| ネットワーク基礎（OSI・TCP/IP・IPアドレス・サブネット） | VPCのCIDR設計、サブネット分割 | 高 |
| IPコネクティビティ（スタティックルート・ルーティングの考え方） | ルートテーブル、VPCピアリング | 高 |
| IPサービス（NAT・DHCP・DNS） | NATゲートウェイ、DNS設定 | 高 |
| セキュリティ基礎（ACL・AAA・VPN） | セキュリティグループ、ネットワークACL、Site-to-Site VPN | 高 |
| ネットワークアクセス（VLAN・STP・EtherChannel） | 直接の出番は少ない | 低 |
| OSPFなどのルーティングプロトコル詳細 | 直接の出番は少ない | 低 |

この表は筆者の判断による優先度で、公式が定めた範囲ではありません。

<strong>優先度「高」の範囲だけでも、VPC章を「初見の用語の山」にしない効果は十分にあります。</strong>

ただし、CCNAという資格そのものが目的なら全範囲を学ぶ必要があります。部分学習は「SAAのための補強」と割り切ってください。

## AIで知識の継承関係を確認しながら学習する

CCNAの知識がAWS SAAにどう活きるかを実感しながら学習を進めると、モチベーションを維持しやすくなります。以下のようなプロンプトが有効です。

```text
CCNAで学んだ「ルーティングテーブル」の概念が、
AWSのVPCの「ルートテーブル」にどう対応するか、
共通点と相違点を表形式で整理してください。
実務でどちらか一方しか触ったことがない人にも
わかるように説明をお願いします。
```

```text
AWS SAAの学習を始めたのですが、VPC設計の章で
用語が多く混乱しています。CCNAで学んだ
ネットワーク基礎の知識と対応づけながら、
サブネット設計の考え方を説明してください。
```

### Geminiで実行した結果

1つ目のプロンプトを、Geminiで実行しました（2026年10月）。

回答は「比較表」と「片方しか知らない人向けの説明」の2部構成でした。比較表の要点は次のとおりです。

| 項目 | CCNA（オンプレミスのルータ） | AWS VPC |
| --- | --- | --- |
| 基本の役割 | 宛先IPを見て、次のルータやインターフェースへ転送する | 宛先IPを見て、インターネットや別のネットワークへ転送する |
| エントリの形 | 宛先ネットワーク＋ネクストホップ（または出力インターフェース） | 宛先CIDR＋ターゲット（`local`・`igw-`・`nat-` など） |
| ルートの選び方 | 最長一致（ロンゲストマッチ） | 最長一致（ロンゲストマッチ） |
| 持つ単位 | ルータごと | サブネットに関連づける |
| 動的ルーティング | OSPFやBGPで経路を自動で交換できる | 基本は手動で設定。VPN接続などでBGPを使う場面がある |

続けて、CCNA経験者に向けて次の2点が説明されました。

> - ネクストホップは「次のルータのIPアドレス」ではなく、`igw-xxxxxxxx`（インターネットゲートウェイ）のような<strong>AWSが管理するリソースのID</strong>になる
> - ルートテーブルは「ルータの中」ではなく「サブネット」に関連づける。そのサブネットのEC2から出た通信が、このテーブルを見る

AWS経験者に向けては、オンプレミスでは経路を自分で書くかOSPFなどで学習させる必要があること、物理ポートを意識することが挙げられていました。

> [!exp]
> 文章で説明させるなら、AIは本当に優秀です。ただ、ネットワークは「どこからどこへつながっているか」を図で見たほうがわかりやすいこともあります。Geminiなら「ちょっとわかりにくいから図解にしてほしい」と頼むだけで、図を作ってくれました。

「図解にしてほしい」と続けて頼んだときに、Geminiが作った図です。

![Geminiが作った、CCNAのルーティングテーブルとAWS VPCのルートテーブルの比較図](~/data/post/trend/ccna-vs-aws-saa/gemini-route-table-diagram.jpg)

左がルータ、右がVPCで、真ん中に共通点の「最長一致」が置かれています。全体像をつかむには十分です。

ただし、図の細かい所は崩れています。ルーティングテーブルの「Mask」の列がずれていたり、同じ説明文が2回出ていたりします。

宛先やネクストホップの値は、図ではなく文章の回答や上の表で確かめてください。

このように、新しく学ぶ知識を「すでに知っている知識との対応」として整理させることで、丸暗記ではなく体系的な理解につながります。特にAWS SAAの学習でCCNA知識が活きる場面は多いため、意識的にこの対応関係を確認する習慣を持つことをおすすめします。

## AWS SAAを先行させる判断が合理的なケース

すでにネットワーク実務経験がある場合は、AWS SAAを先行させることが合理的です。

サブネット設計・ルーティング・ACLを実務で日常的に扱っているエンジニアにとっては、AWS SAAのネットワーク関連章は「既知の概念のクラウド版」です。CCNAをわざわざ取得する前にAWSで先行し、後からCCNAで知識を体系化する逆ルートも有効です。

また<strong>クラウド求人を急いで取りに行く場合も、AWS SAAを先行させる判断はあります</strong>。VPC章での苦労を覚悟した上で集中投資することで合格は可能です。

## 未経験者がやりがちな失敗パターン

ネットワーク未経験からAWS SAAをいきなり学習し始めた場合に、よく見られる失敗パターンをいくつか紹介します。自分に当てはまっていないか確認してみてください。

- <strong>サービス名の暗記に終始してしまう</strong>: VPC・サブネット・ルートテーブル・NATゲートウェイなど、似た役割の用語が多く、意味を理解しないまま名前だけを覚えようとして混乱する。
- <strong>「なぜこの設計にするのか」を説明できない</strong>: 過去問は解けても、実際の設計課題（例：パブリックサブネットとプライベートサブネットをどう分けるか）に応用が利かない。
- <strong>セキュリティグループとネットワークACLの違いが最後まで曖昧なまま</strong>: どちらもアクセス制御の仕組みですが、ステートフルかステートレスかという違いは、ネットワークの基礎知識がないと直感的に理解しづらいポイントです。

これらの失敗は、ネットワークの基礎原理（なぜルーティングが必要か、なぜアクセス制御に階層があるのか）を理解しないまま、AWSサービスの使い方だけを表面的に学んでしまうことが根本原因です。CCNAの基礎学習はこれらを理解する土台になりますが、AWS固有の設定は別に確認する必要があります。

AWS SAA側の勉強法は、[AWS SAA初心者の現実](/method/aws-saa-beginner-reality/)で詳しく扱っています。

## 状況別の優先順位

| 状況 | 推奨順番 | 理由 |
|---|---|---|
| 経路を説明できず、ネットワーク運用も目指す | CCNA先行 | 基礎と設定演習をまとめて学ぶ |
| IPアドレス・経路の説明ができる | AWS SAA先行 | Linux経験だけではネットワーク理解の代わりにならない |
| 応募先でSAAが指定されている | 必要な基礎を補ってSAA先行 | 応募条件と学習範囲を一致させる |
| インフラ全般を体系化したい | CCNA先行 | オンプレ→クラウドの論理的な継承が作れる |
| セキュリティ分野に進みたい | CCNA先行 | ACL・ファイアウォールの基礎がクラウドセキュリティの土台になる |
| 学生・第二新卒で時間に余裕がある | CCNA先行 | じっくり基礎から積み上げる時間的余裕を活かせる |

この表はあくまで一般的な傾向であり、絶対的な正解ではありません。重要なのは、自分が置かれている状況（実務経験の有無、転職の緊急度、学習に割ける時間）を正直に棚卸しした上で、表のどの行に自分が最も近いかを判断することです。

## 学習時間の目安比較

順番による時間短縮を保証するデータは確認できないため、固定の比較時間は示しません。まず同じ学習枠で次の課題を試し、残りの範囲を見積もります。

| 前提 | 時間を測る課題 | 次の配分 |
| --- | --- | --- |
| ネットワーク未経験 | IPアドレスから宛先までの経路を説明する | 不明な基礎を先に学ぶ |
| 一部の基礎知識あり | ルート・NAT・アクセス制御の役割を分ける | 説明できない項目だけ補強する |
| 関連資格・経験あり | AWSの複数構成を比較して選択理由を説明する | AWS固有の可用性・権限・コストに配分する |

### CCNA→AWS SAAのスケジュール目安

たとえば週10時間なら、最初の2週間は合計20時間の診断枠にします。1週目は基礎と設定演習、2週目はAWSのサンプル問題と解説の確認に使います。これは合格までの必要時間の目安ではありません。

説明できなかった範囲と、1テーマにかかった時間から残りの計画を作り、毎週見直します。CCNA取得まで待つか、基礎の部分学習でSAAへ進むかも、この結果で判断できます。

## 両方取得した後のキャリアパス

CCNAとAWS SAAの両方を取得すると、オンプレミスとクラウドの両方を理解した「ハイブリッドインフラエンジニア」としての市場価値が生まれます。近年は完全なクラウドネイティブ環境だけでなく、オンプレミスとクラウドを併用するハイブリッド構成の企業も多く、応募先の構成と担当業務を確認し、両方の知識が必要かを判断します。資格数から採用や収入は保証できません。

さらに上位資格を目指す場合、CCNA取得者はCCNP（より高度なネットワーク資格）へ、AWS SAA取得者はAWS SAP（ソリューションアーキテクト プロフェッショナル）やAWS Advanced Networking（クラウドネットワークの専門資格）へとつながる道があります。CCNAとAWS SAAの両方を土台にしておくと、将来的にAWS Advanced Networkingのような「ネットワークとクラウドの両方の知識」を要求される上位資格にも無理なく進めます。

## よくある質問

<strong>Q. 両方同時に学習するのは非効率ですか？</strong>

A. 非効率になりやすい傾向があります。ネットワークの基礎概念とクラウドサービスの用語を同時にインプットすると、どちらも中途半端な理解にとどまりがちです。よほど時間に余裕がある場合を除き、順番を決めて集中する方が結果的に早く両方を取得できます。

<strong>Q. CCNAを取らずにAWS SAAだけ取得するのは悪い選択ですか？</strong>

A. 悪い選択ではありません。クラウド専業でキャリアを築く場合、CCNAの取得は必須ではありません。ただし、VPC設計やトラブルシューティングの理解を深めたい場合は、CCNAの該当範囲（ルーティング・NAT・ACL）だけを部分的に学習する、という選択肢も有効です。

<strong>Q. 情報処理技術者試験（ネットワークスペシャリスト等）との関係はどうなりますか？</strong>

A. ネットワークスペシャリスト試験はより理論・記述寄りの国家資格で、CCNAは実務・ハンズオン寄りのベンダー資格です。両方に共通する基礎知識は多いため、どちらかを先に学んでおくと、もう一方の学習コストも下がります。目的（国内企業向けか、グローバル・実務寄りか）に応じて選ぶとよいでしょう。ネットワークスペシャリストの学習では、[AIにネットワーク構成図を描かせる勉強法](/method/nw-mermaid-hack/)がCCNA・AWS SAAの構成理解にも応用できます。

<strong>Q. AWS CLF（クラウドプラクティショナー）は挟むべきですか？</strong>

A. AWSの用語や料金・責任共有モデルに慣れたい人には有効です。ただしCLFはクラウドの概念が中心で、VPCのネットワーク設計を補ってはくれません。CCNA→SAAの流れの代わりにはならないため、「CCNA→CLF→SAA」のように間に入れるのが現実的です。

<strong>Q. LPIC・LinuCはどこに入りますか？</strong>

A. サーバー操作が目的ならLinuxの学習を先に置けます。CCNA受験の前提資格ではありません。3資格の全体像は[AWS・CCNA・LPICの取る順番](/method/aws-hub/)で整理しています。

<strong>Q. 学習期間はどのくらい間隔を空けるべきですか？</strong>

A. CCNA取得後、間隔を空けすぎると知識が薄れてAWS SAAでの「対応関係の想起」がスムーズにいかなくなります。理想は1〜2ヶ月以内にAWS SAAの学習に着手することです。知識が新鮮なうちに関連づけることで、CCNAで学んだ内容の定着にもつながる相乗効果が生まれます。

## まとめ

CCNAとAWS SAAは、通信経路を説明できるかと、目指す業務で順番を決めます。ネットワーク運用も目指すならCCNA先行、AWS設計が目的で基礎があるならSAA先行が候補です。

受験前の部分学習も選択肢です。まず経路・NAT・アクセス制御を自分の言葉で説明し、不足する範囲を確認してください。筆者は両資格とも未受験です。上のGemini実行記録は、受験体験とは分けて掲載しています。
