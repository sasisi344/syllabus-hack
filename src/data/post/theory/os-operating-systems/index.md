OSは、コンピュータ全体を管理・制御する、最も土台となるソフトウェアです。アプリとハードウェアの間に立ち、CPU、メモリ、ファイルといった限られた資源を、うまく割り振ります。

ITパスポートでは「OSの役割と種類」が、基本情報技術者試験では「その管理の仕組み」が問われます。この記事では、両方を1ページに並べます。前半で全体像をつかみ、後半で仕組みの中身に進みます。

## OSの役割と3つの管理機能

OSは、ハードウェアとアプリケーションの橋渡し役です。ユーザーが複雑な電気信号やメモリの番地を意識せず、ボタンをクリックするだけで操作できるのは、OSが間に入っているからです。

| 管理機能 | 内容 |
| --- | --- |
| タスク管理 | CPUの処理時間を割り振り、複数のプログラムが同時に動いているように見せる |
| 記憶管理 | アプリが必要とするメモリ領域を割り当てる。足りないときは仮想記憶で補う |
| ファイル管理 | データがディスクのどこにあるかを把握し、要求に応じて保存・提供する |

### API、GUI/CLI、ディレクトリ

| 用語 | 内容 |
| --- | --- |
| API | アプリがOSの機能を使うための共通の呼び出し口。開発者がOSの内部を意識せずに、ファイルを開く、画面に表示するなどの機能を使える |
| GUI／CLI | GUIはアイコンやウィンドウをマウスで操作する方式。CLIはキーボードから命令（コマンド）を入力する方式で、サーバー管理や自動化に向く |
| ディレクトリ管理 | ファイルを木のような階層（ツリー構造）で整理する。絶対パスと相対パスの違いも問われる |

## OSの種類

| 種類 | 特徴 |
| --- | --- |
| Windows／macOS | PC向けの汎用OS。複数のアプリを同時に動かす<strong>マルチタスク</strong>が基本 |
| Linux | ソースコードが公開された<strong>オープンソース</strong>のOS。安定性とカスタマイズ性が高く、サーバーなどのインフラで広く使われる。配布版を<strong>ディストリビューション</strong>という |
| iOS／Android | スマートフォンやタブレット向け。省電力、タッチ操作、アプリストアを通じた配布が特徴 |

## タスク管理｜複数の処理を切り替えて動かす

CPUは同時に1つの処理しか実行できません。それでも複数のアプリが同時に動いて見えるのは、OSが極めて短い間隔で処理を切り替えているからです。この仕組みを<strong>タスク管理（プロセス管理）</strong>といいます。

### タスクの状態遷移

| 状態 | 内容 |
| --- | --- |
| 実行状態 | CPUを使って、実際に処理を進めている |
| 実行可能状態 | CPUの割り当てを待っている |
| 待ち状態 | 入出力の完了などを待っている（CPUを使わない） |

実行状態のタスクが入出力待ちになれば、待ち状態に移り、その間にCPUは別のタスクに割り当てられます。

### スケジューリング方式

どのタスクに次にCPUを割り当てるかを決めるルールです。

| 方式 | 概要 | 特徴 |
| --- | --- | --- |
| ラウンドロビン | 一定時間（タイムスライス）ごとに順番に割り当てる | 公平だが、切り替えのコストがかかる |
| 優先度順 | 優先度の高いタスクから実行する | 重要な処理は速いが、低優先度のタスクが待たされ続けることがある |
| 到着順（FCFS） | 実行可能になった順に割り当てる | 単純だが、長い処理が先に来ると後続が待たされる |

試験では、「タイムスライスを長くすると何が起こるか」のように、方式の特徴を理解しているかが問われます。

## 割込み｜処理を緊急に中断する

<strong>割込み</strong>は、CPUが実行中の処理をいったん中断し、優先度の高い別の処理に切り替える仕組みです。キーボード入力、ネットワークの受信、ハードウェアの異常のような、予測できないタイミングのイベントに対応するために使います。

| 種類 | 内容 |
| --- | --- |
| 外部割込み | ハードウェア（キーボード、タイマー、ディスク）からの信号による割込み |
| 内部割込み | プログラム自体が原因（ゼロ除算、不正な命令など）で発生する割込み |

処理の流れは、次のとおりです。

1. 割込みが発生すると、CPUは現在の処理状態（レジスタの内容など）を退避する
2. 割込みの種類に応じた処理ルーチンを実行する
3. 終わったら、退避した状態を復元し、元の処理を再開する

試験では、この「状態の退避と復元」の順序や、複数の割込みが同時に起きたときの優先度が問われます。

## 仮想記憶｜実メモリより大きな空間を扱う

<strong>仮想記憶</strong>は、実際に搭載されているメモリ（主記憶）の容量を超えるプログラムやデータを、扱えるようにする仕組みです。補助記憶装置（ディスク）の一部を、仮想的なメモリ空間として使います。

| 用語 | 内容 |
| --- | --- |
| ページング方式 | メモリを一定サイズの「ページ」に分けて管理する。必要なページだけを主記憶に読み込み、使われていないページはディスクに退避する |
| ページフォールト | 必要なページが主記憶にないときに起きる。ディスクから該当ページを読み込む |
| スラッシング | ページの入れ替えが頻発して、CPUがディスクの待ち時間ばかりになり、性能が著しく落ちる現象。主記憶の容量が不足したときの問題として問われる |
| ページ置き換えアルゴリズム | 主記憶がいっぱいのとき、どのページを追い出すかを決めるルール。代表が<strong>LRU</strong>（最も長く使われていないページを追い出す）で、頻出 |

## 生成AIで状態遷移を追う

OS制御は、言葉の定義よりも、状態がどう変わるかを図で追うほうが理解が速い分野です。

```text
タスクA（実行状態）が入出力待ちになり、
タスクB（実行可能状態）にCPUが割り当てられた直後に
タイマー割込みが発生した場合、タスクA・タスクBの状態は
それぞれどう変化するか、時系列で説明してください。
```

```text
主記憶が3ページ分しかない環境で、
参照順序が 1,2,3,4,1,2,5,1,2,3,4,5 のとき、
LRU方式でのページフォールト回数を教えてください。
```

```text
あなたはIT業界のベテランエンジニアです。
新入社員に、WindowsとLinuxの使い分けと、OSがそもそも何をしてくれる司令塔なのかを、
マルチタスクやファイル管理の用語を使って教えてください。
```

条件を変えた問題をAIに作らせ、状態遷移を書き出しながら確かめると、定着しやすくなります。AIの答えは、自分で手を動かした結果と照らし合わせてください。

## まとめ

- OSは、ハードウェアとアプリの間に立つ司令塔。主な仕事は、<strong>CPU・メモリ・ファイルという資源の管理</strong>
- 種類は、PC向け（Windows／macOS）、オープンソースのLinux、モバイル向け（iOS／Android）
- タスク管理は状態遷移とスケジューリング、割込みは状態の退避と復元、仮想記憶はページフォールト・スラッシング・LRUが試験のポイント
- 3つの仕組みはいずれも「限られた資源をどう効率よく共有するか」への答え
