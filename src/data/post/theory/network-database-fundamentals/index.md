OSI参照モデル・TCP/IP・サブネット・DNS・正規化は、「情報を届ける途中の話か、保存する側の話か」で分けると整理できます。

用語の定義を覚えても、設問でどれを選ぶか迷うことがあります。この記事では通信先の特定からDBの更新までをつなぎ、問題文の手がかりから仕組みを選べるようにします。

## なぜネットワークとデータベースはセットで出題されるのか

ITパスポート・情報セキュリティマネジメントでは、ネットワークとデータベースの両方が学習対象です。[IPAの試験要綱・シラバス](https://www.ipa.go.jp/shiken/syllabus/gaiyou.html)理由はシンプルで、どちらも<strong>「システムが正しく動くための土台」</strong>だからです。

- <strong>ネットワーク</strong>は「機器」「アドレス」「プロトコル（通信規約）」の3層で、情報を宛先まで正しく届ける仕組み
- <strong>データベース</strong>は「設計（正規化）」「操作（トランザクション・排他制御）」の2軸で、情報を正しく保存し続ける仕組み

この整理では、新旧の試験形式によらず、用語が担う役割の違いを押さえます。

| DB操作 | トランザクション・排他制御 | 同時アクセス時の正しさ | ACID特性、ロック、デッドロック |

## ネットワークの階層構造 — OSI参照モデルとTCP/IP

<strong>OSI参照モデル</strong>は、ネットワークの役割を7つの階層に分けた理論上のモデルです。物理層（ケーブル・ハブ）→データリンク層（MACアドレス・スイッチ）→ネットワーク層（IPアドレス・ルータ）→トランスポート層（TCP/UDP）→セッション層→プレゼンテーション層→アプリケーション層（HTTP・SMTP）という順で役割が分かれています。「ハブは物理層、スイッチはデータリンク層、ルータはネットワーク層」という機器と階層の対応が頻出です。

実務で使われるのは、これを4階層にシンプル化した<strong>TCP/IP</strong>モデルです。アプリケーション層（HTTP・DNS）、トランスポート層（TCP：信頼性重視／UDP：速度重視）、インターネット層（IP・ICMP）、ネットワークインタフェース層（イーサネット・Wi-Fi）の4層で構成されます。HTTPは80番、HTTPSは443番、SMTPは25番というポート番号の組み合わせもあわせて覚えておきましょう。

### TCPとUDPの違い

トランスポート層の代表的な2つのプロトコルは、試験で違いがよく問われます。

| プロトコル | 特徴 | 向いている通信 |
| --- | --- | --- |
| TCP | 到達確認と再送制御を行い、確実にデータを届ける | メール、Webページの閲覧など、正確性が重要な通信 |
| UDP | 到達確認をせず、高速に送り続ける | 動画配信、音声通話など、多少の欠落より速度が重要な通信 |

TCPとUDPの表は基礎の対比です。「UDPなら必ず速い」「Webなら必ずTCP」とは限りません。たとえばHTTP/3はUDP上のQUICを利用します。[RFC 9114](https://www.rfc-editor.org/rfc/rfc9114.html)

### IPアドレスとサブネットマスク

IPアドレスは、ネットワーク上の機器を識別する「住所」です。IPv4では32ビットを8ビットずつ4つに区切り、`192.168.1.1` のように10進数で書きます。

IPアドレスは、所属するネットワークを示す<strong>ネットワーク部</strong>と、そのネットワーク内の個体を示す<strong>ホスト部</strong>に分かれます。この境界を示すのが<strong>サブネットマスク</strong>です。`192.168.1.0/24` という表記は、先頭24ビットがネットワーク部だという意味です。

```text
IPアドレス:       192.168.1.10
サブネットマスク: 255.255.255.0（先頭24ビットが1）
→ ネットワーク部: 192.168.1.0
→ ホスト部:       .10（このネットワーク内での個体番号）
```

通常のIPv4サブネットの計算問題では、ホスト部のビット数を n として、収容できるホスト数を<strong>2のn乗 − 2</strong>で求めます。ネットワークアドレスとブロードキャストアドレスの2つを除くためです。たとえば `/24`（ホスト部8ビット）なら、2の8乗 − 2 = 254台です。

### ポート番号

1台のサーバーが、Webやメールなど複数のサービスを同時に提供するとき、IPアドレスだけでは「どのサービス宛の通信か」を区別できません。この区別に使うのが<strong>ポート番号</strong>です。

| ポート番号 | プロトコル | 用途 |
| --- | --- | --- |
| 80 | HTTP | Webページの閲覧 |
| 443 | HTTPS | 暗号化されたWebページの閲覧 |
| 25 | SMTP | メールの送信 |
| 53 | DNS | ドメイン名の名前解決 |

## DNS — ドメイン名を解決する仕組み

コンピュータは本来、数字（IPアドレス）でしか通信先を識別できません。<strong>DNS（Domain Name System）</strong>は、人間が覚えやすい「ドメイン名」とIPアドレスなどを対応づける「インターネットの電話帳」です。

ドメイン名からIPアドレスを求める<strong>正引き</strong>と、IPアドレスからドメイン名を求める<strong>逆引き</strong>の違いが試験で問われます。通常のDNSはUDPだけでなくTCPの53番ポートも使います。端末が問い合わせたDNSキャッシュサーバに有効な記録がなければ、権威DNSサーバをたどって必要な情報を得ます。毎回すべてのサーバへ問い合わせるわけではありません。[RFC 7766](https://www.rfc-editor.org/rfc/rfc7766.html)

## HTTP/HTTPSとCookie — Webの通信とセッション管理

<strong>HTTP</strong>はWebページをやり取りする基本プロトコルですが、データを平文（そのまま）で送るため盗聴・改ざんのリスクがあります。これを<strong>SSL/TLS</strong>で暗号化したものが<strong>HTTPS</strong>で、共通鍵暗号と公開鍵暗号を組み合わせて安全な通信路を作ります。通信結果を示す3桁のステータスコード（200 OK、404 Not Found、500 Internal Server Errorなど）も試験頻出です。

HTTPは本来「記憶力がゼロ」（ステートレス）なプロトコルのため、ログイン状態を維持する仕組みが別途必要です。それが<strong>Cookie</strong>で、サーバーが発行したセッションIDをブラウザが保存し、次のリクエストに自動で添えることで「あなたは誰か」を継続的に認識できます。サイト自身が発行する1st Party Cookieと、広告配信業者などが発行しサイトをまたいで追跡する3rd Party Cookieの違いも押さえておきましょう。

## 5G — 無線通信の3つの特徴

ネットワークの話題では、モバイル通信の<strong>5G（第5世代移動通信システム）</strong>もITパスポートの定番です。試験では、3つの特徴と、それが可能にする用途の組み合わせが問われます。

| 特徴 | 内容 | 結びつく用途の例 |
| --- | --- | --- |
| 高速大容量 | 一度に送受信できるデータ量が増え、速度も上がる。高精細なデータを扱うための性能を高める | 4K・8Kの高精細な映像配信、VR／ARの体験 |
| 超低遅延 | 送信から受信までの時間が極めて短い。1ミリ秒程度が目標とされる | 遠隔手術、建設機械の遠隔操作、自動運転 |
| 多数同時接続 | 限られた範囲で、多数の機器を同時につなげる。1平方キロメートルあたり100万台が目標とされる | IoTのセンサー、スマートシティ、スマート工場 |

出題は「リアルタイムの制御が必要な用途に欠かせない5Gの機能はどれか」のように、用途から特徴を選ぶ形が中心です。3つは単独でなく、組み合わせて働きます。遠隔医療なら、高速大容量で患者の高精細な情報を共有し、超低遅延で手術ロボットを操作します。なお、数値は設計上の目標で、すべての利用環境で同時に達成できる保証ではありません。[ITUのIMT-2020ビジョン](https://www.itu.int/rec/R-REC-M.2083-0-201509-I/en)

## データベースの正規化 — 設計の正しさを守る

データベース設計が甘いと、1件のデータ更新で複数行を修正しなければならない<strong>更新異常</strong>が発生します。<strong>正規化</strong>は、この更新異常を防ぐためにテーブルを分解・整理するプロセスです。

| 正規形 | 排除するもの | 判断の基準 |
| --- | --- | --- |
| 第1正規形（1NF） | 繰り返しグループ | 各セルが単一値か |
| 第2正規形（2NF） | 部分関数従属 | 非キー列が主キー全体に依存しているか |
| 第3正規形（3NF） | 推移関数従属 | 非キー列が別の非キー列に依存していないか |

「まず主キーを決める→各列の依存先を矢印で書く→分割する」という3ステップで、依存関係を整理できます。実際には主キー以外の候補キーも含めて依存を確認します。

## トランザクションとACID特性・排他制御 — 同時アクセスの正しさを守る

正規化が「静的な設計の正しさ」を守るのに対し、<strong>トランザクション</strong>は「動的な同時アクセスの正しさ」を守ります。関連する複数の処理を1つのまとまりとして扱い、すべて成功する（<strong>コミット</strong>）か、すべて失敗して元に戻る（<strong>ロールバック</strong>）かのどちらかにする仕組みです。

トランザクションが備えるべき4つの性質が<strong>ACID特性</strong>です。

- <strong>原子性（Atomicity）</strong>：全か無か。処理を完全に実行するか、まったく実行しなかった状態に戻す
- <strong>一貫性（Consistency）</strong>：処理の前後でデータのルール（制約）が壊れない
- <strong>独立性（Isolation）</strong>：複数の処理が同時に行われても互いに干渉しない
- <strong>耐久性（Durability）</strong>：コミット済みのデータは障害が起きても失われない

このうち<strong>独立性</strong>を実現する具体的な技術が<strong>排他制御</strong>です。基礎モデルでは、<strong>共有ロック</strong>は読み取り同士を許可し、<strong>占有ロック</strong>は競合するロックを制限すると整理します。ただし実装での読み取りまで一律に禁止されるわけではなく、PostgreSQLでは行ロックが通常の参照を妨げない場合があります。[PostgreSQLのロック仕様](https://www.postgresql.org/docs/current/explicit-locking.html)ロックの使い方を誤ると、複数の処理がお互いの解放待ちで動けなくなる<strong>デッドロック</strong>が発生します。回避策としては、資源を確保する順番を揃える、ロックの保持時間を短くする、デッドロックを検出して一方を強制的にロールバックする、などがあります。

問題文で止まったら、まず「何が困っているか」を探します。

| 問題文の条件 | 最初に確認する仕組み |
| --- | --- |
| 同じネットワークに属するか知りたい | IPアドレスとサブネットマスク |
| 同じサーバーのどのアプリへ送るか | ポート番号 |
| ドメイン名から通信先を知りたい | DNSの正引き |
| 同じ事実を複数行で直す必要がある | 正規化と更新異常 |
| 同時更新で値が食い違う | トランザクションと排他制御 |

## Syllabus Hack Points：AIにネットワーク・DBの全体像を検証させる

個別の用語を聞くより、一連の流れの中でどこに位置するかを確認させると理解が深まります。

```text
Webサイトにアクセスしてからログイン情報が保存されるまでの流れを、OSI参照モデルの階層・DNSによる名前解決・HTTPSの暗号化・Cookieによるセッション管理の順に説明してください。あわせて、その裏側でユーザー情報を更新するデータベース処理が、正規化された設計とトランザクション（ACID特性）によってどう守られているかも解説してください。
```

```text
IPアドレス 172.16.5.20、サブネットマスク 255.255.255.192 の場合、
ネットワークアドレス・ブロードキャストアドレス・収容可能なホスト数を、
計算過程も示して求めてください。
```

```text
5Gの3つの特徴（高速大容量・超低遅延・多数同時接続）を、日常生活のたとえを使って、各項目1行で説明してください。
```

サブネットの計算は、数をこなすほど速くなります。条件を変えた問題をAIに繰り返し出させて練習してください。IPアドレスの計算でつまずくときは、[CCNAのサブネット計算は実務で使う？社内LANの分け方から理解する計算の手順](/method/ip-address-ai-metaphor-hack/)も参考になります。

回答をもらったら、<strong>「これはネットワークの話か、データベースの話か」</strong>そして「その中のどの階層・どの特性の話か」を自分で仕分けし直してみましょう。断片的な用語ではなく、1つのシステムが動く流れとして説明できるようになれば、試験本番でも迷いません。

## まとめ

ネットワークとデータベースの基礎用語は、<strong>「情報を正しく届ける」（ネットワーク）と「情報を正しく保存し続ける」（データベース）</strong>という2つの基盤技術に整理できます。

- ネットワークはOSI参照モデル（7階層）とTCP/IP（4階層）で役割分担を理解し、IPアドレス・サブネット・ポート番号で通信先を特定する
- DNSは名前とアドレスを結びつけ、HTTP/HTTPS・Cookieが実際のWeb通信とセッションを支える。5Gは高速大容量・超低遅延・多数同時接続の3特徴を用途と結びつける
- データベースは正規化で構造上の正しさを、トランザクション（ACID特性）と排他制御で同時アクセス時の正しさを守る

この2軸で押さえておけば、ネットワーク・データベース分野は個別の用語暗記ではなく、システム全体の動きとして得点できます。

学ぶ順番は[ITパスポートの学習hub](/method/itp-hub/)で確認できます。[IPの20時間コース](/course/ip/)では基礎の位置づけを整理し直せます。
