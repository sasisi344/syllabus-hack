ITパスポートのAI分野には、ハルシネーション、RAG、マルチモーダルAI、XAI、MLOps……と、カタカナの新しい用語が次々に並びます。1つずつ覚えようとすると、どれがどの話なのか混ざってしまいます。

この記事では、これらの用語を<strong>生成AIの弱点とその対策、使い方、運用の流れ</strong>という1本の筋でつなげて、1ページで整理します。読み終えたときに、問題文の状況から、どの用語の話かを見分けられるようにします。

## 用語の全体像

| 分類 | 用語 | ひとことで |
| --- | --- | --- |
| 弱点 | ハルシネーション | AIが、事実でないことを、もっともらしく生成してしまう現象 |
| 弱点への対策 | RAG（検索拡張生成） | 回答を作る前に、外部の信頼できる情報を検索して参照させる |
| 弱点への対策 | HITL（ヒューマンインザループ） | プロセスのどこかに、人間を介在させる |
| 能力 | マルチモーダルAI | 文字だけでなく、画像・音声・動画なども、同時に扱う |
| 信頼性 | 説明可能なAI（XAI） | AIが「なぜその結論に至ったか」を、人間が理解できるようにする |
| 使い方 | AIアシスタント | 議事録、コード、メールなどの業務を支援する。人間の副操縦士 |
| 運用 | MLOps | AIモデルの開発と運用を連携させ、精度の劣化を防ぐ |

## ハルシネーション｜AIの「知ったかぶり」

<strong>ハルシネーション（幻覚）</strong>は、生成AIが、事実とは異なる内容を、あたかも正しいかのように生成してしまう現象です。

原因は、大規模言語モデル（LLM）の仕組みにあります。LLMは、文章の意味を人間のように「理解」しているのではなく、訓練データから学んだパターンに基づいて、「次に来る確率が高い言葉」を予測して、つないでいます。そのため、もっともらしい文章を自信たっぷりに作っても、内容が事実だとは限りません。特に、訓練データに含まれない最新の情報や、ごくニッチな質問には、統計的な推論で埋めようとして起こりやすくなります。

試験では、ハルシネーションが<strong>リスク</strong>として問われます。AIの出力をそのまま報告書や顧客対応に使うと、誤った意思決定や、企業の信頼の低下、法的な問題につながります。基本の対策は、人間による<strong>ファクトチェック（事実確認）</strong>です。

### HITL｜人間を介在させる

<strong>ヒューマンインザループ（HITL）</strong>は、AI任せにせず、プロセスの適切な場所に人間を入れる考え方です。AIが生成した内容のレビューや、AIが判断しにくいケースの最終決定を、人間が担います。ハルシネーション対策の根幹にあたり、「AIの能力と限界を理解して、人とAIが協調する」設計思想として問われます。

## RAG｜根拠を調べてから答えさせる

<strong>RAG（Retrieval-Augmented Generation：検索拡張生成）</strong>は、AIが回答を作る前に、外部の信頼できるデータベースや文書から関連情報を検索し、その情報に基づいて回答を生成する仕組みです。「検索（Retrieval）」と「生成（Generation）」の組み合わせです。

AIに、最新の「カンニングペーパー」を渡してから答えさせるイメージです。学習データの古さや、社内限定の情報の不足といった弱点を補い、ハルシネーションを抑えます。回答の根拠がどこにあるかを示せるので、透明性と信頼性も高まります。社内規定の検索、問い合わせ対応、ナレッジの活用が代表的な使い道です。

### ベクトル検索とエンベディング

RAGの検索を支える、周辺用語もセットで出ます。

| 用語 | 内容 |
| --- | --- |
| エンベディング | 文章や画像などを、コンピュータが計算しやすい数値の並び（ベクトル）に変換する技術。意味の近いものは、近い位置に置かれる |
| ベクトル検索 | 質問もベクトルに変換し、意味が最も近い情報を、高速に探し出す検索 |

試験では、これらの技術が、RAGのどの部分で役に立つかが問われます。

## マルチモーダルAI｜複数の形式を同時に扱う

<strong>モダリティ</strong>は、情報の形式（文字、画像、音声、動画、センサー情報など）のことです。<strong>マルチモーダルAI</strong>は、複数のモダリティを同時に処理し、統合して理解するAIです。「マルチ（複数）」の「モード（形式）」と分解すると覚えられます。

テキストだけを扱う従来のAIと比べて、「何ができるようになったか」が問われます。

| 能力 | できること | 応用の例 |
| --- | --- | --- |
| 画像・動画の理解 | 画像や動画の文脈を理解する | 工場の生産ラインでの欠陥の検知、防犯カメラの映像の分析 |
| 音声・感情の分析 | 声のトーンや言葉から、感情を読み取る。リアルタイムで多言語に通訳する | コールセンターでの顧客の不満の検知、会議の自動議事録 |
| 複数センサーの統合 | カメラ、レーダー、温度などの情報を組み合わせて、判断を支援する | 自動運転の障害物の回避、医療での診断支援 |

スマートフォンで冷蔵庫の中身を撮ると、食材を認識して（画像）、献立を提案する（テキスト）アプリは、画像とテキストという異なるモダリティをつなぐ、マルチモーダルAIの例です。

## 説明可能なAI（XAI）｜なぜその答えになったのか

AIの判断の理由が、人間には分かりにくい状態を<strong>ブラックボックス問題</strong>といいます。<strong>XAI（Explainable AI：説明可能なAI）</strong>は、AIが「なぜその結論に至ったか」の根拠を、人間が理解できるように説明する技術の総称です。

AIが意思決定に深く関わる場面（自動運転、医療診断、融資の審査など）で、XAIの役割が問われます。

| 目的 | 内容 |
| --- | --- |
| 信頼性の向上 | AIの答えを鵜呑みにせず、人間が「妥当か」を最終判断する材料になる |
| 責任の所在 | 不具合や事故が起きたとき、判断の過程をさかのぼって調査し、改善できる |
| 公平性の確保 | 学習データの偏り（バイアス）で、特定の人を不当に扱っていないかを確かめる |

「精度が高ければ、中身はどうでもいい」という時代から、「正しく説明できなければ使いにくい」という時代に変わってきた、と捉えるのがポイントです。AIガバナンス（社会的な信頼性・安全性）の文脈でも、よく出ます。

## AIアシスタント｜人間の「副操縦士」

<strong>AIアシスタント</strong>は、議事録の作成、プログラムコードの生成、メールの返信案、データの傾向の整理といった、業務を支援するAIツールです。定型的な作業を任せて、人間が企画や意思決定のような仕事に集中できる点が、導入のメリットです。

試験で大切なのは、<strong>最終的な成果物のチェックは、必ず人間が行う</strong>という点です。AIの出力には、ハルシネーションや、倫理的に問題のある内容が含まれる可能性があります。「<strong>コパイロット（副操縦士）</strong>」という言葉が使われ、操縦士である人間を隣で助ける存在で、最終的な判断と責任は人間にある、という位置づけです。

## MLOps｜AIを作って終わりにしない

AIモデルは、一度作れば終わりではありません。現実の世界は変化し続けるため、時間が経つと、モデルの予測精度が落ちていきます。<strong>MLOps</strong>は、機械学習（ML）の開発と運用を連携させ、そのライフサイクル全体を管理する手法です。ソフトウェアの<strong>DevOps</strong>の考え方を、AIシステム特有の課題に合わせて広げたものです。

| 用語 | 内容 |
| --- | --- |
| データドリフト | 学習したときのデータと、現在入ってくるデータの間に、ズレが生じること。流行や社会情勢の変化で起こり、予測精度を下げる |
| 継続的学習（CT） | 新しいデータを取り込み、モデルを再学習させ続ける仕組み |
| 自動化の範囲 | データの品質チェック、モデルの学習・評価、デプロイ、稼働後の精度の監視、再学習の開始まで、広く自動化する |

AIを「生き物」にたとえると、新しいデータで再学習させる（餌を与える）、精度を監視する（健康診断をする）のが、MLOpsの役割です。

## 生成AIで用語のつながりを確かめる

用語は、場面に当てはめて説明させると、境目がはっきりします。

```text
あなた自身が「ハルシネーション」を起こしてしまったときの気持ちになりきって、
「なぜ私は嘘をついてしまったのか」を、IT用語（学習データ、統計的な予測など）を交えて説明してください。
```

```text
「RAG」の仕組みを、プロ野球の解説者にたとえて、IT試験の初心者向けに説明してください。
普通の生成AIとRAGの違いが分かるようにしてください。
```

```text
あるAIパン屋が、今日売れる量を予測していますが、急なSNSのブームで予測が全く当たらなくなりました。
この問題を解決するための「MLOps」の役割を、データドリフトと継続的学習の言葉を使って、1分で説明してください。
```

AIの説明を読む前に、自分で「これは弱点の話か、対策の話か、運用の話か」を仕分けしてから、答え合わせをしてみてください。

## まとめ

- ハルシネーションは、LLMが確率で言葉をつなぐために起こる。対策は、ファクトチェックとHITL、そして<strong>RAG</strong>（外部の根拠を検索してから答えさせる）
- マルチモーダルAIは、文字・画像・音声など複数の形式を同時に扱う
- XAIは、AIの判断の根拠を説明できるようにして、信頼性・責任の所在・公平性を支える
- AIアシスタントは副操縦士。最終的なチェックと責任は人間にある
- MLOpsは、データドリフトによる精度の劣化を、継続的な再学習と監視で防ぐ運用の手法

次は、AIの利用にまつわる法律と倫理（著作権、AI倫理、オプトアウト、ディープフェイク）を整理した[AIの法律・倫理の記事](/theory/ai-law-ethics-basics/)に進むと、生成AIの周辺知識がつながります。
