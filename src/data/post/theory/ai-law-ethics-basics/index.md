生成AIを使うとき、「AIが作った絵は誰のものか」「入力した社内の情報はどこへ行くのか」「本物そっくりの偽の動画をどう見分けるのか」と、法律や倫理の疑問が次々に出てきます。

ITパスポートでも、これらは近年よく問われる分野です。この記事では、<strong>著作権・AI倫理・オプトアウト・ディープフェイク</strong>を、「作る側の権利」「使う側の責任」「入力するデータの守り方」「悪用のリスク」という筋で、1ページに並べて整理します。

## 用語の全体像

| 論点 | 用語 | 問われること |
| --- | --- | --- |
| 作ったものの権利 | AI生成物の著作権 | AIが作ったものに著作権はあるか。他人の作品を学習に使ってよいか |
| 使う側の責任 | AI倫理（公平性・安全性・プライバシー） | AIの不適切な利用の例が、どの原則に反するか |
| 入力するデータの守り方 | オプトアウト | 入力データを、AIの学習に使わせない設定。機密情報の保護 |
| 悪用のリスク | ディープフェイク、GAN | 本物そっくりの偽の映像や音声が、社会にもたらすリスク |

## AI生成物と著作権

著作権は、人間の思想や感情を創作的に表現したものに認められます。ここから、試験で問われる考え方が出てきます。

| 場面 | 著作権の扱い | ポイント |
| --- | --- | --- |
| AIが単独で生成したもの | 原則として、認められない | 「風景を描いて」といった簡単な指示だけで出力されたものは、人間の創作的な表現とは言えない |
| 人間が創作的に関与したもの | 認められる可能性がある | 指示の具体性や、出力を人間が修正・加工した作業などが、判断材料になる（創作的寄与） |
| AIの学習に著作物を使うこと | 著作権者の利益を不当に害さない限り、原則として許諾なしにできる | 著作権法30条の4。情報解析が目的の場合 |
| 特定の作品に似せたものを出力させること | 侵害にあたるリスクが高い | 「依拠性」と「類似性」の両方が成立すると、侵害になる |

<strong>依拠性</strong>は、既存の著作物に接して、それを自分の作品に利用したことです。<strong>類似性</strong>は、既存の著作物と似ていることです。特定の作品をAIに入力して、それに似せたものを出力させると、依拠性があるとみなされやすくなります。生成AIで作った画像をブログに使うときも、この2つを意識して、他人の作品に似ていないかを確かめる必要があります。

学習への利用が認められる範囲には限りがあり、著作権者の利益を不当に害する場合は、認められません。「学習なら何でもよい」とは考えない点が、ひっかけになります。

## AI倫理｜公平性・安全性・プライバシー

AIが社会に広がるほど、倫理の原則が重要になります。試験では、AIの不適切な利用の例が、どの原則に反するかを問われます。

| 原則 | 内容 | 反する例 |
| --- | --- | --- |
| 公平性 | 学習データに偏り（バイアス）がなく、特定の属性（性別、人種、地域など）を不当に扱わない | 採用AIが特定の性別を不利に扱う。融資審査のAIが、特定の地域の人にだけ不利な条件を出す |
| 安全性 | 予期しない動作で、人に危害を与えない。誤作動のリスクを管理する | 自動運転や医療診断のAIで、十分なテストや安全基準がない |
| プライバシー | 個人情報を、本人の同意なく学習に使わない。個人情報保護法などを守る | 本人の同意のない個人データのAI学習、収集目的を超えた利用 |

ハルシネーション（事実でない内容の生成）を放置して使うことも、不適切な利用の例として出ます。判断の根拠を説明できるXAI（説明可能なAI）や、最終判断を人間が行うHITLは、これらの原則を守るための手段です。詳しくは、[生成AIの用語を整理した記事](/theory/generative-ai-terms-basics/)にまとめています。

## オプトアウト｜入力データを学習に使わせない

<strong>オプトアウト</strong>は、自分のデータが、AIの学習などに使われることを、拒否する意思表示や設定です。企業が生成AIを使うときは、入力した機密情報が、AIの学習に使われて外部に出てしまわないかが問題になります。

試験や実務で、次の点がよく問われます。

| 観点 | 内容 |
| --- | --- |
| APIと一般向けの画面（UI）の違い | 学習に使うかどうかの既定の扱いが、異なることがある |
| 無料版のリスク | 初期設定のままだと、入力データが学習の対象になる可能性がある |
| 規約の確認 | オプトアウトができるか、データの保持期間、第三者への提供の条件を読む |
| ガバナンス | 個人任せにせず、組織のポリシーで統制する |

「どのデータが、どの目的で、どこに送られ、どこで止められるか」を、図にして説明できる状態が目標です。利用目的ごとのデータの分類や、機密情報を入力しないルール、ログの管理も、あわせて整えておきます。

## ディープフェイク｜本物そっくりの偽物

<strong>ディープフェイク</strong>は、AIを使って作った、本物そっくりの偽の映像・画像・音声です。対象の人物の顔や声をAIに学習させ、あたかも本人が話しているかのように見せることができます。試験では、社会にもたらすリスクが問われます。

| リスク | 内容 |
| --- | --- |
| なりすまし | 声や顔まで似せて、家族や上司のふりをする。詐欺に使われる |
| 偽情報の拡散 | 災害や選挙のときに、偽の動画で世論を誘導したり、パニックを起こしたりする |
| 情報の真正性の低下 | 見聞きした情報が「本物であること」の証明が、難しくなる |

基盤技術のひとつが<strong>GAN（敵対的生成ネットワーク）</strong>です。<strong>生成器</strong>（偽物を作るAI）と<strong>識別器</strong>（本物か偽物かを見分けるAI）を、互いに競わせて、本物に近いデータを作らせます。偽札を作る泥棒と、それを見破る警察官にたとえると分かりやすくなります。泥棒が腕を上げるほど、警察官も見破る力が上がり、結果として偽物の質が高くなります。

対策として、出どころを確認する、複数の情報源で確かめる、重要な連絡は別の手段で本人に確かめる、といった基本が有効です。

## 生成AIで事例に当てはめて確かめる

法律や倫理の用語は、具体的な場面に当てはめると、区別がつきます。

```text
生成AIで作成したイラストを、自分のブログのトップ画像に使おうと思います。
著作権侵害を避けるために気をつけるべき「類似性と依拠性」について、100文字以内で注意点を教えてください。
```

```text
あなたは企業の情報セキュリティ責任者です。
日本の個人情報保護法と社内のコンプライアンスを前提に、生成AIの利用ポリシーの要点を作成してください。
利用目的の明確化、取り扱いを禁止するデータ、オプトアウトの確認を必ず含めてください。
```

```text
ディープフェイクを支える技術「GAN（敵対的生成ネットワーク）」について、
偽札を作る泥棒と、それを見破る警察官のたとえで、100文字以内で仕組みを教えてください。
```

AIの回答は、法律の専門家の判断ではありません。実務で迷う場合は、会社の法務部門や専門家に確かめてください。

## まとめ

- AI生成物の著作権は、AI単独の生成には原則として認められず、人間の創作的な関与があれば認められる可能性がある。学習への利用は原則として許諾なしにできるが、侵害にあたるのは依拠性と類似性が成立するとき
- AI倫理は、公平性・安全性・プライバシーの原則に、事例を当てはめて考える
- オプトアウトは、入力データを学習に使わせない設定。APIと一般向けの画面の違い、無料版のリスク、規約の確認がポイント
- ディープフェイクは、なりすまし・偽情報・真正性の低下のリスクを高める。基盤技術はGAN
