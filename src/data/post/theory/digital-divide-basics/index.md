スマートフォンを渡せば、情報格差は解消するのでしょうか。通信できても操作で止まる人、操作できても情報の真偽を判断しにくい人では、必要な支援が違います。

デジタルディバイドの対策を、架空のオンライン申請の例で整理します。読み終えたら、「使えない理由」から必要な支援を選べるようになります。

## デジタルディバイドとは、情報通信技術を使う機会の格差

<strong>デジタルディバイド（情報格差）</strong>は、情報通信技術を利用できる人と、利用しにくい・できない人との間に生じる格差です。回線や端末を持つ条件に加え、操作や情報活用の条件も関わります。

例えば、申請窓口がオンラインだけになったと仮定します。端末がない人も、画面を読めない人も、操作できずに申請を終えられなければ、同じサービスを利用する機会を失います。

これは学習用の架空事例であり、特定の行政サービスの現状を示すものではありません。

## 原因ごとの対策を選ぶ判断基準

「高齢者向け講習を開く」と先に決めるより、どこで利用が止まるかを確かめます。

| 利用が止まる条件 | 主に必要な支援 | それだけでは足りない対策 |
| --- | --- | --- |
| 住む場所で通信できない | 回線や共同利用拠点などの環境整備 | 操作講習だけを開く |
| 端末・通信費を負担しにくい | 貸出や費用負担を抑える利用方法 | 高機能なアプリだけを作る |
| 入力や手順が分からない | 練習機会、相談窓口、分かりやすい手順 | 端末だけを渡す |
| 見え方・聞こえ方・操作方法が合わない | 読み上げ、キーボード操作などに対応する設計 | 同じ画面の操作を繰り返し教える |
| 偽情報と公式情報を区別しにくい | 発信元・更新日・根拠を確認する学習 | 回線だけを高速化する |

この表は原因を切り分けるための整理で、原因は重なることがあります。まず申請を完了できる窓口を確保し、並行して利用環境や学習機会を整える、といった組合せが必要になります。

## アクセシビリティとリテラシー教育は役割が違う

アクセシビリティは、障害のある人を含め、情報や機能にアクセスできるようにすることです。W3Cは、Webを知覚し、理解し、操作し、利用できることを説明し、視覚・聴覚・身体などの条件を挙げています。[出典：W3C「Introduction to Web Accessibility」](https://www.w3.org/WAI/fundamentals/accessibility-intro/)

文字を画像だけで表示していて読み上げられないなら、利用者への講習だけでは解決しません。サービス側の設計を直す必要があります。

一方、公式サイトと広告を区別する知識や、不審なメールの見分け方は、情報リテラシーを育てる学習の領域です。「使う人が学ぶこと」と「提供側が使える形にすること」を分けると、対策がずれにくくなります。

## 年齢やAIの利用経験だけで判断しない

若くても、スマートフォンには慣れていてパソコンのファイル操作には不慣れな場合があります。年齢を原因と決めず、必要な場面で何ができないのかを確認します。

生成AIを使う場合も同じです。AIへの指示ができることと、出力の根拠を検証できることは別の能力です。

「AIを使わせれば格差がなくなる」と考えると、端末や通信の負担、入力の難しさ、出力の誤りの確認が置き去りになります。支援策は、利用者が目的を達成できたかで評価します。

## 生成AIと、支援が届かない理由を考える

次の対話は、対策の名前を暗記する代わりに、その対策で解決できない条件を確かめるためのものです。

```text
デジタルディバイドの対策を理解したいです。
架空のオンライン申請で、端末はあるが入力操作が分からず、
一部の画面は読み上げにも対応していないと仮定します。
私の提案は「操作講習を開く」です。
これだけでは解決しない理由を、利用者側の学習と
サービス側のアクセシビリティに分けて問い返してください。
実在する自治体の制度や統計は作らないでください。
```

## まとめ：困り方を確かめてから対策を選ぶ

デジタルディバイドの対策は、通信・費用・操作・設計・情報の判断のどこに障壁があるかで変わります。端末の有無だけで、利用できるかどうかを判断しないことが要点です。
