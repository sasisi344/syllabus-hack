## この章で学ぶこと

第1〜7章では、脅威・マネジメント・対策・認証暗号という「守るべきもの」と「守り方」を学びました。この章は、2027年シラバスで<strong>完全新設</strong>された中分類で、それらを<strong>実際にどう実装し、どう評価するか</strong>という一段実務的な視点を扱います。生成AI・LLMのセキュリティ、セキュアコーディング、クラウド・コンテナ実装、ハードウェア/IoT/OT、デジタルフォレンジック、そして脆弱性管理・評価制度という6つのテーマは、シラバスハックの「生成AI×資格」という軸とも直結する、このコース最大の差別化ポイントです。

## ゼロトラストとAI・LLMセキュリティ

第6章で触れた<strong>ゼロトラストアーキテクチャ(ZTA)</strong>を実装レベルで見ると、米国の指針<strong>NIST SP 800-207</strong>に基づき、アクセスを許可するかを判断する<strong>ポリシー決定ポイント(PDP)</strong>と、実際にその判断を執行する<strong>ポリシー実施ポイント(PEP)</strong>という2つの要素で構成されます。

生成AIの普及に伴い新設されたのが<strong>AIを使ったセキュリティ技術(AI for Security)</strong>です。第2章で学んだプロンプトインジェクションへの対策として、指示と外部データを分離する<strong>プロンプトインジェクション対策(プロンプト分離・エージェントの権限分離)</strong>、システムプロンプトを強化し機密情報を分離する<strong>LLMの脅威への対策</strong>（システムプロンプトの強化・入力プロンプトの検証・外部参照データの検証と分離・RAG用データストアへのアクセス制御）が具体的に明記されています。こうした対策の拠り所となるのが<strong>AIのセキュリティ確保のための技術的対策に係るガイドライン</strong>です。

**扱う用語（精選・5語）**

- ゼロトラストアーキテクチャ(ZTA・NIST SP 800-207・PDP・PEP)
- AIを使ったセキュリティ技術(AI for Security)／プロンプトインジェクション対策／LLMの脅威への対策／AIのセキュリティ確保のための技術的対策に係るガイドライン

## セキュアコーディングとWebアプリケーション実装対策

第1〜2章で学んだ攻撃手法に対応する実装レベルの防御を学びます。脆弱性を作り込まない<strong>セキュアプログラミング</strong>の実践と、IPAが公開する<strong>セキュアコーディングの指針(安全なウェブサイトの作り方など)</strong>が土台です。脆弱性を発見する<strong>脆弱性検査技術</strong>には、ソースコードを解析する<strong>SAST(静的検査)</strong>、実際に動かして検査する<strong>DAST(動的検査)</strong>、Web特有の<strong>脆弱性検査</strong>、想定外の入力を大量に送り込む<strong>ファジング</strong>があります。

具体的な対策としては、出力時に特殊文字を無害化する<strong>出力時のエスケープ処理(出力エンコーディング)</strong>による<strong>クロスサイトスクリプティング対策</strong>、命令文と値を分離する<strong>SQLインジェクション対策(プレースホルダなど)</strong>、リクエストの正当性を確認する<strong>CSRFトークン</strong>、境界チェックによる<strong>バッファオーバーフロー対策</strong>、ソルトを加えてハッシュを強化する<strong>パスワードクラック対策(ソルト・ストレッチングなど)</strong>があります。ブラウザの基本的な防御である<strong>Same Origin Policy</strong>と、それを緩和して許可する<strong>CORS(オリジン間リソース共有)</strong>、cookieの安全な設定である<strong>cookieの属性指定(Secure・HttpOnly・SameSite)</strong>、常時HTTPS通信を強制する<strong>HSTS(HTTP Strict Transport Security)</strong>、実行可能なスクリプトの出所を制限する<strong>CSP(Content Security Policy)</strong>、外部リソースの改ざんを検知する<strong>SRI(Subresource Integrity)</strong>も、Webアプリケーションの標準的な防御手段です。

**扱う用語（精選・15語）**

- セキュアプログラミング／セキュアコーディングの指針／脆弱性検査技術(SAST・DAST・ファジング)
- 出力時のエスケープ処理／クロスサイトスクリプティング対策／SQLインジェクション対策／CSRFトークン／バッファオーバーフロー対策／パスワードクラック対策
- Same Origin Policy／CORS／cookieの属性指定／HSTS／CSP／SRI

## ソフトウェアサプライチェーン・クラウド・コンテナのセキュリティ実装

第2章で学んだソフトウェアサプライチェーン攻撃への対策として、機密情報をコードに埋め込まない<strong>シークレット管理(シークレットストア・ハードコードの排除)</strong>、外部ライブラリを最新に保つ<strong>依存ライブラリの更新管理</strong>、開発者本人であることを証明する<strong>署名付きコミット</strong>、ビルド成果物の正当性を確認する<strong>成果物の署名検証</strong>、サプライチェーン全体の完全性を保証する枠組み<strong>SLSA</strong>があります。

クラウド環境では、不要な機能を停止し攻撃対象領域を減らす<strong>要塞化(ハードニング)</strong>、第3章で学んだ<strong>責任共有モデルに基づく役割分担</strong>の実践、<strong>クラウドのアイデンティティ・アクセス管理</strong>、公開範囲や権限の誤りである<strong>クラウドの設定不備</strong>、クラウド基盤の内部情報を守る<strong>インスタンスメタデータサービスの保護</strong>が実装課題になります。コンテナ技術の普及に伴い、<strong>コンテナイメージの脆弱性管理</strong>、コンテナ群を管理するオーケストレーション基盤での<strong>コンテナオーケストレーションのアクセス制御(RBAC・ネットワークポリシー)</strong>、インフラをコードとして定義する際の<strong>IaC(Infrastructure as Code)のセキュリティスキャン</strong>も、2027年シラバスで具体化された実装課題です。

**扱う用語（精選・13語）**

- シークレット管理／依存ライブラリの更新管理／署名付きコミット／成果物の署名検証／SLSA
- 要塞化(ハードニング)／責任共有モデルに基づく役割分担／クラウドのアイデンティティ・アクセス管理／クラウドの設定不備／インスタンスメタデータサービスの保護
- コンテナイメージの脆弱性管理／コンテナオーケストレーションのアクセス制御／IaCのセキュリティスキャン

## ハードウェア・IoT・産業制御システム(OT)のセキュリティ

ソフトウェアだけでなくハードウェアレベルの保護も重要です。改ざん耐性のある専用チップ<strong>セキュアエレメント</strong>、鍵の保管・暗号処理を行う<strong>TPM(Trusted Platform Module)</strong>、ディスク自体が暗号化機能を持つ<strong>自己暗号化ドライブ(SED)</strong>、起動プロセスの正当性を検証する<strong>セキュアブート(UEFI)</strong>、物理的な解析への耐性である<strong>耐タンパ性</strong>があります。これらはセンサーや家電など<strong>IoTのセキュリティ</strong>を実現する基盤技術でもあります。

工場やプラントを制御する<strong>制御システムのセキュリティ</strong>には、専用の国際規格<strong>IEC 62443(産業用オートメーション及び制御システムのセキュリティ)</strong>、それに基づく管理体制<strong>サイバーセキュリティマネジメントシステム(CSMS)</strong>、製品の認証制度<strong>ISASecure CSA認証(IEC 62443-4-2)</strong>、日本独自の<strong>JC-STAR(セキュリティ要件適合評価及びラベリング制度)</strong>があります。制御システムを階層的に捉える<strong>Purdueモデル</strong>を土台に、情報系(IT)と制御系(OT)を分離する<strong>IT／OT境界のDMZ</strong>、一方向にしかデータを流さない<strong>一方向ゲートウェイ</strong>、機器のソフトウェアを安全に更新する<strong>ファームウェアのセキュアアップデート</strong>、調達段階でセキュリティを確認する<strong>IT製品の調達におけるセキュリティ要件リスト</strong>もあわせて押さえておきましょう。

**扱う用語（精選・16語）**

- セキュアエレメント／TPM／自己暗号化ドライブ(SED)／セキュアブート(UEFI)／耐タンパ性／IoTのセキュリティ
- 制御システムのセキュリティ／IEC 62443／サイバーセキュリティマネジメントシステム(CSMS)／ISASecure CSA認証／JC-STAR／Purdueモデル／IT／OT境界のDMZ／一方向ゲートウェイ／ファームウェアのセキュアアップデート／IT製品の調達におけるセキュリティ要件リスト

## デジタルフォレンジックとマルウェア解析

インシデント発生後、証拠として法的に通用する形でデータを保全する<strong>証拠保全</strong>が第一歩です。メモリのように消えやすい情報から先に集める<strong>揮発性データの収集順序</strong>、原本を変更しないよう複製する<strong>ディスクイメージの取得と書込み防止</strong>、複製元と同一であることを証明する<strong>ハッシュ値による同一性の証明</strong>、誰がいつ証拠を扱ったかを記録し続ける<strong>Chain of Custody(証拠保全の連鎖)</strong>が、証拠の信頼性を支えます。収集した記録から事象の時系列を再構築する<strong>タイムライン分析</strong>、メモリの内容を解析する<strong>メモリフォレンジック</strong>も代表的な手法です。

攻撃者やマルウェアの挙動を安全に観察する環境として、隔離された領域でプログラムを実行する<strong>サンドボックス</strong>、おとりのシステムで攻撃者を誘い込む<strong>ハニーポット</strong>、それをネットワーク規模に広げた<strong>ハニーネット</strong>、通信内容を記録する<strong>パケットキャプチャ</strong>があります。マルウェア自体を分析する際は、実行ファイルの構造を調べる<strong>バイナリファイルの解析</strong>、機械語をプログラミング言語に近い形に戻す<strong>逆アセンブル</strong>、圧縮・難読化されたコードを元に戻す<strong>アンパック</strong>が基本手順で、攻撃者側もこれらの解析を妨害する<strong>解析やセキュリティ検知を回避する技術(パッカー・難読化・アンチデバッグ・マルウェア対策ソフトの停止など)</strong>を使ってくることを念頭に置く必要があります。

**扱う用語（精選・15語）**

- 証拠保全／揮発性データの収集順序／ディスクイメージの取得と書込み防止／ハッシュ値による同一性の証明／Chain of Custody／タイムライン分析／メモリフォレンジック
- サンドボックス／ハニーポット／ハニーネット／パケットキャプチャ
- バイナリファイルの解析／逆アセンブル／アンパック／解析やセキュリティ検知を回避する技術

## 脆弱性管理・診断とセキュリティ評価制度

ソフトウェアに含まれる部品を洗い出す<strong>ソフトウェア構成分析(SCA)</strong>と、その部品表である<strong>SBOMを利用した脆弱性管理</strong>は、第2章のサプライチェーン攻撃対策とも直結します。日本の脆弱性情報ポータル<strong>JVN(Japan Vulnerability Notes)</strong>、脆弱性の深刻度を数値化する<strong>共通脆弱性評価システム(CVSS)</strong>、個々の脆弱性を一意に識別する<strong>共通脆弱性識別子(CVE)</strong>、脆弱性の種類を分類する<strong>共通脆弱性タイプ一覧(CWE)</strong>、セキュリティ設定を標準化して自動チェックする<strong>セキュリティ設定共通化手順(SCAP)</strong>が代表的な枠組みです。優先度づけの新しい指標として、実際に悪用が確認された脆弱性を示す<strong>KEV(Known Exploited Vulnerability)</strong>、悪用される確率を予測する<strong>EPSS(Exploit Prediction Scoring System)</strong>、組織の状況に応じて対応優先度を判断する<strong>SSVC(Stakeholder-Specific Vulnerability Categorization)</strong>も2027年シラバスで新設されています。

実際にシステムの弱点を確認する手法として、既知の脆弱性の有無を確認する<strong>脆弱性診断</strong>、実際に侵入を試みてどこまで到達できるか検証する<strong>ペネトレーションテスト</strong>、外部の研究者に脆弱性発見を報奨金付きで依頼する<strong>脆弱性報奨金制度(バグバウンティプログラム)</strong>があります。

製品自体の安全性を第三者が評価する国際的な枠組みが<strong>ISO/IEC 15408</strong>で、これに基づく評価基準<strong>コモンクライテリア(CC)</strong>、製品カテゴリごとの要求事項<strong>プロテクションプロファイル(PP)</strong>、評価の実施方法を定める<strong>ISO/IEC 18045</strong>・<strong>共通評価方法(CEM)</strong>、評価の厳格さの度合いを示す<strong>評価保証レベル(EAL)</strong>があります。日本国内の認証制度としては、IT製品を評価する<strong>JISEC(ITセキュリティ評価及び認証制度)</strong>、暗号モジュールを評価する<strong>JCMVP(暗号モジュール試験及び認証制度)</strong>、米国の暗号モジュール要求事項<strong>FIPS 140</strong>、政府調達で参照される<strong>CRYPTREC暗号リスト</strong>があり、支援士がシステムの安全性を第三者に説明する際の拠り所になります。

**扱う用語（精選・23語）**

- ソフトウェア構成分析(SCA)／SBOMを利用した脆弱性管理／JVN／CVSS／CVE／CWE／SCAP／KEV／EPSS／SSVC
- 脆弱性診断／ペネトレーションテスト／脆弱性報奨金制度
- ISO/IEC 15408／コモンクライテリア(CC)／プロテクションプロファイル(PP)／ISO/IEC 18045／共通評価方法(CEM)／評価保証レベル(EAL)／JISEC／JCMVP／暗号モジュールのセキュリティ要求事項(FIPS 140)／CRYPTREC暗号リスト

ここまでの用語は、ChatGPTやClaudeなどの生成AIに以下のプロンプトを投げかけると、比較表つきでさらに深く掘り下げて学習できます。コピーして使ってみましょう。

【ゼロトラストとAI・LLMセキュリティ】ゼロトラストアーキテクチャ(ZTA)、PDP、PEP、AI for Security、プロンプトインジェクション対策、LLMの脅威への対策
