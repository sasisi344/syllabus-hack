## この章で学ぶこと

第6章では検知・防御の技術を学びました。この章では、それらの対策を支える土台となる<strong>認証技術</strong>と<strong>暗号・PKI</strong>を学びます。まずデータを守る暗号技術と多様化する認証方式を押さえ、次にアイデンティティ連携・生体認証、そして暗号技術そのものの仕組み（暗号方式の基礎・鍵管理・ハッシュ関数）、最後に<strong>PKI・証明書</strong>と<strong>耐量子計算機暗号</strong>まで進みます。77語とやや多めですが、「何を・誰を・どう証明するか」という視点で一貫しています。

## データ保護のための暗号技術と認証の基礎

保存データを守る技術として、ディスク全体を暗号化する<strong>ストレージ暗号化</strong>、個々のファイル単位で暗号化する<strong>ファイル暗号化</strong>、データベース内のデータを暗号化する<strong>データベース暗号化</strong>があります。改ざんされていないことと作成者を証明する<strong>デジタル署名</strong>、共有鍵を使ってメッセージの改ざんを検知する<strong>メッセージ認証符号(MAC)</strong>、その代表的な実装である<strong>HMAC</strong>、ソフトウェアの配布元と完全性を保証する<strong>コードサイニング</strong>、通信相手が本人であることを確認する<strong>エンティティ認証</strong>、DNS応答が偽造されていないことを保証する<strong>DNSSEC</strong>も、データと通信の真正性を守る技術です。

認証そのものも多様化しています。パスワードに加えて別の要素も求める<strong>多要素認証</strong>、複数の段階を経て認証する<strong>多段階認証</strong>、普段と異なるアクセス状況を検知して追加認証を求める<strong>リスクベース認証</strong>、盗まれても再利用できない<strong>フィッシング耐性のある認証</strong>（後述のFIDOが代表例）があります。歴史的な認証プロトコルとしては、チケットを使って何度もパスワードを送らずに済む<strong>Kerberos方式</strong>、組織のディレクトリサービスと連携する<strong>LDAPサーバでの認証</strong>も押さえておきましょう。

**扱う用語（精選・15語）**

- ストレージ暗号化／ファイル暗号化／データベース暗号化／デジタル署名／メッセージ認証符号(MAC)／HMAC／コードサイニング／エンティティ認証／DNSSEC
- 多要素認証／多段階認証／リスクベース認証／フィッシング耐性のある認証／Kerberos方式／LDAPサーバでの認証

## アイデンティティ連携・SSOと生体認証・パスワードレス認証

複数のサービス間で認証情報を安全に連携させる標準規格が<strong>アイデンティティ連携(OpenID Connect・SAML・OAuth 2.0・IdP)</strong>です。認可の仲介役であるIdP(Identity Provider)を軸に、認可の途中経路を保護する<strong>PKCE</strong>、サービスへのアクセス許可を表す<strong>アクセストークン</strong>、期限切れ後に再取得するための<strong>リフレッシュトークン</strong>、利用者情報を安全にやり取りする形式<strong>JWT(JSON Web Token)</strong>が組み合わさって動きます。1回のログインで複数サービスを使える<strong>シングルサインオン(SSO)</strong>、これをクラウドサービスとして提供する<strong>IDaaS(Identity as a Service)</strong>も、実務で広く使われています。

パスワードに頼らない認証も普及が進んでいます。指紋や虹彩のような<strong>身体的特徴</strong>、歩き方やタイピングの癖のような<strong>行動的特徴</strong>を使う生体認証には、本人なのに拒否してしまう<strong>本人拒否率(FRR)</strong>、他人なのに受け入れてしまう<strong>他人受入率(FAR)</strong>、両者が釣り合う水準を示す<strong>等価誤り率(EER)</strong>という精度指標があります。写真や録音による「なりすまし」を見破る<strong>ライブネス検知(アクティブ検知・パッシブ検知)</strong>も重要な技術です。パスワードを使わない認証の標準規格が<strong>FIDO(FIDO2・WebAuthn・CTAP・パスキー)</strong>で、SMSなどで一度きりのコードを送る<strong>ワンタイムコード</strong>とあわせて、パスワードレス時代の認証基盤を形成しています。

**扱う用語（精選・15語）**

- アイデンティティ連携(OpenID Connect・SAML・OAuth 2.0・IdP)／PKCE／アクセストークン／リフレッシュトークン／JWT(JSON Web Token)／シングルサインオン(SSO)／IDaaS
- 身体的特徴／行動的特徴／本人拒否率(FRR)／他人受入率(FAR)／等価誤り率(EER)／ライブネス検知／FIDO(FIDO2・WebAuthn・CTAP・パスキー)／ワンタイムコード

## 暗号方式の基礎と鍵管理

暗号方式には、同じ鍵で暗号化・復号する<strong>共通鍵暗号方式</strong>と、暗号化用と復号用で異なる鍵を使う<strong>公開鍵暗号方式(RSA暗号・DSAなど)</strong>があり、それぞれの長所（速度・鍵配送の容易さ）を組み合わせた<strong>ハイブリッド暗号</strong>が実務では広く使われます。公開鍵暗号の中でも、より短い鍵長で同等の強度を実現する<strong>楕円曲線暗号</strong>と、その署名方式<strong>ECDSA(楕円曲線DSA)</strong>が近年主流です。安全に鍵を共有する方法として<strong>Diffie-Hellman鍵交換(DH)</strong>とその楕円曲線版<strong>ECDH</strong>があり、過去の通信が後で鍵が漏れても解読されない性質である<strong>前方秘匿性(PFS)</strong>を実現します。

暗号の安全性は鍵の管理に大きく依存します。鍵を作る<strong>鍵生成</strong>から始まり、配送・保管・更新・廃棄までを含む<strong>鍵管理</strong>全体を<strong>鍵のライフサイクル</strong>として捉えます。鍵を安全に保管する専用のハードウェアが<strong>HSM(Hardware Security Module)</strong>、それをソフトウェア・クラウドで実現する<strong>鍵管理システム(KMS)</strong>です。鍵の元になる乱数を生成する仕組みとしては、計算で生成する<strong>擬似乱数生成器(PRNG)</strong>、量子力学的な現象を使うことで真の乱数に近づける<strong>量子乱数生成器(QRNG)</strong>があります。技術の進歩により暗号が安全でなくなることを<strong>危殆化</strong>と呼び、鍵の長さなどで表される<strong>暗号強度(ビットセキュリティ)</strong>を定期的に見直す必要があります。

**扱う用語（精選・17語）**

- 共通鍵暗号方式／公開鍵暗号方式(RSA暗号・DSAなど)／ハイブリッド暗号／楕円曲線暗号／ECDSA／Diffie-Hellman鍵交換(DH)／ECDH／前方秘匿性(PFS)
- 鍵生成／鍵管理／鍵のライフサイクル／HSM／鍵管理システム(KMS)／擬似乱数生成器(PRNG)／量子乱数生成器(QRNG)／危殆化／暗号強度(ビットセキュリティ)

## ハッシュ関数とブロック暗号

データから固定長の値を計算し、わずかな変更でも全く違う値になる仕組みがハッシュ関数です。代表的な規格が<strong>SHA-2(SHA-256など)</strong>・<strong>SHA-3</strong>で、安全なハッシュ関数には、ハッシュ値から元データを逆算できない<strong>原像計算困難性(一方向性)</strong>、同じハッシュ値になる別のデータを見つけられない<strong>第二原像発見困難性</strong>・<strong>衝突発見困難性</strong>という3つの性質が求められます。かつて広く使われた<strong>MD5及びSHA-1の危殆化</strong>（脆弱性が発見され安全でなくなったこと）は、暗号アルゴリズムも永遠には安全でないことを示す典型例です。

データを一定サイズの塊（ブロック）ごとに暗号化する<strong>ブロック暗号(AES(Advanced Encryption Standard)など)</strong>、データを連続的に暗号化する<strong>ストリーム暗号(KCipher-2など)</strong>があり、ブロック暗号を実際にどう繰り返し適用するかを定めるのが<strong>暗号利用モード(CBC・CTRなど)</strong>です。暗号化と改ざん検知を同時に行う<strong>認証暗号(認証付き暗号・AEAD)</strong>、IoT機器のように計算資源が限られた環境向けの<strong>軽量暗号</strong>も、2027年シラバスで扱われる実務的なテーマです。

**扱う用語（精選・11語）**

- SHA-2(SHA-256など)／SHA-3／原像計算困難性(一方向性)／第二原像発見困難性／衝突発見困難性／MD5及びSHA-1の危殆化
- ブロック暗号(AES)／ストリーム暗号(KCipher-2など)／暗号利用モード(CBC・CTRなど)／認証暗号(AEAD)／軽量暗号

## PKI・証明書と先進暗号技術

公開鍵が本当に本人のものであることを保証する仕組みが<strong>公開鍵基盤(PKI)</strong>です。信頼できる第三者として証明書を発行する<strong>認証局(CA)</strong>、政府機関向けの<strong>政府認証基盤(GPKI)</strong>、CAの運用方針を定めた<strong>CP/CPS(Certificate Policy/Certification Practice Statement)</strong>、ブラウザベンダーとCAが証明書の基準を協議する<strong>CA/Browser Forum</strong>、証明書の国際標準形式<strong>ITU-T X.509</strong>があります。証明書を検証する際は、発行元をたどって信頼できるか確認する<strong>証明書パス検証</strong>、失効した証明書の一覧である<strong>証明書失効リスト(CRL)</strong>、その場でオンライン照会する<strong>OCSP</strong>、ソフトウェア配布用の<strong>コードサイニング証明書</strong>、発行手続きを自動化する<strong>証明書自動発行(ACME)</strong>、CAを限定できる<strong>CAA(Certification Authority Authorization)</strong>が使われます。

先進的な暗号技術としては、秘密情報を複数に分割し一定数以上集めないと復元できない<strong>秘密分散</strong>、暗号化したまま計算できる<strong>準同型暗号</strong>、秘密の中身を明かさずに知っていることだけを証明する<strong>ゼロ知識証明</strong>、ハードウェア内に隔離された安全な実行環境<strong>TEE(Trusted Execution Environment)</strong>、量子力学の原理で盗聴を検知しながら鍵を配送する<strong>量子鍵配送(QKD)</strong>があります。将来の量子コンピュータでも解読されにくい<strong>耐量子計算機暗号(PQC・ML-KEM・ML-DSA)</strong>への移行は2027年シラバスの新設テーマで、移行に備えて暗号方式を柔軟に切り替えられるようにしておく<strong>暗号アジリティ(Crypto Agility)</strong>という考え方もあわせて重要です。

**扱う用語（精選・19語）**

- 公開鍵基盤(PKI)／認証局(CA)／政府認証基盤(GPKI)／CP/CPS／CA/Browser Forum／ITU-T X.509
- 証明書パス検証／証明書失効リスト(CRL)／OCSP／コードサイニング証明書／証明書自動発行(ACME)／CAA
- 秘密分散／準同型暗号／ゼロ知識証明／TEE／量子鍵配送(QKD)／耐量子計算機暗号(PQC)／暗号アジリティ(Crypto Agility)
