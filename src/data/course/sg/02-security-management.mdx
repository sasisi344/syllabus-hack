## この章で学ぶこと

第1章で学んだ脅威・脆弱性に対して、組織としてどう向き合うかを扱う章です。個々の技術対策の前に必要なのが<strong>リスクマネジメント</strong>という考え方で、「何を」「どれくらい」守るかを決めてから対策を選びます。この章では、情報資産の管理からリスクアセスメント、組織の運営ルールである<strong>ISMS</strong>、そしてインシデントが起きたときに動く<strong>CSIRT</strong>などの体制まで、一連の流れとして押さえます。

## 情報資産の管理とリスクの種類

情報セキュリティ管理の出発点は、守るべき<strong>情報資産</strong>を洗い出し、その重要性に応じて分類・管理することです。調査結果は<strong>情報資産台帳</strong>にまとめ、誰が・何を・どの重要度で管理しているかを可視化します。管理の前提となる考え方が<strong>リスクマネジメント（JIS Q 31000）</strong>で、必要な人だけがアクセスできるようにする<strong>need-to-know（最小権限）の原則</strong>に基づく<strong>利用者アクセス権の管理</strong>や、クラウド事業者と利用者のどちらがどこまで責任を持つかを整理する<strong>クラウドサービスの責任共有モデル</strong>もあわせて出題されます。

リスクは金銭的な損失だけではありません。事業上の損失である<strong>財産損失</strong>・<strong>責任損失</strong>・<strong>純収益の喪失</strong>に加えて、業務プロセス自体に起因する<strong>オペレーショナルリスク</strong>、委託先や取引先を経由する<strong>サプライチェーンリスク</strong>、従業員の不用意な投稿が招く<strong>SNSによる情報発信のリスク</strong>、国際情勢に起因する<strong>地政学的リスク</strong>など、多様な切り口で問われます。

**扱う用語（精選・21語）**

- 情報資産／情報資産台帳／リスクマネジメント（JIS Q 31000）
- need-to-know（最小権限）の原則／利用者アクセス権の管理／アカウント管理
- クラウドサービスの責任共有モデル／外部委託やクラウドサービス利用時における情報セキュリティ／サイバーハイジーン
- 財産損失／責任損失／純収益の喪失／人的損失
- オペレーショナルリスク／サプライチェーンリスク／外部サービス利用のリスク／SNSによる情報発信のリスク／地政学的リスク／モラルハザード
- 情報セキュリティ事象／情報セキュリティインシデント

## リスクアセスメントとリスク対応

リスクアセスメントは、<strong>リスクの特定</strong>（何が起こりうるか）→<strong>リスクの分析</strong>（発生確率と影響度の把握）→<strong>リスクの評価</strong>（対応の要否・優先順位の判断）という3ステップで進みます。分析には、数値化しない<strong>定性的分析</strong>と、金額や確率で数値化する<strong>定量的分析</strong>があり、判断のよりどころとなる<strong>リスク基準（リスク受容基準）</strong>をあらかじめ組織で定めておきます。評価の結果は、発生確率と影響度を軸にまとめる<strong>リスクマトリックス</strong>や、リスクごとの責任者を示す<strong>リスク所有者</strong>とともに<strong>リスク登録簿</strong>で一元管理します。

評価したリスクへの対応は、影響が大きすぎる活動自体をやめる<strong>リスク回避</strong>、保険等で第三者に移す<strong>リスク共有（リスク移転，リスク分散）</strong>、対応せずそのまま受け入れる<strong>リスク保有</strong>、複数の小さなリスクをまとめて管理する<strong>リスク集約</strong>に大別されます。金銭的な備えとして<strong>サイバー保険</strong>による<strong>リスクファイナンシング</strong>も実務での選択肢です。対応後もなお残る<strong>残留リスク</strong>を許容できる水準か判断し、具体的な実施項目・責任者・期限をまとめた<strong>リスク対応計画</strong>に落とし込みます。関係者へリスク情報を伝える<strong>リスクコミュニケーション</strong>も忘れず押さえておきます。

**扱う用語（精選・18語）**

- リスクの特定／リスクの分析／リスクの評価／定性的分析／定量的分析
- リスク基準（リスク受容基準）／リスクレベル／リスクマトリックス／リスク所有者／リスク登録簿
- リスク回避／リスク共有（リスク移転，リスク分散）／リスク保有／リスク集約／残留リスク
- リスク対応計画／リスクコミュニケーション／サイバー保険（リスクファイナンシング）

## ISMSと情報セキュリティ諸規程

<strong>ISMS（情報セキュリティマネジメントシステム）</strong>は、リスクマネジメントを組織的な仕組みとして継続的に回す枠組みです。国際規格<strong>JIS Q 27001（ISO/IEC 27001）</strong>がISMSの要求事項を定め、これに基づいて第三者機関の審査を受けて取得するのが<strong>ISMS認証</strong>（国内の運用の仕組みが<strong>ISMS適合性評価制度</strong>）です。管理策の実装指針は<strong>JIS Q 27002（ISO/IEC 27002）</strong>にまとめられ、管理策は<strong>組織的・人的・物理的・技術的</strong>の4区分、機能面では<strong>予防・検知・是正</strong>の3タイプに分類されます。経営層が主導する<strong>情報セキュリティガバナンス（JIS Q 27014）</strong>という考え方もあわせて押さえます。

ISMSの運用は<strong>リーダーシップ</strong>のもとで計画を立て、<strong>内部監査</strong>や<strong>マネジメントレビュー</strong>による<strong>パフォーマンス評価</strong>を行い、不適合を是正する<strong>継続的改善</strong>のサイクルを回します。これらを支えるのが、情報セキュリティ方針を頂点とする<strong>情報セキュリティ諸規程</strong>の体系です。基本方針である<strong>情報セキュリティ方針</strong>・<strong>情報セキュリティ対策基準</strong>のもとに、<strong>情報管理規程</strong>・<strong>秘密情報管理規程</strong>・<strong>情報セキュリティインシデント対応規程</strong>・<strong>ソーシャルメディアガイドライン</strong>などの個別規程がぶら下がる構造だとイメージすると整理しやすくなります。

**扱う用語（精選・22語）**

- ISMS（情報セキュリティマネジメントシステム）／ISMS認証／ISMS適合性評価制度
- JIS Q 27001（ISO/IEC 27001）／JIS Q 27002（ISO/IEC 27002）／情報セキュリティガバナンス（JIS Q 27014）
- 情報セキュリティ管理策（組織的・人的・物理的・技術的）／管理策タイプ（予防・検知・是正）
- サイバーセキュリティ概念（識別・防御・検知・対応・復旧）
- リーダーシップ／内部監査／マネジメントレビュー／パフォーマンス評価／継続的改善
- 情報セキュリティ方針／情報セキュリティ対策基準／情報管理規程／秘密情報管理規程
- 情報セキュリティインシデント対応規程／情報セキュリティ教育の規程／プライバシーポリシー／ソーシャルメディアガイドライン

### 仕組みを理解する: PDCAサイクルは実際のISMS運用でどう回るか

ISMSの「継続的改善」は抽象的に聞こえますが、実際には次のような具体的なサイクルとして回ります。

<strong>Plan（計画）</strong>: 前節で学んだリスクアセスメントの結果をもとに、「どのリスクに」「どの管理策で」対応するかをリスク対応計画としてまとめる。<strong>Do（実行）</strong>: 計画した管理策（例: アクセス権の見直し、暗号化の導入）を実際に導入し、日常業務として運用する。<strong>Check（評価）</strong>: 内部監査やマネジメントレビューで、管理策が意図通り機能しているか、新たなリスクが生まれていないかを確認する。<strong>Act（改善）</strong>: 評価で見つかった不適合（規程通りに運用されていない箇所など）を是正し、必要であれば情報セキュリティ諸規程そのものを見直す。

このサイクルは1周して終わりではなく、Actの結果が次のPlanの材料になって回り続ける点がISMSの本質です。「1回やって終わり」ではなく「毎年見直され続ける仕組み」だと理解しておくと、パフォーマンス評価やマネジメントレビューがなぜ必要かも腑に落ちやすくなります。

## インシデント対応体制と公的機関・基準

インシデントが発生した際に対応する専門組織が<strong>CSIRT</strong>で、製品開発元向けの<strong>PSIRT</strong>、24時間監視を担う<strong>SOC（Security Operation Center）</strong>と役割が異なります。対応の流れは、検知・連絡受付から始まり<strong>トリアージ</strong>（重大度に応じた優先順位付け）を経て<strong>インシデントレスポンス</strong>・報告に至る<strong>インシデントハンドリング</strong>という一連のプロセスで理解します。悪意あるサイトやサーバを停止させる<strong>テイクダウン</strong>という対応もあります。

日本の公的機関としては、政府全体の司令塔である<strong>内閣サイバーセキュリティセンター（NISC）</strong>、インシデント対応や注意喚起を行う<strong>JPCERTコーディネーションセンター</strong>、脆弱性情報を集約する<strong>JVN（Japan Vulnerability Notes）</strong>、そして<strong>IPAセキュリティセンター</strong>を押さえます。組織のセキュリティ対策状況を自己宣言する<strong>SECURITY ACTION</strong>、クラウドサービスを政府が評価する<strong>ISMAP</strong>も実務での認知度が高まっています。経営層向けの指針である<strong>サイバーセキュリティ経営ガイドライン</strong>、中小企業向けの<strong>中小企業の情報セキュリティ対策ガイドライン</strong>、クレジットカード業界の<strong>PCI DSS</strong>など、業界・規模別のガイドライン・基準が複数存在する点も押さえておきます。

**扱う用語（精選・16語）**

- CSIRT／PSIRT／SOC（Security Operation Center）
- インシデントハンドリング（検知/連絡受付，トリアージ，インシデントレスポンス，報告/情報公開）／テイクダウン
- 内閣サイバーセキュリティセンター（NISC）／JPCERTコーディネーションセンター／JVN／IPAセキュリティセンター
- SECURITY ACTION／ISMAP
- サイバーセキュリティ経営ガイドライン／中小企業の情報セキュリティ対策ガイドライン／PCI DSS／サイバーセキュリティフレームワーク（CSF）

## コラム: 2027年シラバス改訂プレビュー（予想・現行シラバス未確定）

<!-- 本コラムは現行v4.1シラバスに明記されていない予想内容。確定知識と混同させないよう独立枠として扱う（sg-course-curriculum.md §4-2） -->

現行シラバスにも「AIに対する脅威」「AIを悪用した攻撃」は含まれていますが、2027年度に予定されている情報処理安全確保支援士（SC）試験の新シラバス案では、生成AIのセキュリティが専門知識として大きく拡充される予定です（[SC2027シラバス差分レポート](https://www.ipa.go.jp/shiken/syllabus/henkou/2026/20260630.html)より）。情報セキュリティマネジメント試験（SG）も同じ2027年度に新制度へ移行する予定ですが、2026年9月時点でSGの新シラバス案はまだ公開されていません。ただし、IPA試験区分をまたいで知識体系が共有される設計になっているため、SGでも管理者目線に翻訳された形で同様の論点が追加される可能性があります。

- <strong>生成AI利用ガイドラインの整備</strong>: 従業員が生成AIを業務で使う際のルール（機密情報の入力禁止、出力結果の検証義務など）
- <strong>シャドーAI対策</strong>: 組織が許可していない生成AIサービスを従業員が無断で利用するリスクへの対応（第1章のシャドーITと同じ発想）
- <strong>AIサプライチェーンリスク管理</strong>: 外部の生成AIサービス・APIを業務に組み込む際の情報セキュリティ管理
- <strong>AI利用に関する新しい標準</strong>: ISO/IEC 42001（AIマネジメントシステム）、AI事業者ガイドライン

これらは<strong>現行シラバスには明記されていない予想</strong>であり、出題が確定しているわけではありません。ただし、実務で情報セキュリティを担当するうえでは早晩必要になる知識のため、動向として頭に入れておくとよいでしょう。

## AIで学ぶ

ここまでの用語は、ChatGPTやClaudeなどの生成AIに以下のプロンプトを投げかけると、比較表つきでさらに深く掘り下げて学習できます。コピーして使ってみましょう。

```
あなたは情報セキュリティマネジメント試験の講師です。「情報セキュリティマネジメント体制（ISMS・リスク対応）」の範囲について、以下の用語を初学者向けに**関連づけながら**説明してください（単体の丸暗記より、用語同士のつながりを理解したほうが記憶に定着しやすく、試験本番で紛らわしい選択肢を見分ける力もつくためです）。用語同士の違いが分かる**比較表**を最後に付けてください。

【情報資産とリスクの種類】情報資産、情報資産台帳、リスクマネジメント、need-to-knowの原則、クラウドサービスの責任共有モデル、財産損失、責任損失、オペレーショナルリスク、サプライチェーンリスク
【リスクアセスメントと対応】リスクの特定、分析、評価、定性的分析、定量的分析、リスク基準、リスクマトリックス、リスク回避、リスク移転、リスク保有、残留リスク、リスク対応計画
【ISMSと諸規程】ISMS、ISMS認証、JIS Q 27001、JIS Q 27002、情報セキュリティ管理策（組織的・人的・物理的・技術的）、管理策タイプ（予防・検知・是正）、情報セキュリティ方針、情報セキュリティ対策基準
【インシデント対応体制】CSIRT、PSIRT、SOC、インシデントハンドリング、トリアージ、NISC、JPCERTコーディネーションセンター、JVN
```

このプロンプトには3つの工夫が入っています。<strong>役割</strong>を与えて回答のトーンをそろえ、<strong>関連づけて説明させる</strong>ことで用語の羅列を防ぎ、<strong>比較表で受け取る</strong>ことで紛らわしい選択肢の整理をAIに任せています。次章以降で自分なりにプロンプトを書き換えるときも、この3つを軸に調整してみてください。
