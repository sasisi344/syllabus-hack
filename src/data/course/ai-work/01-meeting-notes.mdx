## この章で学ぶこと

会議のあと、走り書きのメモを議事録にまとめる仕事は、多くの職場で「誰かがやらなければならない」作業です。
1時間の会議なら、整えるだけで30分かかることも珍しくありません。

この章では、その作業を生成AIに手伝わせながら、<strong>プロンプトを「投げる前に設計する」練習</strong>をします。
扱う力は次の3つです。

- 目的・入力・制約・出力形式・検証の5要素で、依頼を組み立てる
- 素材にない情報をAIに補わせない指示の書き方
- 出力を鵜呑みにせず、元の素材と突き合わせて検証する

本コースは実務練習用の教材です。AIの出力は必ず人が検証してください。
また、この章の素材はすべて架空のデータです。

<strong>実際の職場で練習するときは、社外秘・個人情報をそのまま貼らないこと。</strong>
社内のAI利用ルールを確認し、伏せ字やダミーに置き換えてから使います。

## このユースケースが起きる場面

週次の定例会議、取引先との打ち合わせ、プロジェクトの立ち上げ。
議事録の目的は「参加していない人にも、決まったこと・決まっていないこと・次に誰が何をするかが伝わる」ことです。

ところが会議中のメモは、こうなりがちです。

- 雑談と業務の話が混ざっている
- 「〜という方向」「〜頃？」のように、決まったのか曖昧な発言がある
- 担当者や期限が抜けている

これを整えるとき、AIは強力な助手になります。
一方で、<strong>担当者や期限を勝手に補ってしまう</strong>という、議事録にとって致命的な失敗も起こします。
だからこそ、この章の練習になります。

## プロンプト設計シート

この章のすべての問題で、AIに投げる前に次の5要素を自分で埋めます。
紙でもメモ帳でも構いません。

```
**目的**：誰に・何のために・何を作るか
**入力**：AIに渡す素材は何か（機密は伏せたか）
**制約**：やってはいけないこと・守るルール
**出力形式**：表・箇条書き・文字数など
**検証**：出力が正しいか、何と突き合わせるか
```

「ChatGPTに聞いてみる」の前に、この5行が埋まっているかどうか。
これが、対話するだけの練習との違いです。

## 実例：整っていないメモを議事録にする

まず、1つの課題を最後まで解いてみせます。
練習問題を解く前に、流れをつかんでください。

### 状況と素材

あなたは総務部の担当者です。
社内ポータルの移行に関する打ち合わせが終わり、上司から「参加していない部長にも共有できる議事録にしておいて」と頼まれました。
手元にあるのは次の走り書きです。

```
【メモ】ポータル移行 打ち合わせ 9/24 10:00〜10:45
参加：田中（情シス）、佐藤（総務）、鈴木（営業企画）、山本（外部ベンダー）

- 冒頭、山本さんが台風の影響で遅れて到着。少し雑談
- 旧ポータルは今年12月末でサポート終了。移行先は新ポータルで進める方向。田中さんが「基本はそれで決まりでいい」と言っていた
- 移行対象：ワークフロー申請とお知らせは移行、過去の掲示板は移行しない（佐藤さん了承）
- 社内周知の時期は10月中旬頃？ 総務で文案を作る、と佐藤さんが言ったが期限は決まらず
- 営業企画から、モバイル対応が必須かどうか質問。山本さん「対応はできるが追加費用がかかる」。見積は10/1までにお願いした
- 権限設定の方針は未定。部長以上のみ閲覧可とする案と、全員閲覧の案。持ち帰り
- 誰かが昼のランチの話。駅前の新しい定食屋が良いらしい
- 次回は10/8 同じ時間
```

このメモには、議事録の難しさが詰まっています。

- 決まったこと（移行対象の範囲）
- 決まっていないこと（周知時期・権限・モバイル対応）
- 担当と期限が揃っているもの（山本さんの見積）と揃っていないもの（佐藤さんの文案）
- 雑談（ランチの話）

### 悪い指示とその失敗

最初にやりがちなのは、これです。

```
この会議メモを要約して。
```

返ってくるのは、たとえば次のような文章です。

> 社内ポータルの移行について打ち合わせを行い、新ポータルへの移行が決定した。周知は10月中旬に実施予定で、佐藤さんが文案を10月上旬までに作成する。モバイル対応は追加費用がかかる。ランチの話題も出た。

失敗が3つあります。

- 「10月中旬頃？」という曖昧な発言が「実施予定」と断定されている
- 元メモにない「10月上旬まで」という期限が作られている
- 雑談が混ざっている

指示に「目的」も「制約」も「出力形式」もないので、AIは自分で判断し、もっともらしく補ってしまったのです。

### 改善したプロンプト

5要素で組み立て直します。

```
あなたは社内の会議記録を整理する事務担当です。以下の「会議メモ」から、共有用の議事録を作成してください。

**目的**
会議に参加していない部長にも、決まったこと・決まっていないこと・次に誰が何をするかが一目で分かる議事録を作る。

**制約**
- メモに書かれていない事実（担当者・期限・金額など）を補わない。不明な項目は「未定」と書く
- 雑談や業務に関係のない話題は含めない
- 断定できない発言（「〜という方向」「〜頃？」）は「決定事項」に入れず、「未決事項」に入れる

**出力形式**
1. 決定事項（箇条書き）
2. 未決事項（「内容」「論点」の2列の表）
3. 担当・期限（「担当者」「やること」「期限」の3列の表）
4. 最後に、元メモと突き合わせるための確認ポイントを3つ

**会議メモ**
（ここにメモを貼る）
```

### AIの出力と、人が確認した点

このプロンプトからは、次のような出力が得られます。

> <strong>決定事項</strong>
> - 旧ポータルは12月末でサポート終了のため、新ポータルへ移行する
> - 移行対象はワークフロー申請とお知らせ。過去の掲示板は移行しない
> - 次回は10/8（同じ時間）
>
> <strong>未決事項</strong>：社内周知の時期（10月中旬頃の案）／モバイル対応の要否（追加費用あり）／権限設定（部長以上のみ閲覧 or 全員閲覧）
>
> <strong>担当・期限</strong>：山本｜モバイル対応の見積提出｜10/1　佐藤｜社内周知の文案作成｜未定

前の失敗がすべて消えています。
それでも、人が確認するべき点が残っています。

- 「新ポータルへ移行する」を決定事項にしてよいか。メモでは「進める方向」で、了承しているのは田中さんの発言のみ。<strong>会議の場の合意かどうかは、AIには判断できない</strong>ので、必要なら参加者に確認する
- 佐藤さんの期限が「未定」になっているか（補われていないか）
- ランチの話が消えているか

議事録に責任を持つのはAIではなく、あなたです。

### 設計メモ：なぜこの書き方か

| 要素 | 実例での書き方 | 効いた理由 |
| --- | --- | --- |
| 目的 | 「参加していない部長にも」 | 誰が読むかが決まると、何を残し何を捨てるかの基準ができる |
| 入力 | 「会議メモ」を末尾に区切って貼る | 指示と素材が混ざらない |
| 制約 | 「補わない」「未定と書く」「曖昧な発言は未決へ」 | AIが起こしやすい失敗を、先回りして禁止した |
| 出力形式 | 決定／未決／担当・期限の3区分 | 議事録として必要な情報の抜けが見つけやすい |
| 検証 | 確認ポイントを3つ出させる | 人が元メモと突き合わせる手がかりが増える |

<strong>制約は「こうしてほしい」より「これは絶対にするな」のほうが効く</strong>場面が多くあります。
AIが起こしやすい失敗を予想し、あらかじめ書いておくのがコツです。

## 練習問題

ここからは自分で解きます。進め方は全問共通です。

1. 素材を読み、プロンプト設計シートの5要素を自分で埋める（AIはまだ使わない）
2. 埋めた内容をもとにプロンプトを書き、ChatGPT・Claude・Geminiなど普段使うAIで実行する
3. 出力をルーブリックで自己採点する
4. 解説を開き、自分の設計と比べる

模範プロンプトの丸写しでは力がつきません。先に解説を開かないようにしてください。

### 問1 整ったメモから共有用の議事録を作る

<strong>状況</strong>：営業部の週次ミーティングの議事録係です。部内メンバー全員に共有します。

<strong>成果物</strong>：決定事項・担当・期限の3列の表と、共有メール1通（150字程度）。

```
【営業部 週次ミーティング 10/6】出席：課長、山田、井上、中村
1. 10月の新規訪問目標は各自12件で決定
2. 展示会のブース担当は井上さんに決定。10/16までに配布資料の案を出す
3. 顧客リストの更新は中村さんが担当、10/10まで
4. 次回は10/13
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 決定事項が3件とも表に入っている
- [ ] 担当者と期限が素材どおり（井上 10/16、中村 10/10）で、追加・変更がない
- [ ] 目標「12件」「次回10/13」など数字・日付が正しい
- [ ] メールに、宛先の想定（部内メンバー）と依頼事項が含まれる
- [ ] プロンプトに「素材にない情報を補わない」旨の制約を書いた

</details>

<details>
<summary>よくある失敗と解説</summary>

素材が整っているので、「これを表にして」だけでも動きます。
ここで差がつくのは、<strong>制約を書いたかどうか</strong>です。
整った素材でも、AIは「課長」の担当を推測して補うことがあります。

模範の考え方は、実例の5要素をそのまま使うことです。
目的を「部内メンバー全員に共有」、出力形式を「3列の表＋150字のメール」と決め、制約に「メモにない情報は補わない」を入れます。
簡単な問題ほど、型どおりに書く習慣をつけてください。

</details>

### 問2 曖昧で不足の多いメモを整理する

<strong>状況</strong>：新入社員研修の準備担当です。上司にメモを見せる前に、状況を整理しておきたいと考えています。

<strong>成果物</strong>：「決まっていること」「決まっていないこと」「確認が必要な質問（誰に聞くか付き）」の3区分。

```
【新入社員研修 準備メモ】
- 研修は来月からの方向？ 人事の意見待ち
- 会場は本社の会議室Bで一旦OK（空いていれば）
- 講師は外部に頼むか社内でやるか、まだ
- 資料はなるべく早めに、と言われた
- 誰か、去年の研修アンケートを探しておいてほしい
- 予算は昨年並み…だったかな
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 「決まっていること」が0〜1件に絞られ、「会場」は条件つき（空いていれば）と書かれている
- [ ] 「予算は昨年並み」を確定情報として扱っていない（要確認になっている）
- [ ] 「誰か」の担当者をAIが補っていない（担当未定のまま）
- [ ] 確認質問に「誰に聞くか」が付いている
- [ ] 質問が具体的で、そのまま送れる（「いつからか」「誰が決めるか」など）

</details>

<details>
<summary>よくある失敗と解説</summary>

このメモは<strong>ほとんど何も決まっていません</strong>。
AIに「整理して」と頼むと、きれいな表にするために、決まっていないことまで決まったように書いてしまいがちです。

ここで使える型が2つあります。

- 制約に「確定していない事項は決定事項に入れない。条件つきのものは条件を残す」と書く
- 出力形式に「不足している情報は、誰に何を聞くべきかの質問にする」と書く

AIを「整える役」ではなく「足りないものを洗い出す役」として使う発想です。
「不明な点があれば、出力の前に私に質問してください」と最初に頼む方法もあります。

</details>

### 問3 社外向けの制約つきで議事録とお礼メールを作る

<strong>状況</strong>：取引先B社との打ち合わせのあと、B社にも共有できる議事録とお礼メールを作ります。手元のメモには、社内だけで使う情報が混ざっています。

<strong>成果物</strong>：B社に共有できる議事録（決まったことは3点以内）と、お礼メール（200字以内、敬体）。

```
【B社との販促連携 打ち合わせ 10/2 15:00】
出席：当社 高橋・伊藤／B社 渡辺様・小林様
- 販促キャンペーンは11月1日開始で合意
- 当社の原価率は約62%なので、B社への卸値は上代の70%以内で提示したい（社内メモ：これは先方に言わない）
- 競合のC社が先月同様の企画を出したので、差別化として「限定パッケージ」を付ける案
- B社側の窓口は渡辺様。携帯は090-0000-0000（緊急時のみ）
- チラシの入稿データは10/20までに当社(伊藤)からB社へ送付
- 先方から「決裁は部長の確認後」との話。回答は10/9までにいただく
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 原価率・卸値の社内方針が、議事録にもメールにも含まれていない
- [ ] 競合C社の名前が含まれていない
- [ ] 渡辺様の携帯番号が含まれていない
- [ ] 決まったことが3点以内で、正しい（開始11/1、入稿10/20・伊藤、回答10/9・B社）
- [ ] お礼メールが200字以内である（文字数を実際に数えた）
- [ ] AIにメモを貼る前に、社外秘の扱いを考える工程を設計シートに入れた

</details>

<details>
<summary>よくある失敗と解説</summary>

この問題の難所は2つです。

1つ目は、<strong>制約の「除外ルール」を具体的に書く</strong>こと。
「社外に出せない情報は除いて」では、AIはどれが社外秘か判断できません。
「原価・卸値・社内の方針、競合他社名、個人の連絡先は含めない」のように、種類を挙げます。

2つ目は、<strong>文字数の指定は守られないことがある</strong>こと。
「200字以内」と書いても超えることがあります。
出力後に自分で数えるか、AIに「文字数を数えて、超えていれば書き直して」と続けて頼みます。これが検証の設計です。

もう一つ大事な点があります。
この素材は架空ですが、本物の社外秘メモを外部のAIに貼ってよいかは、社内のルール次第です。
実務なら、原価率や電話番号を<strong>貼る前に伏せ字にする</strong>手順を、設計シートの「入力」に入れます。
「AIが漏らさないようにする」より「最初から渡さない」ほうが確実です。

</details>

### 問4 AIが書いた議事録の誤りを見抜く

<strong>状況</strong>：同僚がAIに作らせた議事録が、あなたのところに回ってきました。共有前のチェックを頼まれています。

<strong>成果物</strong>：誤りの指摘リストと、AIに修正させるためのプロンプト。

元のメモ：

```
【システム更改 打ち合わせ 10/3】出席：森、大野、清水
- 現行サーバは来年3月で保守終了。更改は必須
- 移行先はクラウドとオンプレの2案。どちらにするかは次回までに大野さんが比較表を作る
- 予算枠は来週の経営会議で確認（森さん）
- 新システムの稼働時期は、来年4月か5月ごろ
```

AIが作った議事録：

```
決定事項
・現行サーバは来年3月で保守終了のため更改する
・移行先はクラウドに決定
・新システムは来年4月に稼働開始

担当・期限
大野｜比較表の作成｜10/10
森｜予算枠の確認｜来週の経営会議
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 「クラウドに決定」は誤り（元は2案で未決）と指摘できた
- [ ] 「来年4月に稼働開始」は誤り（元は4月か5月ごろ）と指摘できた
- [ ] 「10/10」は誤り（元は「次回まで」で日付がない）と指摘できた
- [ ] 修正プロンプトに、元メモと議事録の両方を渡し、食い違いを列挙させる指示を入れた
- [ ] 修正プロンプトに「元メモのどの部分が根拠か引用して示す」指示を入れた
- [ ] 修正後の出力も、最後は自分の目で元メモと突き合わせる、と設計した

</details>

<details>
<summary>よくある失敗と解説</summary>

誤りは3つあります。

- 未決を決定にした（クラウドに決定）
- 幅のある表現を1つに絞った（4月か5月ごろ→4月）
- 期限の日付を作った（次回まで→10/10）

どれも、もっともらしく、誤りに気づきにくい形です。
ここから読み取れるのは、<strong>AIの誤りは「間違った」ではなく「補った」の形で出る</strong>ということです。

修正の依頼は、「間違いを直して」ではなく、次のように<strong>根拠を出させる</strong>形にします。

```
以下の「元メモ」と「議事録」を突き合わせ、議事録の記述のうち、元メモに根拠がないもの・元メモと食い違うものをすべて列挙してください。

**制約**
- 各項目について、根拠となる元メモの一文を引用すること
- 根拠が見つからない場合は「根拠なし」と書くこと
```

ただし、これで検証が終わるわけではありません。
AI自身の「確認しました」も間違えることがあります。最後の突き合わせは、人が行います。

</details>

## 繰り返し使う制約は、AIに登録して短くする

この章のプロンプトは、制約を毎回書き込む形で練習しました。
同じ業務を繰り返すなら、<strong>変わらない制約は、AIにあらかじめ登録しておく</strong>ことで、依頼を短くできます。

この章で登録しておくとよいのは、議事録の出力の型、「メモにない情報は補わない」「不明は未定と書く」「機密は伏せる」といった制約です。
ChatGPT・Claude・Geminiでの登録手順は、[生成AIに社内ルールを覚えさせるスキル設定のやり方](/method/ai-skill-rules-setup/)で解説しています。
登録しても、最終確認は人が行うことに変わりはありません。

## 自分の職場に置き換える

最後に、この章の型を自分の仕事に当てはめます。

1. 直近で参加した会議（または想像した会議）を1つ選ぶ
2. 実際のメモを使う場合は、社名・人名・金額を伏せ字にする。使わない場合は、架空のメモを自分で作る
3. プロンプト設計シートの5要素を埋め、AIに実行させる
4. ルーブリックを自分で作る（この章の「担当者を補っていないか」などを参考に、5項目）

仕上げに、S.E.L.F.ループの「F（Forge it）」として、<strong>この章で学んだ5要素をAIに説明し直してみて</strong>ください。
「議事録づくりで大切なことを、新入社員に教えるつもりで解説して」と頼み、自分の理解とのズレを確かめます。
S.E.L.F.ループの詳しい使い方は、[コラム記事](/method/self-loop-ai-learning/)を参照してください。

## この章のまとめ

- 生成AIに議事録を作らせるときは、目的・入力・制約・出力形式・検証の5要素で、投げる前に設計する
- AIの誤りは「補う」形で出る。「補わない」「未定と書く」を制約に入れる
- 曖昧な発言は、決定事項ではなく未決事項に入れる
- 制約は「絶対にするな」を具体的に書く。文字数など守られにくい指示は、出力後に検証する
- 社外秘・個人情報は、AIに貼る前に伏せ字にする
- 最終責任は人にある。AIの出力は、必ず元の素材と突き合わせる

次の章では、問い合わせ対応とFAQ作成を題材に、「相手の感情」と「社内ルール」を含む依頼の組み立て方を練習します。
