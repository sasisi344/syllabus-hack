## この章で学ぶこと

生成AIに調べものを頼むと、驚くほど速く、それらしい答えが返ってきます。
その答えの中に、<strong>存在しない統計や、実在しない出典</strong>が混ざっていることがあります。
職場の資料にそのまま載せれば、信頼を失う原因になります。

この章では、調査とファクトチェックを題材に、次の3つを練習します。

- 手元の資料を渡し、「資料の範囲内で」答えさせる
- 複数の資料の食い違いを見つけ、断定せずに扱う
- AIが挙げた出典を、人が確認する手順を設計する

第1章の5要素（目的・入力・制約・出力形式・検証）は、この章でも使います。
この章の素材は、すべて架空の資料です。実在の統計や団体名は使っていません。
本コースは実務練習用の教材です。AIの出力は必ず人が検証してください。

## このユースケースが起きる場面

会議資料の背景データを集める、業界の動向をまとめる、社内アンケートの結果を報告する。
調査の仕事では、次のような場面でAIが失敗します。

- 質問に答えるために、データを「作って」しまう
- 実在しそうな報告書名やページ数を挙げる（実際には存在しない）
- 調査対象や年が違う数字を、同じ土俵で比べてしまう

大切なのは、AIを「調査担当」ではなく、<strong>「手元の資料を整理する助手」</strong>として使うことです。
調査の責任は、あくまで人にあります。

## プロンプト設計シート（再掲）

```
**目的**：誰に・何のために・何を作るか
**入力**：AIに渡す素材は何か（機密は伏せたか）
**制約**：やってはいけないこと・守るルール
**出力形式**：表・箇条書き・文字数など
**検証**：出力が正しいか、何と突き合わせるか
```

この章では、「入力」と「検証」の設計が中心です。
<strong>AIに知識を出させるのではなく、こちらが資料を渡して、その中から答えさせる</strong>のが安全な基本形です。

## 実例：複数の資料から、自社の状況を報告する

### 状況と素材

あなたは、社内のテレワークの現状を、役員向けに報告することになりました。
手元にある資料は、次の3つです。

```
【資料1：社内アンケート（2026年8月実施・有効回答240名）】
テレワークを週1日以上している：132名（55%）。
実施者132名のうち、生産性が「上がった」：58名、「変わらない」：49名、「下がった」：25名。

【資料2：業界団体のレポート（2025年）】
業界内のテレワーク実施率は48%。
生産性について「上がった」と答えた割合は52%。
調査対象は、従業員1,000名以上の企業のみ。

【資料3：外部コラム（2024年）】
「テレワークで生産性は下がる」と主張。根拠となるデータの記載なし。
```

### 悪い指示とその失敗

```
テレワークの生産性について調べて、まとめて。
```

返ってくるのは、次のような文章です。

> 調査によると、テレワークにより生産性が平均して向上したという結果が多く、日本企業の導入率は約60%に達しています。ただし、コミュニケーション不足による課題も指摘されています。

失敗が3つあります。

- 手元の3つの資料が、まったく使われていない
- 「約60%」という、出典不明の数字が出てきている
- 自社の数字と、業界の数字が、比較されていない

「調べて」という依頼は、AI自身の知識で答えるよう求めるものです。
その知識には、出典が確認できないものが混ざります。

### 改善したプロンプト

```
あなたは、社内報告の資料を整理する担当です。以下の3つの資料だけを使って、自社のテレワークの状況を、業界の水準と比較して報告する1段落（250字程度）を作成してください。

**目的**
役員が、自社の状況を業界と比べて把握できるようにする。

**制約**
- 3つの資料に書かれていない情報は使わない。資料にないことは「資料にない」と書く
- 数字には、出典として資料番号を付ける（例：55%［資料1］）
- 調査対象・時期・母集団が異なる場合は、比較の前提の違いを明記する
- 根拠のデータがない主張は、事実としてではなく、「データの裏付けがない見解」として区別する

**出力形式**
1. 報告の1段落
2. 使用した数字の一覧（数字／出典の資料番号／調査対象・時期）
3. 比較する際の注意点を箇条書きで

**資料**
（ここに3つの資料を貼る）
```

### AIの出力と、人が確認した点

> <strong>報告</strong>：自社のテレワーク実施率は55%［資料1］で、業界団体の調査の48%［資料2］を上回った。ただし、資料2は従業員1,000名以上の企業のみが対象で、比較の前提が異なる。生産性が「上がった」と答えた割合は、自社の実施者で約44%（58名／132名）［資料1］、業界で52%［資料2］だった。「テレワークで生産性は下がる」という外部の見解［資料3］には、データの裏付けが示されていない。

人が確認する点は、次のとおりです。

- 約44%が、58÷132で正しく計算されているか（自分で計算してみる）
- 「上回った」という比較に、対象の違いが明記されているか
- 資料3が「事実」として扱われていないか

<strong>資料に番号を振り、数字ごとに出典を付けさせる</strong>と、人が元の資料と突き合わせる作業が、格段に速くなります。

### 設計メモ：なぜこの書き方か

| 要素 | 実例での書き方 | 効いた理由 |
| --- | --- | --- |
| 目的 | 「役員が、業界と比べて把握できる」 | 比較が必要だと分かり、資料を使い分けられる |
| 入力 | 3つの資料を、番号つきで貼る | AIの記憶に頼らず、資料の中から答えさせられる |
| 制約 | 「資料にないことは書かない」「比較の前提を明記」 | 数字の創作と、条件の違う比較を防いだ |
| 出力形式 | 報告文＋数字の一覧＋注意点 | 人が確認するための材料を、同時に得られる |
| 検証 | 出典の資料番号と、自分での計算 | 数字の誤りを、数分で見つけられる |

<strong>「資料の範囲内で答えて」は、調査系のプロンプトの基本形</strong>です。
AIの知識が必要な場合は、資料内の事実と、AI自身の知識を、分けて書かせます（問3で練習します）。

## 練習問題

進め方は全問共通です。

1. 素材を読み、プロンプト設計シートの5要素を自分で埋める（AIはまだ使わない）
2. 埋めた内容をもとにプロンプトを書き、普段使うAIで実行する
3. 出力をルーブリックで自己採点する
4. 解説を開き、自分の設計と比べる

### 問1 3つの資料から、上司向けの要点を3行でまとめる

<strong>状況</strong>：社内の生成AIの利用状況を、上司に3行で報告します。

<strong>成果物</strong>：報告の3行と、使った数字の一覧（出典の資料記号つき）。

```
【資料A：社内調査（2026年7月・回答180名）】
業務で生成AIを週1回以上使う：72名。
使う人の主な用途（複数回答）：文章作成60名、要約48名、調査35名、コード12名。

【資料B：ベンダー資料（2026年5月）】
自社ツールの導入企業では、利用率が平均65%に達した。調査方法の記載なし。

【資料C：社内ヒアリング（2026年8月・10名）】
「何に使えばいいか分からない」という声が、6名。
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 利用率が「40%（72名÷180名）」と、正しく計算されている
- [ ] 用途の順位（文章作成・要約・調査・コード）が、資料Aと一致している
- [ ] 資料Bの65%が、「調査方法が不明」という注意つきで扱われている（社内の利用率と、同列に比べていない）
- [ ] 資料Cが「10名のヒアリング」という母数つきで扱われている（一般化していない）
- [ ] 数字ごとに、資料記号（A・B・C）が付いている

</details>

<details>
<summary>よくある失敗と解説</summary>

この問題のワナは、<strong>資料の質の違い</strong>です。
資料Aは、回答者数がはっきりしています。
資料Bは、調査方法が書かれていないベンダー自身の資料で、参考程度です。
資料Cは、10名の声なので、傾向は読み取れても、全社の割合とは言えません。

AIは、放っておくと、3つの資料を同じ重みで扱います。
制約に、「各資料の対象・母数・調査方法を確認し、信頼性の違いを注記する」と入れてください。
3行という制限の中で、この注意書きを残せるかが、報告の質を分けます。

</details>

### 問2 資料同士の食い違いを見つける

<strong>状況</strong>：営業成績の集計で、3つの部署の数字が合いません。原因を調べる前に、食い違いを整理します。

<strong>成果物</strong>：食い違いの一覧、原因の仮説、確認すべき相手やデータのリスト。

```
【資料X：営業部のレポート】
9月の新規契約件数は42件。

【資料Y：経理部の集計】
9月の新規契約件数は39件。

【資料Z：システムのログ】
9月に「新規」のステータスで登録された契約は44件（うち5件は取消済み）。
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 3つの数字（42・39・44）の食い違いを、正しく整理している
- [ ] 資料Zの「44件－取消5件＝39件」が、資料Yと一致することに気づいている
- [ ] 資料Xの42件だけ、説明がつかないことを指摘している（どれが正しいかを、AIが決めつけていない）
- [ ] 原因の仮説が複数あり、それぞれ「仮説」と明記されている
- [ ] 確認すべき相手（営業部の担当者など）と、見るべきデータが具体的に書かれている

</details>

<details>
<summary>よくある失敗と解説</summary>

AIに「どれが正しい？」と聞くと、<strong>根拠もなく、1つを選んでしまう</strong>ことがあります。
この問題では、YとZが一致し、Xだけが合いません。
ただし、Xが間違いだと決めるには、Xの集計条件（「新規」の定義、取消の扱い）を確認する必要があります。

制約に、次の2点を入れます。

- 「食い違いを整理するだけで、どれが正しいかは判断しない」
- 「原因は仮説として挙げ、確認に必要な情報を添える」

「資料から言えること」と「まだ分からないこと」を分けて出力させる設計です。
人が確認に動くための、次の一手が分かる出力になります。

</details>

### 問3 資料にないことを、資料にないと答えさせる

<strong>状況</strong>：問1の資料Aだけを渡して、上司からの追加の質問に答えます。

<strong>成果物</strong>：次の2つの質問への回答。

- 質問1：業界全体の生成AI利用率は、どれくらいですか
- 質問2：来年度の利用者は、どれくらい増えそうですか

```
【資料A：社内調査（2026年7月・回答180名）】
業務で生成AIを週1回以上使う：72名。
使う人の主な用途（複数回答）：文章作成60名、要約48名、調査35名、コード12名。
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 質問1に対し、資料Aから「業界全体の数字は分からない」と答えている
- [ ] 質問2に対し、資料Aから予測はできない、または「推測」と明示して答えている
- [ ] 資料に基づく事実と、AIの一般的な知識・推測が、別の見出しで分けて出力されている
- [ ] 存在しない統計（「業界の利用率は約〇%」など）が出力されていない
- [ ] プロンプトに「資料にない場合は、資料にないと書く」という指示を入れた

</details>

<details>
<summary>よくある失敗と解説</summary>

AIは、質問されると、答えようとします。
資料がなくても、「一般的には50%前後と言われています」のような、根拠のない数字を出すことがあります。

対策は、<strong>答えられない場合の出口を、先に用意しておく</strong>ことです。

```
**制約**
- 資料に書かれている事実のみを使って答える
- 資料から答えられない場合は、「資料からは分かりません」と書く
- 推測や一般的な知識を述べる場合は、「【資料外の推測】」という見出しの下に分けて書き、確認が必要だと添える
```

「資料外の推測」をゼロにするのではなく、<strong>混ざらないように分けて出させる</strong>のがコツです。
分けておけば、人が事実部分だけを採用できます。

</details>

### 問4 AIが挙げた出典を、確認する手順を設計する

<strong>状況</strong>：同僚が、AIに調べさせた文章を、資料に載せようとしています。出典が付いているので安心そうですが、確認を頼まれました。

<strong>成果物</strong>：検証計画の表（主張／出典／確認方法／採用の基準）と、AIに追加で依頼するプロンプト。

以下は、架空の団体名と架空の白書の例です。

```
- 国内企業の生成AI導入率は、2025年に約60%に達した
  （出典：一般社団法人ワークスタイル研究協会『2025年版 働き方白書』p.87）
- 導入企業の8割が「業務時間が減った」と回答した
  （出典：同上 p.92）
- 生成AIの利用でミスが減った企業は、3割程度である
  （出典：不明）
```

<details>
<summary>ルーブリック（自己採点）</summary>

- [ ] 検証計画に、「出典を検索して原本を確認する」「該当ページの数字が一致するか確認する」が含まれている
- [ ] 「見つからない場合は採用しない」という判断基準を決めている
- [ ] 3つ目の「出典：不明」の主張を、採用しない、または「一般に言われている」として扱う、と判断している
- [ ] 「AIに『この出典は実在しますか』と聞く」のは検証にならない、という点を理解している
- [ ] AIへの追加依頼に、「出典が確認できない主張は含めず、『要確認』と書く」という制約を入れた

</details>

<details>
<summary>よくある失敗と解説</summary>

最も大切なのは、<strong>出典が付いていても、それが本物とは限らない</strong>ことです。
AIは、実在しそうな団体名・書名・ページ数を、それらしく組み合わせて作ることがあります。

「この出典は本当にありますか」とAIに聞いても、検証にはなりません。
AIは、「確認しました」と答えることがあります。

人が行う検証は、次の手順です。

1. 団体名・書名で検索し、公式サイトなどで、実在を確認する
2. 原本の該当ページを開き、数字が一致するかを確認する
3. 見つからない、または数字が違う場合は、その主張を採用しない

AIにできるのは、「確認が必要な箇所を洗い出す」ことです。
「出典の確認が必要な主張を、すべて一覧にして、確認方法を提案して」と頼めば、検証作業の段取りを手伝わせられます。
最終的な確認は、人が原本を見て行います。

</details>

## 繰り返し使う制約は、AIに登録して短くする

この章のプロンプトは、制約を毎回書き込む形で練習しました。
同じ業務を繰り返すなら、<strong>変わらない制約は、AIにあらかじめ登録しておく</strong>ことで、依頼を短くできます。

この章で登録しておくとよいのは、「資料の範囲内で答える」「数字に資料番号を付ける」「資料にないことは資料にないと書く」という制約です。
ChatGPT・Claude・Geminiでの登録手順は、[生成AIに社内ルールを覚えさせるスキル設定のやり方](/method/ai-skill-rules-setup/)で解説しています。
登録しても、最終確認は人が行うことに変わりはありません。

## 自分の職場に置き換える

この章の型を、自分の仕事に当てはめます。

1. 調べたいこと（または、資料に載せたい数字）を1つ選ぶ
2. 手元にある資料（社内データ、公的機関の発表、記事など）を2〜3個集める。機密は伏せる
3. 資料に番号を振り、「資料の範囲内で」まとめさせる。資料にないことは「資料にない」と書かせる
4. AIが挙げた数字を、自分で元の資料と突き合わせ、一致しないものを記録する

仕上げに、S.E.L.F.ループの「F（Forge it）」として、<strong>AIの出力で、資料と食い違っていた箇所を書き出し</strong>、「どんな指示があれば防げたか」を1つ考えます。

## この章のまとめ

- 調査は、AIの知識に頼らず、手元の資料を渡して「資料の範囲内で」答えさせる
- 数字には資料番号を付けさせ、人が元の資料と突き合わせられる状態にする
- 資料同士が食い違うときは、AIに正解を決めさせず、食い違いと確認先の整理に使う
- 答えられない質問には、「資料にない」と答える出口を用意する。資料外の推測は、別の見出しに分けさせる
- AIの出典は、人が原本で確認する。AIに「本当ですか」と聞くのは、検証にならない

次の章では、Excel・スプレッドシートの業務を題材に、「入力の形」と「期待する結果」を具体的に渡す書き方を練習します。
